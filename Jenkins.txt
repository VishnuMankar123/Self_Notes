# Step-by-step explanation (Hindi + English mix)

ठीक है Vishnu — नीचे आपका पूरा `Jenkinsfile` line-by-line और stage-by-stage समझा रहा हूँ, साथ में वो pitfalls / fixes और बेहतर practices भी दे रहा हूँ.

---

## `pipeline { agent any ... }`

* **`pipeline {}`** — यह declarative Jenkins pipeline block है।
* **`agent any`** — कोई भी available Jenkins agent/node इस pipeline को रन करेगा.

  * मतलब: जो node चुनकर job आएगा उस पर `sh`/`docker`/`mvn` कमांड चलेगी.
  * **Important:** जिस node पर ये चलाना है, वहाँ **Docker** और **Maven/JDK** installed और correctly configured होना चाहिए (या Docker-in-Docker/socket mounting use करना होगा).

---

## `tools { maven 'Maven3' jdk 'JDK17' }`

* Jenkins → **Manage Jenkins → Global Tool Configuration** में आपने जो tool names डाले हैं (e.g. `Maven3`, `JDK17`) वही यहाँ refer किये जा रहे हैं.
* Jenkins pipeline इन tools को PATH में add करेगा ताकि `mvn` और `java` commands मिलें।
* **Note:** अगर tools नहीं configured → build fail होगा. Tool names exact match होने चाहिए.

---

## `stage('Checkout') { steps { git 'https://github.com/username/your-springboot-repo.git' } }`

* यह stage आपका source code Git से clone करता है.
* अगर repo **private** है तो Jenkins credentials setup करके `credentials` parameter देना पड़ेगा, example:

  ```groovy
  git url: 'https://github.com/..', credentialsId: 'github-creds'
  ```
* Clone करने के बाद workspace में project files मिल जाएँगे (pom.xml, src/, Dockerfile, Jenkinsfile आदि).

---

## `stage('Build Jar') { steps { sh 'mvn clean package -DskipTests' } }`

* `sh 'mvn clean package -DskipTests'` — Maven से Spring Boot fat JAR बनाता है.

  * `clean package` → build artifact बनेगा: `target/*.jar`.
  * `-DskipTests` → tests skip कर रहा है (dev/fast builds के लिए). Production: tests run कर लें।
* **Requirements:** node पर Maven और JDK होना चाहिए (tools block configured होने पर Jenkins auto set कर सकता है).

---

## `stage('Build Docker Image') { steps { sh 'docker build -t vishnudas/filegenerator:1.0 .' } }`

* `docker build` command workspace में मौजूद `Dockerfile` के हिसाब से image बनाता है।
* `-t vishnudas/filegenerator:1.0` — image का नाम और tag set करता है (username/repo\:tag).

  * **Important:** Docker Hub में push करने के लिए image name में Docker Hub username prefix होना चाहिए (yaha `vishnudas`).
* **Potential issues:**

  * Agent पर Docker daemon installed और accessible होना चाहिए.
  * अगर Jenkins एक अलग user में चल रहा है जिसे Docker permission नहीं है → `docker` command fail होगा.

---

## `stage('Push Docker Image') { steps { withCredentials([usernamePassword(credentialsId: 'dockerhub-creds', usernameVariable: 'USER', passwordVariable: 'PASS')]) { sh 'echo $PASS | docker login -u $USER --password-stdin' sh 'docker push vishnudas/filegenerator:1.0' } } }`

* **Purpose:** Docker Hub (registry) में image push करना।
* **`withCredentials([...])`** — Jenkins credentials store से secure credentials लेते हैं:

  * `credentialsId: 'dockerhub-creds'` — ये Jenkins में पहले बनाये जाने चाहिए (Kind = Username with password).
  * फिर `USER` और `PASS` environment variables के रूप में available होते हैं सिर्फ इस block में।
* **Login command:** `echo $PASS | docker login -u $USER --password-stdin` — password stdin के द्वारा pass करना ज्यादा secure होता है (plain text avoid)।
* **Push:** `docker push vishnudas/filegenerator:1.0` — remote registry पर image upload करेगा।
* **Errors to watch:**

  * Invalid credentials → login fail.
  * Network/proxy issues → push fail.
  * If image tag already exists and you don’t want to overwrite, use unique tags (see improvements).

---

## `stage('Run Container') { steps { sh ''' docker rm -f springboot-app || true docker run -d -p 8080:8080 --name springboot-app vishnudas/filegenerator:1.0 ''' } }`

* **What it does:** पुराने container (अगर चल रहा) को force remove करता है और नया container start करता है.

  * `docker rm -f springboot-app || true` — अगर container exist नहीं करता तो command non-zero exit status दे सकता है; `|| true` ensures step not fail.
  * `docker run -d -p 8080:8080 --name springboot-app vishnudas/filegenerator:1.0` — detached mode में new container start करता है और host port 8080 को container port 8080 से map करता है.
* **Notes:**

  * Port conflict हो सकता है अगर host पर पहले से कुछ 8080 use कर रहा हो.
  * Container run करने से पहले image local में होना चाहिए (या Docker Hub से pull होगी)।
  * For production, `docker run` से better orchestration use karein (systemd, docker-compose, k8s).

---

## छोटे–छोटे practical tips / improvements (recommended)

1. **Tagging:** हर build पर unique tag use करें:

   ```groovy
   def imgTag = "vishnudas/filegenerator:${env.BUILD_NUMBER}"
   sh "docker build -t ${imgTag} ."
   sh "docker push ${imgTag}"
   ```

   ताकि old images retained रहें और rollbacks आसान हों.

2. **Agent selection:** `agent any` की बजाये सुनिश्चित करें कि agent पर Docker available है. या use `agent { label 'docker' }`.

3. **Windows vs Linux agents:** `sh` POSIX shell use करता है — Windows slave पर `bat` use करें. Example:

   ```groovy
   if (isUnix()) { sh 'docker ...' } else { bat 'docker ...' }
   ```

4. **Use `docker.withRegistry` (Pipeline steps) or `docker.image(...).push()`** — Jenkins provides Docker Pipeline plugin helpers which handle login/push more cleanly.

5. **Error handling & cleanup:** add `post { always { ... } }` block to cleanup workspace or stop containers on failure.

6. **Cache & speed:** For faster builds, use multi-stage Dockerfile and copy only required files first so Docker cache is effective.

7. **Security:** Keep `dockerhub-creds` in Jenkins credentials (Global) and **never** echo passwords into logs.

8. **Healthcheck and Verification:** After `docker run`, add a small wait + curl `http://localhost:8080/actuator/health` to verify service started successfully.

---

## Typical failure reasons & fixes (quick)

* **`mvn` not found** → Maven tool name mismatch / not installed on agent. Fix: configure Maven in Jenkins and correct `tools` name.
* **`docker: command not found`** → agent lacks Docker or Jenkins user lacks permission. Fix: install Docker or give Jenkins user docker group access (Linux) / ensure PATH (Windows).
* **Permission to push** → wrong credentialsId or wrong Docker Hub username. Fix: create correct Jenkins credential and use correct repo name.
* **Port already in use** → change host port mapping or stop previous service.

## Poll SCM

**Teacher:** What is Poll SCM?

**Student:** Jenkins checks repository changes periodically.

Example:

```text
H/2 * * * *
```

Meaning:
Check Git every 2 minutes.

If changes found → build starts.

---

## GitHub hook trigger

**Teacher:** Better than Poll SCM?

**Student:** Yes.

Why?
GitHub instantly notifies Jenkins.

Faster and less resource usage.

# Interview Question

**Teacher:** Poll SCM vs Build periodically?

**Student:**

Poll SCM:

* Checks source code changes
* Runs only if changes exist

Build periodically:

* Runs every scheduled time
* Changes not required
