# Teacher:

Design Pattern kya hota hai?

## Student:

**Definition**

> **Design Pattern is a well-proven solution for commonly occurring problems in software design.**

Simple language me:

Jab hum software banate hain to bahut baar same type ki problems baar-baar aati hain.

Har developer apne hisab se solution bana sakta hai.

Lekin sabse best solution kya hai?

Usi best aur proven solution ko **Design Pattern** kehte hain.

```
↓

```

**Answer**

❌ Nahi.

* Maintainable ho sakta hai

> "Ek standard solution use karo."

# Complete Singleton Code

```java
public class Samosa {

    private static Samosa samosa;

    private Samosa(){

    }

    public static Samosa getSamosa(){

        if(samosa == null){

            samosa = new Samosa();

        }

        return samosa;

    }

}
```

---

Usage

```java
Samosa s1 = Samosa.getSamosa();

Samosa s2 = Samosa.getSamosa();

System.out.println(s1.hashCode());

System.out.println(s2.hashCode());
```

```

25647
```

Same Object.

# Solution 1

Method Synchronization

```java
public synchronized static Samosa getInstance(){

    if(samosa==null){

        samosa=new Samosa();

    }

    return samosa;

}
```

---

## Kaise work karta hai?

Ek time pe

Sirf

```
One Thread
```

method execute karega.

---

Flow

```
T1

↓

Method

↓

Create Object

↓

Exit

↓

T2
```

---

Problem

Pure method lock ho jata hai.

Performance Slow.

---

# Solution 2

Synchronized Block

```java
if(samosa==null){

    synchronized(Samosa.class){

        samosa = new Samosa();

    }

}
```

---

## Teacher:

Ye better kyu hai?

## Student:

Sirf

```
Critical Code
```

lock hota hai.

Pure method nahi.

Performance Better.

---

Flow

```

↓

Enter Block

↓

Create Object

↓

Exit

↓

Thread2
```

# Teacher:

# Quick Revision

| Topic                    | Important Point                                                                           |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| **Pattern Type**         | **Creational Design Pattern**                                                             |
| **Purpose**              | Sirf **ek object** create karna aur reuse karna                                           |
| **Constructor**          | `private`                                                                                 |
| **Instance Variable**    | `private static`                                                                          |
| **Access Method**        | `public static getInstance()`                                                             |
| **Lazy Initialization**  | Object demand par create hota hai                                                         |
| **Eager Initialization** | Object class load hote hi create hota hai                                                 |
| **Thread Safety Issue**  | Multiple threads ek se zyada object bana sakte hain                                       |
| **Thread-safe Solution** | `synchronized` method ya `synchronized` block                                             |
| **Real-world Uses**      | Database Connection, Logger, Cache Manager, Configuration Manager, Spring Singleton Beans |
| **Singleton Break**      | Reflection, Serialization, Cloning (next video topics)                                    |

# Singleton Design Pattern - Breaking Singleton (Complete Q&A Notes)

## **Topic:** 3 Ways to Break Singleton Pattern + Solutions

### **Language:** Simple English + Hindi (Roman Hindi)

### **Level:** Beginner → Interview Level

---

# Introduction

## Teacher:

Pichle lecture me humne kya padha tha?

## Student:

Humne **Singleton Design Pattern** padha tha.

Usme humne sikha tha ki

* Sirf **ek object** create karna hai.
* Constructor **private** hota hai.
* Object **getInstance()** method se milta hai.
* Multi-threading me bhi Singleton kaise banate hain.

Lekin...

Aaj hum dekhenge ki Singleton ko **break (tod)** bhi sakte hain.

Aur uska solution bhi seekhenge.

---

# Teacher:

Singleton Pattern ko break karne ka matlab kya hota hai?

## Student:

Singleton ka rule hai

> **Only One Object**

Agar kisi tarike se

```java
Samosa s1 = Samosa.getInstance();

Samosa s2 = AnotherWay();
```

Aur

```text
s1 != s2
```

to

Singleton Pattern break ho gaya.

Matlab

Ek se jyada object ban gaya.

---

# Teacher:

Singleton Pattern kin-kin tariko se break ho sakta hai?

## Student:

Mainly **3 famous ways**

```
Singleton

↓

Reflection API

↓

Serialization

↓

Cloning
```

Ye teen interview me sabse jyada pooche jaate hain.

# 1. Reflection API

---

# Teacher:

Reflection API kya hoti hai?

## Student:

Reflection API Java ki ek powerful feature hai.

Ye runtime par

* Class ko inspect kar sakti hai.
* Private methods access kar sakti hai.
* Private fields modify kar sakti hai.
* Private constructor call kar sakti hai.

Normally

```java
private Samosa(){

}
```

Outside class

```java
new Samosa();
```

Allowed nahi hai.

Lekin Reflection API ke through

Private constructor ko bhi call kar sakte hain.

Isi wajah se Singleton break ho jata hai.

---

# Teacher:

Reflection API se Singleton kaise break hota hai?

## Student:

Suppose Singleton Class

```java
public class Samosa {

    private static Samosa samosa;

    private Samosa(){}

    public static Samosa getInstance(){

        if(samosa==null){

            samosa=new Samosa();

        }

        return samosa;
    }

}
```

Pehla Object

```java
Samosa s1 = Samosa.getInstance();
```

Ab Reflection se

```java
Constructor<Samosa> constructor =
Samosa.class.getDeclaredConstructor();
```

Private constructor ko accessible banaya

```java
constructor.setAccessible(true);
```

Ab

```java
Samosa s2 = constructor.newInstance();
```

Ab

```
s1

↓

Object1

-----------------

s2

↓

Object2
```

Do alag objects ban gaye.

Singleton Break.

---

# Teacher:

Reflection me `setAccessible(true)` ka kya kaam hai?

## Student:

Normally

```
private Constructor
```

Accessible nahi hota.

Ye line

```java
constructor.setAccessible(true);
```

Private constructor ko temporarily accessible bana deti hai.

Matlab

Private constructor bhi call ho sakta hai.

---

# Teacher:

Reflection se bachne ka solution kya hai?

## Student:

Constructor ke andar hi check lagao.

```java
private Samosa(){

    if(instance != null){

        throw new RuntimeException(
            "Trying to break Singleton Pattern"
        );

    }

}
```

---

Flow

First Time

```
instance == null

↓

Object Created
```

Second Time

Reflection

↓

Constructor Call

↓

instance != null

↓

Exception

↓

No New Object

---

Complete Example

```java
public class Samosa {

    private static Samosa instance;

    private Samosa(){

        if(instance!=null){

            throw new RuntimeException("Singleton Break Attempt");

        }

    }

    public static Samosa getInstance(){

        if(instance==null){

            instance=new Samosa();

        }

        return instance;

    }

}
```

---

# Teacher:

Is solution ka output kya hoga?

## Student:

Normal

```java
Samosa s1=Samosa.getInstance();
```

Works Fine.

Reflection

```java
constructor.newInstance();
```

Output

```
RuntimeException

Singleton Break Attempt
```

Singleton Safe.

```
↓

↓
```


Singleton Safe.

---

Complete Example

```java

    return getInstance();

}
```

# Teacher:

Singleton Safe.

Ye safest approach hai.

# Factory Design Pattern – Complete Q&A Notes (Teacher ↔ Student)

# Introduction

## Teacher:

Aaj hum kis Design Pattern ke baare me padhenge?

## Student:

Aaj hum **Factory Design Pattern** padhenge.

Ye **Creational Design Pattern** hai.

Iska kaam **objects create karna** hai, lekin ek **central factory class** ke through.

Is pattern me client ko ye nahi pata hota ki object kaise create ho raha hai.

---

# Teacher:

Factory Design Pattern ki definition kya hai?

## Student:

**Definition:**

> **Factory Design Pattern ek Creational Design Pattern hai jo object creation ki responsibility ek Factory Class ko de deta hai. Factory class input ke basis par required object create karke return karti hai.**

Simple words me:

> Client sirf batata hai **"Mujhe kis type ka object chahiye."**
> Factory us object ko bana kar de deti hai.

---

# Teacher:

Factory Design Pattern kab use karte hain?

## Student:

Jab

* Ek **Parent Class** ya **Interface** ho.
* Uske multiple **Child Classes** ho.
* Runtime par decide karna ho ki kaunsa object create karna hai.

Example

```text

        │

 │             │
AndroidDev   WebDev
```


```text

```

Banega.

Agar user kahe

```text
Web
```

To

```text
WebDeveloper Object
```

Banega.

Ye decision Factory karegi.

Interview me interviewer aksar ye questions puchte hain:

* **Factory Pattern aur Abstract Factory Pattern me exact difference kya hai?**
* **Abstract Factory ko "Factory of Factories" kyu bolte hain?**
* **Abstract Factory me extra abstraction layer ka kya benefit hai?**
* **Agar kal ek naya `Designer` ya `Manager` employee add ho jaye to code me kya changes karoge?**

# Teacher:

Builder Pattern ka complete code batao.

## Student:

### User

```java
public class User{

    private int id;

    private String name;

    private String email;

    private User(UserBuilder builder){

        this.id=builder.id;

        this.name=builder.name;

        this.email=builder.email;

    }

    public static class UserBuilder{

        private int id;

        private String name;

        private String email;

        public UserBuilder setId(int id){

            this.id=id;

            return this;

        }

        public UserBuilder setName(String name){

            this.name=name;

            return this;

        }

        public UserBuilder setEmail(String email){

            this.email=email;

            return this;

        }

        public User build(){

            return new User(this);

        }

    }

}
```

Reference objects ki sirf reference copy hoti hai.

---

## Q2.

Deep Copy kya hai?

**Answer**

Reference objects ki bhi nayi copy create hoti hai.

---

## Q3.

Java clone() default kya karta hai?

**Answer**

**Shallow Copy**

---

## Q4.

Deep Copy manually kaise karte hain?

**Answer**

Har nested reference object ko separately clone karte hain.

---

## Q5.

Prototype Pattern me Deep Copy kab use karte hain?

**Answer**

Jab object ke andar mutable objects ho aur independent copies chahiye.

---

## Q6.

Shallow Copy fast kyu hoti hai?

**Answer**

Kyuki sirf references copy hote hain, naye nested objects create nahi hote.

---

## Q7.

Deep Copy safe kyu hoti hai?

**Answer**

Kyuki har nested object ki separate copy banti hai, isliye ek object me change dusre ko affect nahi karta.

| Topic                 | Remember                                                  |
| --------------------- | --------------------------------------------------------- |
| **Shallow Copy**      | Reference Copy                                            |
| **Deep Copy**         | Object Copy                                               |
| **Primitive Values**  | Always copied                                             |
| **Reference Types**   | Problem area                                              |
| **Default clone()**   | Shallow Copy                                              |
| **Deep Copy**         | Manual implementation                                     |
| **Fastest**           | Shallow                                                   |
| **Safest**            | Deep                                                      |
| **Prototype Pattern** | Uses cloning; choose shallow or deep based on requirement |

# Introduction

## Student:

Aaj hum **Adapter Design Pattern** padhenge.

> **Adapter Design Pattern ek aisa Structural Design Pattern hai jo do incompatible interfaces ko connect karta hai, taki existing class ko bina modify kiye naye interface ke saath use kiya ja sake.**

Simple words me:

DESIGN PATTERNS - QUICK REVISION

====================================================

1. DESIGN PATTERN CATEGORIES
   ====================================================

Category      : Creational
Purpose       : Object Create Karna
Question      : Object kaise create kare?
Examples      : Singleton, Factory, Abstract Factory, Builder, Prototype

Category      : Structural
Purpose       : Objects ko Connect/Organize Karna
Question      : Do objects ko saath kaise kaam karaye?
Examples      : Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy

Category      : Behavioral
Purpose       : Objects ka Communication aur Behavior Manage Karna
Question      : Objects aapas me kaise interact kare?
Examples      : Observer, Iterator, Strategy, Command, State,
Chain of Responsibility, Mediator,
Memento, Template Method, Visitor, Interpreter

====================================================
2. CREATIONAL DESIGN PATTERNS
=============================

Purpose:
Object create karne ke different aur efficient ways.

Pattern               Use

Singleton             Sirf ek object create karna

Factory               Runtime me decide karna kaunsa object banana hai

Abstract Factory      Related objects ki family create karna

Builder               Complex object step-by-step banana

Prototype             Existing object ki copy (Clone) banana

Shortcut:

Need Object?
|
+--> Only One Object? --------> Singleton
|
+--> Runtime Decision? --------> Factory
|
+--> Family of Objects? -------> Abstract Factory
|
+--> Step-by-Step Object? -----> Builder
|
+--> Copy Existing Object? ----> Prototype

====================================================
3. STRUCTURAL DESIGN PATTERNS
=============================

Purpose:
Objects ko connect ya organize karna.

Pattern         Use

Adapter         Do incompatible objects ko connect karna

Bridge          Abstraction aur implementation alag rakhna

Composite       Tree structure banana

Decorator       Existing object me new feature add karna

Facade          Complex system ke liye simple interface dena

Flyweight       Memory save karna

Proxy           Real object ke access ko control karna

Shortcut:

Need Compatibility?
|
+--> Adapter

Need New Feature?
|
+--> Decorator

Need Simple Interface?
|
+--> Facade

Need Access Control?
|
+--> Proxy

Need Memory Optimization?
|
+--> Flyweight

Need Tree Structure?
|
+--> Composite

Need Separate Abstraction & Implementation?
|
+--> Bridge

====================================================
4. BEHAVIORAL DESIGN PATTERNS
=============================

Purpose:
Objects ka communication aur behavior manage karna.

Pattern                       Use

Observer                      One-to-Many Notification

Iterator                      Collection Traverse Karna

Strategy                      Runtime Algorithm Change Karna

Command                       Request ko Object banana

State                         Object ka behavior state ke hisab se change karna

Chain of Responsibility       Request ko chain me pass karna

Mediator                      Objects ke beech communication control karna

Memento                       Object ka previous state save karna

Template Method               Algorithm ka fixed structure dena

Visitor                       Existing classes me new operation add karna

Interpreter                   Language/Expression interpret karna

Shortcut:

Need Notification?
|
+--> Observer

Need Traversal?
|
+--> Iterator

Need Runtime Algorithm Change?
|
+--> Strategy

Need Request as Object?
|
+--> Command

Need State Change?
|
+--> State

Need Request Chain?
|
+--> Chain of Responsibility

Need Communication Manager?
|
+--> Mediator

Need Undo?
|
+--> Memento

Need Fixed Algorithm Steps?
|
+--> Template Method

Need New Operation?
|
+--> Visitor

Need Expression Parsing?
|
+--> Interpreter
