# 🎯 Interview Definition

**Question**

What is CQRS?

### Answer

CQRS stands for **Command Query Responsibility Segregation**.

It separates **Read** operations and **Write** operations into different services or different models so that they can be developed, optimized and scaled independently.

# 🎤 Interview Questions (Part 1)

## Q1. What is CQRS?

**Answer**

CQRS stands for **Command Query Responsibility Segregation**. It separates Read and Write operations into different services or models.

---

## Q2. What is Command?

**Answer**

Command means any operation that modifies the database.

Example:

* POST
* PUT
* DELETE
* PATCH

---

## Q3. What is Query?

**Answer**

Query means only reading data from the database.

Example:

* GET Product
* GET User
* GET Orders

---

## Q4. Why do we use CQRS?

**Answer**

Because in most applications Read requests are much higher than Write requests. CQRS allows us to scale and optimize Read and Write independently.

---

## Q5. Give one real-world example of CQRS.

**Answer**

Flipkart, Amazon, Instagram, Facebook.

Most users only search or view data. Very few users actually create or update data. So Read traffic is much higher than Write traffic.

---

## Q6. Can CQRS improve scalability?

**Answer**

Yes. Since Read and Write are separated, we can scale the Query service independently without affecting the Command service.

# 🎯 Interview Questions

### Q1. Why do we need CQRS?

**Answer:**

CQRS is used because Read requests are usually much higher than Write requests. It separates Read and Write so they can be optimized and scaled independently.

---

### Q2. What is the biggest problem without CQRS?

**Answer:**

Read and Write operations are mixed in one service, so we cannot scale or optimize them independently.

---

### Q3. Why is independent scaling not possible in a normal CRUD service?

**Answer:**

Because GET, POST, PUT, and DELETE are all inside the same service. If GET traffic increases, we must scale the entire service instead of only the Read part.

---

### Q4. How do complex queries affect performance?

**Answer:**

Complex joins and multiple API calls increase response time and reduce database performance.

---

### Q5. Why can Read performance become slow?

**Answer:**

Because the same database handles both Read and Write operations. Heavy SELECT queries compete with INSERT, UPDATE, and DELETE operations.

---

### Q6. Why is optimization difficult without CQRS?

**Answer:**

Since Read and Write use the same service and database, we cannot optimize them separately with different databases, caching strategies, or security rules.

# 🎤 Interview Questions

## Q1. How many microservices are there in CQRS?

**Answer**

Generally two:

* Command Service
* Query Service

---

## Q2. Which APIs are kept inside Command Service?

**Answer**

All APIs that modify the database.

Example:

* POST
* PUT
* DELETE
* PATCH

---

## Q3. Which APIs are kept inside Query Service?

**Answer**

All Read APIs.

Example:

* GET Product
* GET User
* GET Order

---

## Q4. Why do we use two databases in CQRS?

**Answer**

Because Read and Write are handled independently. This allows separate optimization, better performance, and independent scaling.

---

## Q5. Why do we need Kafka in CQRS?

**Answer**

Kafka synchronizes the Command Database and Query Database by sending events like Create Product, Update Product, and Delete Product.

---

## Q6. What happens after a POST request in CQRS?

**Answer**

1. Command Service saves data.
2. Command DB is updated.
3. Event is published to Kafka.
4. Query Service consumes the event.
5. Query DB is updated.

---

## Q7. Can we use RabbitMQ instead of Kafka?

**Answer**

Yes. Any messaging system like Kafka, RabbitMQ, or Redis Pub/Sub can be used to synchronize Command and Query services.

# Interview Questions

## Q1 Why do we need ProductEvent?

**Answer**

ProductEvent contains both the Product data and the event type (like CREATE_PRODUCT or UPDATE_PRODUCT), so the consumer knows what action to perform.

---

## Q2 Why not send Product directly?

**Answer**

Because the consumer cannot determine whether it should create, update, or delete the record without knowing the event type.

---

## Q3 What does KafkaTemplate do?

**Answer**

`KafkaTemplate` is used by the producer to publish messages to a Kafka topic.

---

## Q4 What does @KafkaListener do?

**Answer**

`@KafkaListener` listens to a Kafka topic and automatically invokes the annotated method whenever a new message arrives.

---

## Q5 What is the role of groupId?

**Answer**

The `groupId` identifies the consumer group. Consumers in the same group share the processing of messages from a topic.

---

## Q6 Why save to the Command DB before publishing the event?

**Answer**

The source of truth is the Command Database. Only after the write succeeds should the event be published so the Query side receives valid data.
