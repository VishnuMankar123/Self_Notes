# Q1. Sidecar Pattern kya hota hai?

## 👨‍🎓 Student

Sidecar Pattern ek **Design Pattern** hai.

Iska purpose hota hai

> **Primary Business Logic ko Secondary (Cross Cutting) Logic se alag rakhna.**

Simple language me

Main service sirf apna kaam kare.

Extra kaam kisi aur service ko de diya jaye.

Isi extra service ko bolte hain

**Sidecar Service**

---

## Example

Suppose mere paas ek

**Order Service**

Uska actual kaam hai

* Create Order
* Update Order
* Delete Order

Lekin Order Service ko aur bhi kaam karne padte hain

* Logging
* Monitoring
* Metrics
* Authentication
* Tracing

Ye sab business logic nahi hai.

Ye sirf support karte hain.

To hum in sab ko alag service me shift kar dete hain.

Yehi Sidecar Pattern hai.

# Video Architecture (Simplified)

```
                    Client
                      |
                      |
               Book Service
          (Business Logic Only)
                      |
          Write Logs to File
                      |
                      V
      ----------------------------
      Remote Log File (/logs)
      ----------------------------
                      |
                      |
                Sidecar Service
             Read Logs Every Minute
                      |
                      |
        Send Logs to Console
      (Real World -> ELK / Splunk)
```

# Primary Task vs Secondary Task

| Primary Task | Secondary Task |
| ------------ | -------------- |
| Add Book     | Logging        |
| Get Book     | Monitoring     |
| Update Book  | Metrics        |
| Delete Book  | Authentication |

---

# Why Sidecar?

| Without Sidecar        | With Sidecar           |
| ---------------------- | ---------------------- |
| Duplicate Logging Code | Single Logging Service |
| Hard to Maintain       | Easy Maintenance       |
| Tight Coupling         | Loose Coupling         |
| Complex Service        | Clean Service          |
| Difficult Updates      | Easy Updates           |

---

# ⭐ Interview Tip

Interviewer:
**Why do we need Sidecar Pattern?**

Simple Answer:

> "Sidecar Pattern use hota hai Cross Cutting Concerns jaise Logging, Monitoring, Metrics aur Authentication ko Main Business Logic se separate rakhne ke liye. Isse code clean, reusable aur maintainable ban jata hai."

# ✅ Part 1 Summary

* **Sidecar Pattern** = Primary aur Secondary task ko alag karna.
* **Cross Cutting Concern** = Logging, Monitoring, Metrics, Authentication, Tracing.

* Duplicate code avoid hota hai.
* Sidecar alag language me bhi likha ja sakta hai (Polyglot).
