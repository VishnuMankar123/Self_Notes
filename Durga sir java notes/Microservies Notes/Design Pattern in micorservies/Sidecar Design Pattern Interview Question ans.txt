# 1. What is Sidecar Pattern?

### Answer

Sidecar Pattern ek **Microservice Design Pattern** hai.

Isme hum **Cross Cutting Concerns** (Logging, Monitoring, Authentication, Metrics, Tracing) ko Main Business Service se alag ek service me rakhte hain.

Isse main service clean aur maintainable rehti hai.

---

# 2. Why do we use Sidecar Pattern?

### Answer

Hum Sidecar Pattern use karte hain because

* Code duplicate nahi hota.
* Business logic clean rehta hai.
* Maintenance easy ho jati hai.
* Cross Cutting Concern easily manage hote hain.

---

# 3. What is Cross Cutting Concern?

### Answer

Cross Cutting Concern wo functionality hai jo har microservice me common hoti hai.

Example

* Logging
* Monitoring
* Metrics
* Authentication
* Authorization
* Tracing

Ye business logic nahi hoti.

---

### Answer

Bike aur Sidecar.

Bike ka kaam chalna hai.

Sidecar ka kaam saman carry karna hai.

Dono ka kaam alag hai.

Waise hi

Microservice business logic karti hai.

Sidecar logging ya monitoring karta hai.

# 5. What problem does Sidecar Pattern solve?

### Answer

Ye duplicate code ko remove karta hai.

Agar 10 microservices me logging likhenge to same code har service me hoga.

Sidecar me sirf ek baar logging implement karte hain.

# 6. Which tasks are usually handled by Sidecar?

Sidecar me sirf ek service update karni padti hai.

# 12. What is the responsibility of Logging Service?

### Answer

Logging Service

# 13. How do Book Service and Sidecar communicate?

Direct API call nahi hoti.

### Answer

Kyuki Book Service continuously logs generate karti hai.

Scheduler har fixed interval me log file read karta hai.

# 19. Why do we run both containers in one Kubernetes Pod?

### Answer

Kyuki dono closely related hain.

Same network share karte hain.

Same volume share karte hain.

Communication fast hota hai.

---

# 20. What is the advantage of sharing a volume?

### Answer

Sidecar usi shared volume se log read karega.

Copy karne ki zarurat nahi.

---

# 21. If tomorrow ELK is replaced with Splunk, what changes?

### Answer

Sirf Sidecar Service change hogi.

Book Service me koi change nahi hoga.

Ye Sidecar ka biggest advantage hai.

---

# 22. What is Loose Coupling?

### Answer

Ek service change hone se dusri service affect na ho.

Ye Loose Coupling hai.

---

# 23. What is Tight Coupling?

### Answer

Agar logging code Book Service ke andar hi likha ho aur logging change hone par Book Service modify karni pade.

Ye Tight Coupling hai.

# 🔥 Interviewer Trap Question

### Q. Sidecar aur API Gateway same hote hain?

**Answer:**

❌ Nahi.

**API Gateway** client requests ko route karta hai aur authentication, rate limiting jaise gateway-level concerns handle karta hai.

**Sidecar** ek specific microservice ke saath chalne wala helper container/service hota hai jo logging, monitoring, metrics, tracing jaise cross-cutting concerns handle karta hai.

---

# ⭐ Final Revision (30 Seconds)

* Sidecar = Separate helper service.
* Purpose = Cross Cutting Concern ko separate karna.
* Common Uses = Logging, Monitoring, Metrics, Tracing.
* Benefits = Loose Coupling, Clean Code, Reusability.
* Kubernetes = Main container + Sidecar container same Pod me.
* Communication = Shared volume/file ya localhost networking.
* Real Tools = ELK, Splunk, Fluentd, Prometheus ecosystem.
