
========================================================================================================================
GraphQL kya hai?

GraphQL ek query language for APIs hai jisme client sirf required fields hi maang sakta hai. REST ke over-fetching/under-fetching problems solve karta hai.
========================================================================================================================
Graphql kay hota hai ?

GraphQL API **ek modern API technology** hai jo client ko **exact data** request karne ki freedom deti hai — na zyada, na kam.

Isko Facebook ne banaya tha REST API ke drawbacks solve karne ke liye.

---

# ✅ **GraphQL kya hai? (Simple Definition)**

**GraphQL ek query language hai APIs ke liye, jisme client sirf wohi fields maang sakta hai jo usko chahiye.**

REST API me:

* Server fixed response deta hai
* Client ko zyada data mil jata hai (over-fetching)
* Kabhi data kam milta hai to multiple API calls karni padti hain (under-fetching)

GraphQL me:
👉 **Client apna response format khud define karta hai**
👉 **Ek hi API endpoint se multiple data fetch ho sakta hai**

---

# 🔥 Example (Simple)

### 🎯 REST API (Traditional):

`/users/1`
Response fix:

```
{
  "id": 1,
  "name": "Vishnu",
  "email": "vishnu@gmail.com",
  "mobile": "9999999999",
  "address": "Pune"
}
```

Aapko sirf “name” chahiye, lekin server pura data bhej deta hai.

---

### 🎯 GraphQL:

Aap query likhoge:

```
{
  user(id: 1) {
    name
  }
}
```

Response sirf:

```
{
  "name": "Vishnu"
}
```

👉 **Client decides what data to fetch.**

### ✔ 1. Over-fetching aur Under-fetching solve

### ✔ 2. Ek hi endpoint hota hai

### ✔ 5. Developer friendly

GraphiQL tools me live testing hoti hai.

# ✅ **1. Query → Data Fetch Karne Ke Liye**

* Data **read** karne ke liye

---

### ⭐ Query ke features:

* **Read-only** operations
* **Caching friendly**
* Server state change nahi hota
* Complex JOIN (user + posts + orders) ek hi request me

### 🟦 Spring Boot Resolver Example:

```java

public User getUser(@Argument Long id) {
```

# 🟦 **GraphQL Schema kya hota hai? (Deep Explanation)**

### **Definition:**

GraphQL Schema ek **contract** hota hai jo define karta hai ki:

* API me kaun-kaunse **types** available hain
* Har type me kaun-se **fields** hain
* Kaun-se **queries** allowed hain
* Kaun-se **mutations** allowed hain
* Kaun-se field ke andar kaun-sa data milega
* Har field ka **return type** kya hoga

**Schema decide karta hai: API ka structure kaisa hoga.**

Yeh `schema.graphqls` file me likhte hain.

---

# ⭐ **Simple language me:**

Schema = **API ka blueprint**
Client + Server dono isi schema ke rules follow karte hain.

Isko GraphQL ki **Schema Definition Language (SDL)** me likhte hain.

---

# 🟩 **Schema ke 4 Main Parts (Deep):**

## **1. Types**

Isme hum batate hain ki humare data me kaun-se objects hain.

Example:

```graphql
type User {
  id: ID!
  name: String!
  age: Int
}
```

👉 Yeh batata hai ki `User` ek GraphQL type hai.
👉 Iske andar 3 fields hain.

---

## **2. Fields**

Field = object ka data column jaise.

Example:

```
name: String!
```

Matlab:

* `name` ek field hai
* `String` return karega
* `!` means **NULL allowed nahi**

---

## **3. Queries**

Server se **data fetch** karne ke entry point.

Example:

```graphql
type Query {
  user(id: ID!): User
  allUsers: [User]
}
```

Matlab:

* `user(id)` → 1 User deta hai
* `allUsers` → User ki list deta hai

REST me:
`GET /users/1`
`GET /users`

GraphQL me:
Ek hi endpoint `/graphql`

---

## **4. Mutations**

Server me **data change** karne ke entry point.

Example:

```graphql
type Mutation {
  createUser(input: UserInput): User
  updateUser(id: ID!, input: UserInput): User
  deleteUser(id: ID!): Boolean
}
```

Matlab:

* `createUser` → new user create karega
* `updateUser` → existing ko update karega
* `deleteUser` → true/false return karega

REST me:
POST / PUT / DELETE

# 🟦 **Resolver kya hota hai? (Deep Explanation)**

### 📌 **Definition**

GraphQL resolver ek **function/method** hota hai jo **GraphQL field ka actual data** return karta hai.

GraphQL query sirf **structure define karti hai**,
But **data kaise aayega** — ye resolver batata hai.

---

# 🟢 Simple Example samajh lo:

Query:

```graphql
{
```

### 1️⃣ `user(id:1)` ka data kaise lana?

→ Yeh Query Resolver karega.

### 2️⃣ user ke andar `name` kaise lana?

→ Yeh field resolver ya model ka default getter handle karega.

### ✔ Step 4: Resolver ko **arguments** + **parent object** pass karta hai

### ✔ Step 6: GraphQL result ko JSON structure me format karta hai

# 🟢 Example Flow (VERY EASY)

Query:

```graphql
{
  user(id:1) {
    name
    orders { product }
  }
}
```

Flow:

1. **user(id:1)** → call Query Resolver
2. User return hua → `{ id:1, name:"Vishnu" }`
3. **orders** field dekhi → Field Resolver call
4. orders(User user) → id:1 se DB call
5. Orders return → combine with user
6. Final JSON bana → client ko return

GraphQL sirf structure define karta hai, but data kaise fetch hoga — database se, service se, ya external API se — yeh resolver decide karta hai.
Query, Mutation, aur nested fields sab apne resolvers ke through resolve hote hain. GraphQL internally har field ke liye matching resolver dhundta hai aur us function ko execute karke final JSON response banata hai.**

# 🟦 **GraphQL Introspection kya hota hai? (Simple Explanation)**

**Introspection = GraphQL API ka self-documentation system.**

Matlab:

👉 Client GraphQL server se **uska schema pooch sakta hai**
👉 API ke andhar ka structure khud bata deta hai
👉 Kaun-se types, queries, mutations available hain
👉 Kaun-se fields exist karte hain
👉 Kya return type hai
👉 Konsa field optional / non-null hai

**Ye sab kuch GraphQL ek special query ke through bata deta hai.**

---

# 🟢 Simple Bhasha Me:

Jaisa tum kisi dukaan wale se poochte ho —
"Yahan kya kya milta hai?"

GraphQL me client server se pooch sakta hai —
"Tumhari API me kya kya milta hai?"

GraphQL API **khud bata deti hai**.
Yahi introspection hai.

---

```graphql
  }
```

# 🟦 **GraphQL Fragment kya hota hai? (Simple Explanation)**

**Fragment = Query ka reusable part.**

Matlab agar tumko **same fields** baar-baar query me likhne pad rahe hain,
to unko ek **fragment** me bana lo
aur jaha-jaha chahiye waha use kar lo.

---

# 🟢 Simple Real-Life Example

Tum 3 jagah pe **User ka id, name, email** fetch kar rahe ho:

### Without Fragment:

```graphql
{
  user1: user(id: 1) {
    id
    name
    email
  }
  user2: user(id: 2) {
    id
    name
    email
  }
  user3: user(id: 3) {
    id
    name
    email
  }
}
```

⭐ Same fields baar-baar likhne pad rahe hain.

---

# 🟩 Ab Fragment use karte hain:

```graphql
fragment userFields on User {
  id
  name
  email
}

{
  user1: user(id: 1) {
    ...userFields
  }
  user2: user(id: 2) {
    ...userFields
  }
  user3: user(id: 3) {
    ...userFields
  }
}
```

* Fragment me tum ek baar fields likh diye
* Fir use jaha-jaha chahiye “...” se include kar liya

👉 **code short ho gaya
👉 maintain karna easy
👉 repeated code hat gaya**

---

# 🟥 WHY Fragment Useful? (Important for Interview)

### ✔ 1. Code Reuse

Same fields baar-baar likhne ki zarurat nahi.

### ✔ 2. Maintenance Easy

Agar kal email field hatana ho — ek hi jagah change karna padega.

### ✔ 3. Complex Query me Structure Clean ho jata hai

React, Angular apps me fragments bahut use hote hain.

---

# 🟦 Spring Boot wala Example

Schema:

```graphql
type User {
  id: ID!
  name: String!
  email: String!
  age: Int
}
```

Client Query (with fragment):

```graphql
fragment basicFields on User {
  id
  name
}

query {
  user(id: 1) {
    ...basicFields
    email
  }
}
```

Spring Boot ko koi extra code nahi likhna hota.
GraphQL engine automatically fragment expand karta hai.

---

# 🟩 Fragment Internally Kaise Work Karte Hain?

GraphQL engine jab query receive karta hai:

### 1️⃣ Fragment definition read karta hai

```
fragment userFields on User { id name email }
```

### 2️⃣ Fragment name find karta hai query me

```
...userFields
```

### 3️⃣ Exactly same fields “expand” karke final query banata hai

GraphQL internally isko is tarah convert kar deta hai:

```graphql
{
  user(id:1) {
    id
    name
    email
  }
}
```

Tumko manually likhne ki zarurat nahi —
GraphQL engine automatically karta hai.

---

# ⭐ Interview Perfect Answer:

**GraphQL Fragment ek reusable query block hota hai jisme hum commonly required fields ko define karte hain. Isse hum same fields ko multiple jagah repeat nahi karte. Fragment query ko readable, maintainable aur DRY (Don’t Repeat Yourself) banata hai. Fragment ko `...fragmentName` syntax se include kiya jata hai.**

# 🟦 **GraphQL Directives kya hoti hain?**

**Directive = Query me dynamic conditions add karne ka tarika.**

Matlab:

👉 Query runtime (code run hone ke time) me decide karegi

* Kaun-sa field include karna hai
* Kaun-sa field skip karna hai
* Data ko kaise handle karna hai

Yeh **if/else** jaisa behavior GraphQL me add karta hai.

---

# 🟢 **Simple real-life example se samajho**

Tum mobile app bana rahe ho.

Kabhi tumko user ka **email** chahiye, kabhi nahi.

Agar "emailRequired = true" ho
→ email field fetch karna.

Agar false ho
→ email field skip karna.

Yeh possible hai **@include** aur **@skip** directives se.

---

# 🟦 **1. @include(if: condition)**

**Agar condition true ho → field include karo**.

Example:

```graphql
query getUser($showEmail: Boolean!) {
  user(id: 1) {
    name
    email @include(if: $showEmail)
  }
}
```

Variables:

```json
{
  "showEmail": true
}
```

Output:

```
{
  "user": {
    "name": "Vishnu",
    "email": "abc@gmail.com"
  }
}
```

Agar variable false ho:

```json
{
  "showEmail": false
}
```

Output:

```
{
  "user": {
    "name": "Vishnu"
  }
}
```

👉 Email field automatically remove ho gaya.

---

# 🟥 **2. @skip(if: condition)**

**Agar condition true ho → field skip karo**.

Example:

```graphql
query getUser($skipEmail: Boolean!) {
  user(id: 1) {
    name
    email @skip(if: $skipEmail)
  }
}
```

---

# 🟩 **Why Directives are useful?**

### ✔ Fetch only required fields

(Optimize data, save bandwidth)

### ✔ Conditional logic from client

(Backend code change nahi karna)

### ✔ Same query har situation me use ho sakti hai

(Frontend me clean code)

---

# 🟦 **More Advanced Directives (Important for interview)**

### 1️⃣ **@deprecated**

Field deprecated karne ke liye.

Schema me:

```graphql
type User {
  oldField: String @deprecated(reason: "Use newField instead")
  newField: String
}
```

Tools jaise GraphiQL is field ko strike line dikhayenge.

---

### 2️⃣ **@specifiedBy**

Custom scalar ke liye URL link add karta hai.

---

# 🟧 **Spring Boot me Directives ka role**

Spring Boot ko directives handle karna nahi padta.
**GraphQL engine automatically**:

* include/skip
* deprecated
* variables
* filtering

Ye sab manage karta hai.

Backend me tumhe kuch extra code nahi likhna padta.

---

# ⭐ **Interview me perfect answer**

**GraphQL directives special annotations hoti hain jisse hum query me dynamic behavior add kar sakte hain. Common directives jaise `@include` aur `@skip` condition ke basis par fields ko include ya skip karte hain. Directives query ko flexible banati hain aur unnecessary data fetch nahi hota, isse performance improve hoti hai.**

public class CustomExceptionResolver implements DataFetcherExceptionResolver {
  @Override
  public Mono<DataFetcherExceptionResolverResult> resolveException(
         Throwable ex, DataFetchingEnvironment env) {
         return Mono.just(DataFetcherExceptionResolverResult.newResult().error(
                 GraphqlErrorBuilder.newError(env).message(ex.getMessage()).build()
         ).build());
  }
}
