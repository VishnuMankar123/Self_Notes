# Introduction of Design Pattern - Top 20 Interview Questions & Answers

## Q1. What is a Design Pattern?

### Answer

Design Pattern ek **proven solution** hai jo software design ki **common problems** ko solve karta hai.

Simple language me:

> "Jab same problem baar-baar aati hai, uska industry me jo best solution use hota hai usko Design Pattern kehte hain."

---

## Q2. Why do we need Design Patterns?

### Answer

Har developer alag tareeke se code likh sakta hai.

Design Pattern use karne se:

* Standard solution milta hai.
* Code maintainable hota hai.
* Code reusable hota hai.
* Team me sab same approach follow karte hain.

---

## Q3. Is Design Pattern a code?

### Answer

**No.**

Ye ready-made code nahi hai.

Ye sirf ek **idea** ya **blueprint** hai.

Implementation hum Java, Python, C#, JavaScript kisi bhi language me kar sakte hain.

---

## Q4. What is the main objective of Design Patterns?

### Answer

Main objective hai:

* Reusable code
* Maintainable code
* Scalable application
* Common problems ka proven solution dena

---

## Q5. What is the difference between Design Pattern and Algorithm?

### Answer

| Algorithm              | Design Pattern                 |
| ---------------------- | ------------------------------ |
| Logic solve karta hai  | Design problem solve karta hai |
| Step-by-step solution  | Best design approach           |
| Example: Binary Search | Example: Singleton             |

---

## Q6. Who introduced the concept of Design Pattern?

### Answer

**Christopher Alexander**

Year: **1977**

Pehle Architecture field me introduce kiya gaya tha.

---

## Q7. Who popularized Design Patterns in Software Engineering?

### Answer

**Gang of Four (GoF)**

Ye 4 authors hain:

* Erich Gamma
* Richard Helm
* Ralph Johnson
* John Vlissides

1995 me inhone famous book publish ki thi.

---

## Q8. What is GoF?

### Answer

GoF ka full form hai:

**Gang of Four**

Ye 4 authors hain jinhone Design Patterns ko software industry me popular banaya.

---

## Q9. How many types of Design Patterns are there?

### Answer

Mainly **3 Types**

1. Creational
2. Structural
3. Behavioral

---

## Q10. What is Creational Design Pattern?

### Answer

Ye Object Creation se related hota hai.

Question:

> Object kaise create kare?

Examples

* Singleton
* Factory
* Builder
* Prototype
* Abstract Factory

---

## Q11. What is Structural Design Pattern?

### Answer

Ye batata hai

Classes aur Objects ko kaise organize kare.

Examples

* Adapter
* Proxy
* Decorator
* Composite
* Facade

---

## Q12. What is Behavioral Design Pattern?

### Answer

Ye batata hai

Objects ek dusre ke saath communication kaise kare.

Examples

* Observer
* Strategy
* State
* Command
* Iterator

---

## Q13. Can we use Design Patterns in every project?

### Answer

Mostly **Yes**.

Lekin har problem me Design Pattern use nahi karna chahiye.

Jahan zarurat ho wahi use karo.

---

## Q14. What are the advantages of Design Patterns?

### Answer

* Code Reusable
* Code Maintainable
* Readable Code
* Loose Coupling
* Scalable Application
* Industry Standard

---

## Q15. What are the disadvantages of Design Patterns?

### Answer

* Beginner ke liye difficult ho sakte hain.
* Har problem me use nahi karna chahiye.
* Galat jagah use karne se code unnecessary complex ho jata hai.

---

## Q16. What is Loose Coupling?

### Answer

Loose Coupling ka matlab

Classes ek dusre par **kam depend** kare.

Benefit:

Ek class me change karne se dusri class par kam impact padta hai.

---

## Q17. When should we use Design Patterns?

### Answer

Jab

* Code repeat ho raha ho.
* Object creation complex ho.
* Future me changes expected ho.
* Multiple developers project par kaam kar rahe ho.
* Maintainable code banana ho.

---

* Restaurant Order → Factory Pattern

Spring me bahut saare Design Patterns use hote hain.

# Breaking Singleton Pattern – 25 Advanced Interview Questions & Answers (4+ Years Java Backend)

**Based on your Design Pattern notes** 

> **Language:** Simple English + Hindi (Interview Style)

---

# Q1. What does "Breaking Singleton" mean?

### Answer

Breaking Singleton ka matlab hai **Singleton Pattern ka rule tod dena**, yani sirf ek object ki jagah multiple objects create ho jana.

---

# Q2. How many ways can Singleton be broken?

### Answer

Java me mainly **3 ways** hain:

* Reflection API
* Serialization
* Cloning

---

# Q3. Which way is most commonly asked in interviews?

### Answer

**Reflection API** sabse jyada interview me pucha jata hai.

---

# Q4. What is Reflection API?

### Answer

Reflection API Java ka feature hai jo runtime par class ke private constructor, methods aur fields ko access kar sakta hai.

---

# Q5. How does Reflection break Singleton?

### Answer

Reflection private constructor ko accessible bana deta hai.

Fir

```java
constructor.newInstance();
```

call karke naya object create kar deta hai.

Result:

```
Singleton Object 1

Reflection

↓

Singleton Object 2
```

---

# Q6. What is the purpose of `setAccessible(true)`?

### Answer

Ye private constructor ya private method ko temporarily accessible bana deta hai.

Isi wajah se Reflection private constructor call kar sakta hai.

---

# Q7. How do you prevent Reflection from breaking Singleton?

### Answer

Constructor ke andar check lagate hain.

```java
private Singleton() {
    if(instance != null){
        throw new RuntimeException("Singleton already exists");
    }
}
```

---

# Q8. Why does the constructor check work?

### Answer

Pehla object normal create hoga.

Reflection jab second object banane ki koshish karega tab `instance != null` hoga aur exception throw ho jayegi.

---

# Q9. What is Serialization?

### Answer

Serialization ka matlab Java Object ko Byte Stream me convert karna.

```
Object

↓

File / Network
```

---

# Q10. What is Deserialization?

### Answer

Byte Stream se object ko wapas Java Object banana.

```
File

↓

Java Object
```

---

# Q11. How does Serialization break Singleton?

### Answer

Deserialize karte waqt Java naya object create kar deta hai.

Result

```
Original Object

↓

Serialize

↓

Deserialize

↓

New Object
```

Singleton break ho jata hai.

---

# Q12. How do you prevent Serialization from breaking Singleton?

### Answer

`readResolve()` method use karte hain.

```java
protected Object readResolve() {
    return instance;
}
```

---

# Q13. When is `readResolve()` called?

### Answer

Automatically **deserialization ke time** call hota hai.

Ye existing Singleton object return karta hai.

---

# Q14. What is Cloning?

### Answer

Cloning ka matlab existing object ki exact copy banana.

```java
obj.clone();
```

---

# Q15. How does Cloning break Singleton?

### Answer

clone() method ek naya object create kar deta hai.

Result

```
Original Object

↓

clone()

↓

Duplicate Object
```

---

# Q16. How do you prevent Cloning?

### Answer

clone() method override karke exception throw kar do.

```java
@Override
protected Object clone() throws CloneNotSupportedException{
    throw new CloneNotSupportedException();
}
```

---

# Q17. Instead of exception, can we return the same instance?

### Answer

Haan.

```java
@Override
protected Object clone(){
    return instance;
}
```

Lekin exception throw karna better practice hai.

---

# Q18. Which Singleton implementation is safest?

### Answer

**Enum Singleton**

```java
public enum Singleton {
    INSTANCE;
}
```

---

# Q19. Why is Enum Singleton safest?

### Answer

Kyuki Java internally ensure karta hai ki

* Reflection
* Serialization
* Cloning

kisi se bhi multiple objects create na ho.

---

# Q20. Which frameworks use Reflection?

### Answer

Reflection ka use hota hai:

* Spring Framework
* Hibernate
* JUnit
* Jackson
* Dependency Injection

---

# Q21. Where is Serialization used in real projects?

### Answer

* Cache
* Session Management
* Distributed Systems
* Network Communication
* File Storage

---

# Q22. Where is Cloning used in real projects?

### Answer

* Prototype Pattern
* Object Copy
* Game Development
* Undo/Redo Feature

---

# Q23. Which way is the most dangerous for Singleton?

### Answer

Reflection.

Kyuki ye private constructor bhi access kar sakta hai.

---

# Q24. What follow-up questions are commonly asked after "What is Singleton?"

### Answer

Interviewer usually asks:

* Reflection se Singleton kaise break hota hai?

Reflection private constructor ko access karta hai, Serialization deserialization ke time naya object bana deti hai aur Cloning duplicate object create kar deti hai. Inke solutions respectively constructor check, `readResolve()` aur clone override karna hain. ### Answer

# Q11. Which SOLID Principle does Adapter follow?

### Answer

> **Mainly Open/Closed Principle. Existing class ko modify nahi karte, sirf naya Adapter add kar dete hain.**

---

# Q12. Does Adapter change business logic?

### Answer

> **Nahi Sir. Adapter sirf request convert karta hai. Business logic Adaptee ke andar hi rehti hai.**

---

# Q13. Why is Adapter called a Translator?

### Answer

> **Jaise English aur Hindi ke beech Translator hota hai, waise hi Adapter do incompatible interfaces ke beech translation karta hai.**

---

# Q14. Can Adapter improve code reusability?

### Answer

> **Yes Sir. Existing classes ko bina modify kiye naye systems me reuse kar sakte hain.**

---

# Q15. What happens if we remove the Adapter?

### Answer

> **Phir Client aur Adaptee directly communicate nahi kar paayenge kyunki unke interfaces compatible nahi hain.**

---

# Q16. In which situations do you use Adapter Pattern?

### Answer

> **Main Adapter Pattern use karunga jab:**
>
> * Third-party API integrate karni ho
> * Legacy system use karna ho
> * Payment Gateway change karna ho
> * Different interfaces ko connect karna ho

---

# Q17. Give a real project example.

### Answer

> **Suppose project me Paytm integration tha. Company ne Razorpay use karna start kiya. Agar application direct Paytm API use kar rahi hai to bahut code change hoga. Adapter bana kar Razorpay ko existing Payment interface ke through connect kar sakte hain.**

---

# Q18. What are the advantages of Adapter Pattern?

### Answer

> **Advantages:**
>
> * Existing code change nahi karna padta
> * Reusability increase hoti hai
> * Loose Coupling maintain hoti hai
> * Third-party integration easy hoti hai
> * Maintenance easy hoti hai

---

# Q19. What are the disadvantages?

### Answer

> **Extra Adapter class likhni padti hai. Design thoda complex ho sakta hai agar bahut adapters ban jayein.**

---

# Q20. Explain Adapter Pattern in one minute.

### Answer

> **Adapter Pattern ek Structural Design Pattern hai jo do incompatible interfaces ko connect karta hai. Client sirf Target Interface ko use karta hai. Adapter request ko convert karke Adaptee ko call karta hai. Isse existing code modify nahi karna padta aur code reusable aur loosely coupled rehta hai. Real-life example iPhone aur Android charger ka Adapter hai.**

---

# Step 1: Target Interface (Application isi ko jaanti hai)

# Step 2: Old Implementation (Paytm)

```java
public class PaytmPayment implements Payment {

    @Override
    public void pay(double amount) {

        System.out.println("Payment Done using Paytm : " + amount);

    }
}
```

Ye perfectly chal raha tha.

---

# Step 3: New Third-Party Class (Razorpay)

Maan lo Razorpay library ka code hai.

Hum isme change nahi kar sakte.

```java
public class Razorpay {

    public void makePayment(double amount) {

        System.out.println("Payment Done using Razorpay : " + amount);

    }

}
```

Notice

Paytm

```java
pay()
```

Razorpay

```java
makePayment()
```

Method names alag hain.

# Step 4: Adapter

```java
public class RazorpayAdapter implements Payment {

    private Razorpay razorpay;

    public RazorpayAdapter(Razorpay razorpay) {

        this.razorpay = razorpay;

    }

    @Override
    public void pay(double amount) {

        razorpay.makePayment(amount);

    }

}
```

Ye sabse important class hai.

Ye translation kar rahi hai.

Application bolegi

```java
pay()
```

Adapter internally bolega

```java
makePayment()
```

## 💡 Golden Rule (Lifetime Yaad Rakho)

Adapter Pattern me hamesha 3 cheezein hoti hain:

1. **Client** → Jo common interface use karta hai (`Payment`)
2. **Adaptee** → Third-party class jiska interface alag hai (`Razorpay`)
3. **Adapter** → Dono ke beech translator (`RazorpayAdapter`)

**Yehi Adapter Pattern ka poora concept hai.**
