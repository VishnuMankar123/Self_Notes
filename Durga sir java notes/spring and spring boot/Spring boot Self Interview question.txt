# What are Starter POMs in Spring Boot?

### Simple Definition

**Starter POMs** Spring Boot dwara diye gaye **predefined dependency packages** hote hain.

Ek Starter add karne se usse related sari required dependencies automatically project me aa jati hain.

> Matlab hume alag-alag dependencies manually add nahi karni padti.

---

## Without Starter POM

Agar Spring Framework use karte ho to tumhe manually add karna padega:

```xml
Spring Core

Spring MVC

Jackson

Validation

Tomcat

Logging

...
```

Bahut sari dependencies.

---

## With Starter POM

Sirf ek dependency add karo.

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Bas.

Spring Boot automatically required libraries download kar leta hai.

---

# Real Example

Suppose tum REST API banana chahte ho.

Sirf ye dependency add karo.

```xml
spring-boot-starter-web
```

Ye automatically add kar deta hai:

* Spring MVC
* Jackson (JSON)
* Validation
* Embedded Tomcat
* Logging

Tumhe manually kuch add nahi karna padta.

---

## Common Starter POMs

| Starter                         | Use                          |
| ------------------------------- | ---------------------------- |
| `spring-boot-starter-web`       | REST APIs & Web Applications |
| `spring-boot-starter-data-jpa`  | Database & Hibernate         |
| `spring-boot-starter-security`  | Security                     |
| `spring-boot-starter-test`      | Unit Testing                 |
| `spring-boot-starter-actuator`  | Monitoring                   |
| `spring-boot-starter-thymeleaf` | HTML Templates               |

---

## Interview Answer (30 sec)

> **Starter POMs are predefined dependency packages provided by Spring Boot. By adding a single starter dependency, all the required libraries for that feature are automatically included, reducing manual configuration and dependency management.**

### **Q. How to change the Embedded Tomcat server in Spring Boot?**

### **Answer**

By default, Spring Boot uses **Embedded Tomcat** as its web server.

Agar hume Tomcat ki jagah **Jetty** ya **Undertow** use karna ho, to hume `spring-boot-starter-web` se Tomcat dependency ko **exclude** karna padta hai aur required server ki dependency add karni padti hai.

**Steps:**

1. Exclude the default Tomcat dependency from `spring-boot-starter-web`.
2. Add the dependency of the required server (Jetty or Undertow) in `pom.xml`.
3. Build and run the application. Spring Boot automatically starts with the new embedded server instead of Tomcat.

---

### **Interview One-Liner (30 sec Answer)**

> "Spring Boot uses Embedded Tomcat by default. If we want to use Jetty or Undertow, we exclude the Tomcat dependency from `spring-boot-starter-web` and add the required server dependency in `pom.xml`."

---

### **Follow-up: Why would you replace Tomcat?**

**Answer:**

* **Jetty** → Lightweight and good for high concurrency.
* **Undertow** → High performance and low memory usage.
* Choice depends on project requirements.

---

### **Real Interview Question**

**Interviewer:** *Have you ever changed the embedded server in your project?*

**Answer:**

> "No, in my current project we use the default Embedded Tomcat. But I know that if required, we can replace it by excluding Tomcat and adding Jetty or Undertow dependency in `pom.xml`."

✅ **Yaad rakhne ki Trick:**

> **Default = Tomcat** → **Exclude Tomcat** → **Add Jetty/Undertow** → **Run Application**

### **Q. What is the difference between `@RequestMapping` and `@GetMapping`?**

### **Answer**

`@RequestMapping` ek generic annotation hai jo **multiple HTTP methods** handle kar sakta hai, jaise **GET, POST, PUT, DELETE**, etc. Isme hum `method` attribute specify karte hain.

`@GetMapping` `@RequestMapping` ka specialized version hai, jo sirf **GET requests** ko handle karta hai. Isse code zyada clean aur readable ho jata hai.

---

### **Interview One-Liner (30 sec Answer)**

> "`@RequestMapping` is a generic annotation that can handle all HTTP methods, whereas `@GetMapping` is a shortcut of `@RequestMapping(method = RequestMethod.GET)` and is used only for GET requests."

---

### **Example**

```java
// Using @RequestMapping
@RequestMapping(value = "/users", method = RequestMethod.GET)
public List<User> getUsers() {
    return userService.getUsers();
}
```

```java
// Using @GetMapping
@GetMapping("/users")
public List<User> getUsers() {
    return userService.getUsers();
}
```

👉 Dono same kaam karte hain, lekin `@GetMapping` zyada concise aur readable hai.

---

### **Follow-up: When should we use `@RequestMapping`?**

Use `@RequestMapping`:

* Class level par common URL define karne ke liye.
* Jab ek hi annotation se different HTTP methods handle karne hon.

Example:

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    // All APIs start with /api/users
}
```

---

### **Follow-up: When should we use `@GetMapping`?**

Use `@GetMapping` jab API sirf data **fetch (GET)** karti ho.

Examples:

* Get all users
* Get employee by ID
* Get product list

---

### **Real Interview Question**

**Interviewer:** *Can we use `@RequestMapping` instead of `@GetMapping`?*

**Answer:**

> "Yes. `@GetMapping` is just a shortcut for `@RequestMapping(method = RequestMethod.GET)`. Both work the same, but `@GetMapping` is preferred because it makes the code simpler and more readable."

---

## ✅ Yaad rakhne ki Trick

| Annotation        | Use                                             |
| ----------------- | ----------------------------------------------- |
| `@RequestMapping` | All HTTP methods (GET, POST, PUT, DELETE, etc.) |
| `@GetMapping`     | Only GET requests                               |
| `@PostMapping`    | Only POST requests                              |
| `@PutMapping`     | Only PUT requests                               |
| `@DeleteMapping`  | Only DELETE requests                            |

### **Easy Formula 🧠**

> **`@RequestMapping` = Parent (Generic)**
> **`@GetMapping` = Child (Only GET)**

# **19. How do you handle exceptions in Spring Boot?**

### **Answer**

Spring Boot handles exceptions using:

* `@ExceptionHandler`
* `@ControllerAdvice`

`@ExceptionHandler` handles specific exceptions, while `@ControllerAdvice` provides **global exception handling** for the entire application.

### **Interview One-Liner**

> "`@ExceptionHandler` handles specific exceptions, while `@ControllerAdvice` provides centralized exception handling across the application."

### **Example**

```java
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleException(Exception ex) {
        return ResponseEntity.badRequest().body(ex.getMessage());
    }
}
```

* Increased infrastructure cost
* More monitoring and deployment effort

### **Interview One-Liner**

> "Microservices improve scalability but increase operational complexity and infrastructure management."

---

# **29. What is the use of Containers in Microservices?**

### **Answer**

Containers package a microservice along with all its dependencies, making deployment easier and ensuring the application runs consistently across environments.

**Docker** is the most commonly used container platform.

### **Interview One-Liner**

> "Containers package a microservice with its dependencies, making deployment portable and consistent."

### **Real Project**

> "We use Docker containers to package Spring Boot microservices."

# **31. How do you access RESTful Microservices?**

### **Answer**

RESTful microservices can communicate using:

* `RestTemplate`
* A load-balanced `RestTemplate`
* (Modern approach) `WebClient` for reactive communication.

### **Interview One-Liner**

> "Microservices communicate using REST APIs through `RestTemplate` or, in modern Spring applications, `WebClient`."
