# ⭐ Part 2 — What is Reactive Programming?

---

### **Q1: Reactive programming hota kya hai?**

**Teacher:** Tell me, what is **Reactive Programming**?
**Student:** Reactive Programming ek **design pattern** hai jo **asynchronous** aur **non-blocking streams** use karke data aur events ko handle karta hai.

**Teacher:** Good! Only these two words are the heart of Reactive Programming:

* **Asynchronous**
* **Non-Blocking**

# ⭐ Part 3 — Real-Life Example (Waiter Example)

---

### **Q2: Sir, asynchronous and non-blocking ko simple language me kaise samjhe?**

**Teacher:** Imagine you go to a restaurant. A waiter takes your order and gives it to the kitchen.
Now tell me, kya waiter kitchen ke bahar khada hota hai jab tak food ready nahi hota?
**Student:** Nahi sir.

**Teacher:** That’s exactly **asynchronous non-blocking**.

* Waiter **order deta hai** → moves on
* Kitchen **background me food banata hai**
* Jab food ready → waiter ko **event/notification** milti hai

**Student:** So waiter = thread, kitchen = background processing, notification = event?
**Teacher:** Exactly! Very good.

---

# ⭐ Part 4 — Traditional Synchronous Blocking Model

---

### **Q3: Sir, old synchronous system me kya problem thi?**

**Teacher:** Old system me kya hota tha?
**Student:** Client request bhejta → server ek **thread allocate** karta
Us thread ko jab tak processing complete na ho → **wait** karna padta
= **Thread block ho jata**

**Teacher:** Aur agar processing 30 minutes le?
**Student:** Fir 30 minutes tak thread free nahi hota → next request handle nahi kar sakta.

**Teacher:** Correct. And threads are **limited** (example: only 20 threads).
Agar 20 threads busy ho gaye → new requests hang/slow.

This is called:

* **Synchronous**
* **Blocking**

---

# ⭐ Part 5 — Asynchronous + Non-Blocking Architecture

---

### **Q4: Reactive me kya different hota hai?**

**Teacher:** Ab batao reactive me thread wait karta hai?
**Student:** Nahi sir. Reactive me:

* Thread request accept karta hai
* Background me processing start karta hai
* Thread free ho kar dusri request le leta hai
* Jab processing complete hoti hai → **event publish hota hai**
* Subscriber ko **notification** milti hai

This is called:
✔ **Asynchronous**
✔ **Non-blocking**

**Teacher:** Great! So one thread can handle **multiple requests**.

---

# ⭐ Part 6 — Important Features of Reactive Programming

---

## **Q5: Sir features kya hote hain Reactive Programming ke?**

### **1️⃣ Asynchronous & Non-blocking**

**Student:** Reactive code **wait nahi karta**.
Thread free ho jata hai → efficiency & scalability **increase**.

---

### **2️⃣ Publisher–Subscriber model**

**Teacher:** Explain this.
**Student:**

* **Publisher** = event/data **produce** karta
* **Subscriber** = us event ko **receive** karta
* Jaise YouTube me: Channel = publisher, Viewer = subscriber

---

### **3️⃣ Functional Programming Style**

**Student:** Reactive me hum bohot use karte hain:

* **map()**
* **flatMap()**
* **filter()**
* **chaining**
* **streams**

Code becomes more readable and clean.

---

### **4️⃣ Event-driven Data Flow**

**Student:** Data kab aayega?
**Teacher:** Jab event publish hoga.

Client koi function call karta → wait nahi karta
Event flow ke through data aata hai → subscriber handle karta hai.

---

### **5️⃣ Backpressure**

**Teacher:** Backpressure kya hota hai?
**Student:** Jab subscriber ke paas zyada data aa raha ho aur woh handle nahi kar pa raha ho, toh woh publisher ko bol sakta hai:

“**Sir slow ho jao, mujhe itna hi data bhejo**.”

Publisher subscriber ki capacity ke hisaab se data bhejta hai.

This avoids overflow or overload.

 # ⭐ Part 2 — Blocking vs Non-Blocking (Most Important)

 ---

 ## **Q1: Sir, Blocking Web Application kya hota hai?**

 *(01:29 - 03:37)*

 **Teacher:** Simple words me batao — Blocking system me thread kya karta hai?
 **Student:** Sir, **thread request accept karta hai** → processing karta hai → **jab tak request complete nahi hoti, tab tak thread block rehta hai**.

 **Teacher:** Example?
 **Student:**

 * Request 1 aayi → **Thread 1** ne li
 * Processing me 5 minutes lag rahe hain
 * **Thread 1 5 minutes tak busy / block rahega**
 * Response ready hoga tabhi thread free hoga

 **Teacher:** Aur agar Request 2 aaye tab?
 **Student:** Fir **Thread 2** lega. But threads limited hote hain, so heavy traffic me server slow ho jata hai.

 ---

 ## **Q2: Non-Blocking kya hota hai?**

 *(04:08 - 05:50)*

 **Teacher:** Non-Blocking me thread ka behaviour kya hota hai?
 **Student:**

 * Thread request accept karta hai
 * IO processing ko **IO thread** ko delegate kar deta hai
 * **Thread turant free ho jata hai**
 * Thread next request bhi accept kar sakta hai
 * Meanwhile IO thread background me kaam karta rehta hai
 * Jab kaam complete hota hai → event publish hota hai → response milta hai

 **Teacher:** So non-blocking = **thread never waits**.
 **Student:** Yes sir. That’s why non-blocking is best for **high-traffic** applications.

 ---

 ## **Q3: Blocking vs Non-Blocking difference? (Simple Table)**

 | Feature                 | Blocking                | Non-Blocking               |
 | ----------------------- | ----------------------- | -------------------------- |
 | Thread waits?           | **Yes**                 | **No**                     |
 | Thread free?            | After work completes    | Immediately                |
 | Good for heavy traffic? | ❌ No                    | ✔ Yes                      |
 | Uses?                   | **Spring Web (Tomcat)** | **Spring WebFlux (Netty)** |

 # ⭐ Part 6 — 3 Important Transformations

 ---

 ## **Q9: Map kya karta hai?**

 *(19:03 - 20:12)*

 **Student:**

 * **Synchronous transformation**
 * Item ko modify karta hai
 * Type same rehta hai


 ## **Q10: FlatMap kya karta hai?**

 *(20:42 - 22:19)*

 * **Asynchronous transformation**
 * Return type can be new Mono

# ⭐ PART 4 — Publisher (01:44 – 03:05)

* Jo data *emit / publish* karega subscriber ko

**Teacher:** Publisher ke paas kitna method hota hai?

```java
void subscribe(Subscriber<? super T> s)
```

**Teacher:** Aur is method ko kaun call karta hai?

# ⭐ PART 5 — Subscriber (03:51 – 06:49)

**Teacher:** Subscriber ke 4 methods kaun se hain?

1️⃣ **onSubscribe(subscription)**

* Ek baar call hota hai
* Subscriber ko Subscription object deta hai

2️⃣ **onNext(T data)**

* Jab bhi publisher data bhejega, ye call hoga
* Data yahan milta hai

3️⃣ **onError(Throwable t)**

* Agar data bhejte time koi error aaye

4️⃣ **onComplete()**

* Jab data successfully deliver ho jaye
* No more data

# ⭐ PART 6 — Subscription (07:13 – 08:38)

1. **request(n)** → kisi n items ka data maango
2. **cancel()** → subscribe cancel karo

**Teacher:** Ye kis concept ke liye useful hai?

# ⭐ PART 7 — Processor (08:38 – 09:23)

# ⭐ PART 8 — Full Reactive Flow (Event Flow Explanation)

*(09:23 – 10:56)*

# ⭐ Pub–Sub Event Flow (Simple Explanation)

Imagine **Publisher = Teacher**
and **Subscriber = Student**

Reactive Streams flow works in this exact sequence:

# ⭐ Step-by-Step Explanation of the Diagram

---

## **1️⃣ Subscriber → Publisher : subscribe()**

**Student:** “Sir, mujhe aapka data chahiye.”
**Student calls:**

```java
publisher.subscribe(thisSubscriber);
```

📌 **Meaning:** Subscriber says “I want to subscribe”.

Arrow (blue) from **Subscriber → Publisher**.

---

## **2️⃣ Publisher → Subscriber : onSubscribe(subscription)**

Publisher replies:

**Publisher:** “Okay! Tum subscribe ho gaye.
Yeh lo tumhara **Subscription pass**.”

Publisher calls:

```java
subscriber.onSubscribe(subscription);
```

📌 **Subscription object** milta hai
→ Subscriber can now **request(n)** or **cancel()**

Arrow (orange) from **Publisher → Subscriber**.

---

## **3️⃣ Subscriber → Publisher : request(n)**

Subscriber requests how much data it wants:

**Student:** “Sir, mujhe bas **n items** chahiye.”

```java
subscription.request(n);
```

📌 **Backpressure** implemented here
Subscriber controls the flow.

Arrow (blue) from **Subscriber → Publisher**.

---

## **4️⃣ Publisher → Subscriber : onNext(data)**

Now Publisher starts sending data one-by-one.

For each item:

```java
subscriber.onNext(data);
```

➤ **If n = 5 → onNext() is called 5 times**
➤ Data moves **Publisher → Subscriber**

Green arrows in diagram.

---

## **5️⃣ Publisher → Subscriber : onComplete()**

When Publisher has sent **all data**:

```java
subscriber.onComplete();
```

**Publisher:** “All data delivered. Processing done.”

Arrow (top green) **Publisher → Subscriber**.

---

## **6️⃣ If any error occurs → onError()**

(Not shown in this image but part of flow)

```java
subscriber.onError(exception);
```

**Publisher:** “Error aaya while sending data.”

---

# ⭐ Full Flow in One Line

1. **subscribe()**
2. **onSubscribe(subscription)**
3. **request(n)**
4. **onNext(data)** repeated n times
5. **onComplete() / onError()**

# **PART 8 — `then()` Operator (Reactive Programming)**

*(15:44 – 17:42)*

### **Teacher:** `.then()` kya karta hai?

### **Student:**

1. Pehle Mono ko **complete hone deta hai**
2. Fir **second Mono execute** hota hai
3. Pehle Mono ka **data ignore** ho jata hai
4. Final output **sirf second Mono** ka hota hai

---

# ✔ **Example 1 — Simple Mono**

```java
Mono<String> m1 = Mono.just("First Mono Completed");
Mono<String> m2 = Mono.just("Second Mono Executed");

m1.then(m2)
  .subscribe(System.out::println);
```

### **Output:**

```
Second Mono Executed
```

**Why?**
Because `.then()` → first Mono complete → ignore its data → run second Mono → output second Mono’s result.

---

# ✔ **Example 2 — Logging + `then()`**

```java
Mono<Void> saveToDB = Mono.fromRunnable(() -> {
    System.out.println("Saving data...");
});

Mono<String> sendNotification = Mono.just("Notification sent!");

saveToDB
    .then(sendNotification)
    .subscribe(System.out::println);
```

### **Console Output:**

```
Saving data...
Notification sent!
```

---

# ✔ **Example 3 — Error Flow**

```java
Mono<String> m1 = Mono.error(new RuntimeException("Error Occurred!"));
Mono<String> fallback = Mono.just("Fallback Mono Running");

m1.then(fallback)
  .subscribe(
      System.out::println,
      err -> System.out.println("Error: " + err.getMessage())
  );
```

### **Output:**

```
Error: Error Occurred!
```

**Explanation:**
`.then()` second Mono ko tabhi chalata hai jab first Mono successfully complete ho.
Error hone par second Mono **execute nahi hota**.

---

# ✔ **Example 4 — Forced execution using onErrorResume**

```java
Mono<String> m1 = Mono.error(new RuntimeException("Something bad!"));

Mono<String> m2 = Mono.just("Second Mono executed after handling error.");

m1
  .onErrorResume(e -> Mono.empty())  // ignore error
  .then(m2)
  .subscribe(System.out::println);
```

### **Output:**

```
Second Mono executed after handling error.
```

# ⭐ **PART 2 — Repository क्यों ज़रूरी है? (00:55 – 02:20)**

**Teacher:** Java application database से data **कैसे fetch** करता है?
**Student:** Sir, उसके लिए हमें **Repository** बनानी पड़ती है।

**Teacher:** Repository क्या है?
**Student:**

* Repository एक **interface** है
* इसमें बहुत से methods पहले से बने होते हैं
* Example:

  * **findById()**
  * **findAll()**
  * **save()**
  * **deleteById()**

**Teacher:** ये methods कहाँ से मिलते हैं?
**Student:**
जब हम repository को extend करते हैं:

```java
public interface BookRepository
       extends ReactiveCrudRepository<Book, Integer> {}
```

तो Spring हमें automatically implementation दे देता है।

# ⭐ **PART 3 — Custom Finder Methods (Simple Search Without SQL) (05:00 – 08:00)**

**Teacher:** कैसे बनते हैं?
**Student:**
Naming convention follow करके:

### ✔ Example 1 — Find Book by Name

```java
Mono<Book> findByName(String name);
```

### ✔ Example 2 — Find Books by Author

```java
Flux<Book> findByAuthor(String author);
```

### ✔ Example 3 — Find Books by Publisher

```java
Flux<Book> findByPublisher(String publisher);
```

### ✔ Example 4 — Find Books by Name AND Author

```java
Flux<Book> findByNameAndAuthor(String name, String author);
```

**Teacher:** यह methods database में automatically SQL execute कर देती हैं?
**Student:** Yes Sir, Spring खुद से query generate करता है।

# ⭐ **PART 4 — Testing Finder Methods (StepVerifier) (09:00 – 12:30)**

**Teacher:** Finder methods test कैसे करते हैं?
**Student:** Using **StepVerifier**:

### ✔ Example

```java
StepVerifier.create(bookRepository.findByName("Java Book"))
    .expectNextCount(1)
    .verifyComplete();
```

* **expectNextCount(1)** → 1 record expected
* **verifyComplete()** → Flux/Mono successfully completed

# ⭐ **PART 5 — Query Methods using @Query (SQL Based) (13:30 – 17:00)**

**Teacher:** अगर complex SQL लिखना पड़े तो?
**Student:** फिर हम repository में **@Query** annotation use करते हैं।

### ✔ Example — Get Books Written By Specific Author

```java
@Query("SELECT * FROM book_details WHERE author = :author")
Flux<Book> getBooksByAuthor(String author);
```

**Teacher:** यहाँ `:author` क्या है?
**Student:** Sir, ये named parameter है जो method parameter से match होना चाहिए।

# ⭐ **PART 6 — Error Fixing (17:45 – 20:50)**

**Teacher:** Query क्यों fail हो रही थी?

→ इसलिए result zero आया।

**Fix:** सही field पास करना।

# ⭐ **PART 7 — Multiple Parameter Query (20:40 – 22:40)**
