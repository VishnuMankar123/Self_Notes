WebClient se aap HTTP calls kar sakte ho:

* GET request
* POST request

* Query params add karna
* JSON send karna

# 🧠 **Kaise work karta hai?**

### **1. Non-blocking architecture**

* Request bhejta hai
* Response ka wait nahi karta
* Thread free ho jata hai
* Jab response milta hai → callback trigger hota hai

Isse performance ⚡ FAST ho jati hai.

---

# ✔ WebClient architecture (simple explanation)

```
Client → WebClient → Server API
         |
         v
   (No waiting → Thread free)
         |
Response milta hai to callback execute → Data return
```

# 🌟 Basic Example 1: GET Request

```java
WebClient webClient = WebClient.create();

String response = webClient.get()
        .uri("https://jsonplaceholder.typicode.com/todos/1")
        .retrieve()
        .bodyToMono(String.class)
        .block();  // convert async → sync

System.out.println(response);
```

# 🌟 Example 2: POST with JSON Body

```java
WebClient client = WebClient.builder().build();

        .bodyValue(Map.of("id", 101, "name", "Vishnu"))
        .retrieve()
        .bodyToMono(String.class)
        .block();

System.out.println(result);
```

# 🌟 Example 3: Non-blocking version (async)

```java
webClient.get()
        .uri("https://api.example.com/users")
        .retrieve()
        .bodyToMono(String.class)
        .subscribe(resp -> {
            System.out.println("Response received: " + resp);
        });

System.out.println("Main thread free!");
```

Output:

```
Main thread free!
Response received: {...}
```

# ⭐ **`block()` kya hai?**

`block()` **reactive Mono ko synchronous data me convert karta hai**.
Simple words me:

⚡ **Non-blocking WebClient** ko **blocking** bana deta hai.

Matlab:

* WebClient async request bhejta hai
* Normally thread wait nahi karta
* `block()` use karoge → **thread ruk jayega** jab tak response nahi aata

---

# 🔍 Example:

### ❌ Without `block()` (non-blocking)

```java
webClient.get()
    .uri("https://api.com/users")
    .retrieve()
    .bodyToMono(String.class)
    .subscribe(resp -> System.out.println(resp));

System.out.println("Main thread free!");
```

Output:

```
Main thread free!
<Response comes later>
```

---

# ✔ With `block()` (blocking)

```java
String response = webClient.get()
        .uri("https://api.com/users")
        .retrieve()
        .bodyToMono(String.class)
        .block();

System.out.println("Main thread waits and prints response:");
System.out.println(response);
```

Output:

```
Main thread waits and prints response:
{...json...}
```

Thread response milne tak wait karega.

---

# 💡 `block()` = “wait for API result synchronously”

Aapka line:

```java
String result = client.post()
        .uri("https://api.example.com/data")
        .header("Authorization", "Bearer token123")
        .bodyValue(Map.of("id", 101, "name", "Vishnu"))
        .retrieve()
        .bodyToMono(String.class)
        .block();
```

Here:

✔ API call async se shuru hota hai
✔ `block()` = “wait until API returns result”
✔ Return type = String
✔ Calling thread busy rahega

---

# 🧠 WHY WebClient provides `block()`?

Because:

### ❗ Many projects do NOT use reactive programming

### ❗ Controllers are synchronous

### ❗ Services expect immediate return values

Example: **Spring Boot REST Controller**

```java
@GetMapping("/user")
public String getUser() {
    return webClient.get()
        .uri("https://api.com/user/101")
        .retrieve()
        .bodyToMono(String.class)
        .block(); // returns String directly
}
```

---

# 🧨 When NOT to use block()

### ❌ Inside reactive pipeline

### ❌ Inside `Flux`/`Mono` chain

### ❌ Large-scale high-throughput services

### ❌ Parallel high-load API calls

`block()` ruins the benefit of WebClient.

---

# ⭐ When to use block()

### ✔ For simple API calls

### ✔ When codebase is not reactive

### ✔ During migration from RestTemplate → WebClient

### ✔ When you want response NOW

### ✔ When writing simple Spring Boot controllers/services

# ⭐ **Mono kya hota hai? (Simple Explanation)**

### 👉 **Mono = Ek promise / future jo 0 ya 1 result dega.**

### 👉 **Mono = async container for a single value.**

### 👉 **Mono = WebClient ka response object.**

Java Future jaisa hota hai, but **more powerful + async + reactive**.

---

# ⭐ Mono basic idea (Like a box)

```
[  Mono<String>  ] → box me ek String result ayega future me
```

WebClient ka response hammesha **Mono** me milta hai:

```java
Mono<String> response = webClient.get()
                                 .uri(url)
                                 .retrieve()
                                 .bodyToMono(String.class);
```

But WebClient **tab tak API call nahi karta**
jab tak aap `subscribe()` ya `block()` nahi lagate.

---

# ⭐ Mono ALWAYS returns:

✔ **0 result** → empty
✔ **1 result** → data
❌ **Never multiple results** → (Flux me hota hai)

---

# ⭐ Example 1 — Mono returning a String (async)

```java
Mono<String> mono = Mono.just("Hello");
```

This means:

```
Mono me ek value "Hello" store hai (async)
```

---

# ⭐ Example 2 — API call Mono me milta hai

```java
Mono<String> result = webClient.get()
        .uri("https://api.com/data")
        .retrieve()
        .bodyToMono(String.class);
```

Yeh API call **abhi execute Nahi hoti**.
Mono sirf ek **pipeline** banata hai.

---

# ⭐ Mono execute kab hota hai?

### ❗ Only when you do:

### 1️⃣ `block()`

Synchronous call (thread wait karega)

```java
String response = result.block();
```

### 2️⃣ `subscribe()`

Asynchronous call (non-blocking)

```java
result.subscribe(res -> System.out.println("Response: " + res));
```

### 3️⃣ WebFlux controller return kare

(Spring automatically execute karta hai)

---

# ⭐ Mono ka use **kaha hota hai?**

### ✔ Asynchronous API calls (WebClient)

### ✔ Reactive pipelines

### ✔ Token generation

### ✔ Authentication

### ✔ Non-blocking backend

### ✔ File reading / streaming

### ✔ Kafka reactive clients
