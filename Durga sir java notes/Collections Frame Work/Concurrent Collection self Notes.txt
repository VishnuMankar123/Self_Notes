
> **Topic:** Concurrent Collections (Important Interview Q&A)

---

# Q1. Why were Concurrent Collections introduced in Java?

### Answer

Concurrent Collections were introduced in **Java 1.5** to solve the problems of traditional collections in multithreaded applications.

Problems with traditional collections:

* They are **not thread-safe** (ArrayList, HashMap).
* Old thread-safe collections (Vector, Hashtable) have **poor performance** because the whole collection is locked even for read operations.
* They throw **ConcurrentModificationException** if one thread modifies while another is iterating.

Concurrent Collections solve all these problems.

---

# Q2. What are the advantages of Concurrent Collections?

### Answer

1. Thread-safe.
2. Better performance than Vector and Hashtable.
3. Multiple threads can read and update safely.
4. No `ConcurrentModificationException`.
5. Suitable for scalable multithreaded applications.

---

# Q3. Why are Vector and Hashtable slower than Concurrent Collections?

### Answer

Vector and Hashtable use **one lock for the entire collection**.

Even if one thread is only reading, other threads must wait.

Concurrent Collections use a better locking mechanism, so multiple threads can work simultaneously, giving better performance.

---

# Q4. Why does ConcurrentModificationException occur?

### Answer

It occurs when:

* One thread is iterating over a collection.
* Another thread modifies the same collection simultaneously.

Example:

```java
ArrayList al = new ArrayList();
Iterator itr = al.iterator();
al.add("D");
```

This throws:

```
ConcurrentModificationException
```

---

# Q5. Why doesn't ConcurrentHashMap throw ConcurrentModificationException?

### Answer

Because its iterator works on a **read-only copy (snapshot)** of the map.

If another thread updates the map while iteration is going on, the iterator is not affected.

Hence no `ConcurrentModificationException`.

---

# Q6. What is ConcurrentHashMap?

### Answer

ConcurrentHashMap is a thread-safe implementation of `ConcurrentMap`.

Features:

* Allows concurrent read operations.
* Allows thread-safe write operations.
* Better performance than Hashtable.
* Does not throw `ConcurrentModificationException`.

---

# Q7. How does ConcurrentHashMap achieve better performance?

### Answer

ConcurrentHashMap does **not lock the entire map**.

Instead, it locks **only a particular bucket (Bucket Level Lock)** during update operations.

* Read operation → No lock required.
* Write operation → Only bucket-level lock.

Hence multiple threads can work simultaneously.

> **Interview Keyword:** Bucket Level Lock

---

# Q8. What is the default concurrency level of ConcurrentHashMap?

### Answer

Default concurrency level is **16**.

This means the map is internally divided into **16 smaller portions**, allowing multiple write operations simultaneously.

---

# Q9. Are null keys and null values allowed in ConcurrentHashMap?

### Answer

No.

ConcurrentHashMap does **not allow**

* null key
* null value

---

# Q10. What are the special methods of ConcurrentMap?

### Answer

### 1. putIfAbsent()

Adds an entry only if the key is not already present.

If key exists, old value remains unchanged.

---

### 2. remove(key, value)

Removes the entry only if both key and value match.

---

### 3. replace(key, oldValue, newValue)

Replaces the value only if the existing value matches the old value.

---

# Q11. Difference between put() and putIfAbsent()?

| put()                            | putIfAbsent()                           |
| -------------------------------- | --------------------------------------- |
| Replaces old value if key exists | Does not replace existing value         |
| Returns old value                | Returns existing value without updating |

---

# Q12. HashMap vs ConcurrentHashMap (Very Important)

| HashMap                                | ConcurrentHashMap                            |
| -------------------------------------- | -------------------------------------------- |
| Not thread-safe                        | Thread-safe                                  |
| Allows null key/value                  | Does not allow null                          |
| Throws ConcurrentModificationException | Never throws ConcurrentModificationException |
| No synchronization                     | Bucket-level locking                         |
| Poor choice for multithreading         | Best for multithreading                      |

| ConcurrentHashMap                   | Hashtable                     |
| ----------------------------------- | ----------------------------- |

# Q15. Difference between ConcurrentHashMap and synchronizedMap()? ⭐⭐⭐⭐

### Answer

**ConcurrentHashMap**

**Collections.synchronizedMap()**

* Fail-Fast iterator

# Q16. What is CopyOnWriteArrayList? ⭐⭐⭐⭐⭐

### Answer

CopyOnWriteArrayList is a **thread-safe version of ArrayList**.

Whenever an update operation (add, remove, update) happens, it creates a **new cloned copy** of the list.

Read operations continue on the old copy without blocking.

---

# Q17. Why is it called CopyOnWriteArrayList?

### Answer

Because **every write operation creates a copy** of the underlying ArrayList.

The modification is performed on the copied list.

---

# Q18. When should we use CopyOnWriteArrayList?

### Answer

Use CopyOnWriteArrayList when:

* Read operations are very frequent.
* Write operations are very few.

Because every write creates a new copy, frequent writes reduce performance.

---

# Q19. Why is CopyOnWriteArrayList costly?

### Answer

Every update operation creates a **new cloned copy** of the list.

Therefore write operations consume extra memory and CPU.

---

# Q20. What are the features of CopyOnWriteArrayList?

### Answer

* Thread-safe
* Insertion order preserved
* Duplicate objects allowed
* Heterogeneous objects allowed
* Null values allowed
* Fail-Safe iterator
* No ConcurrentModificationException

---

# Q21. Does CopyOnWriteArrayList throw ConcurrentModificationException?

### Answer

No.

While one thread is iterating, another thread can safely modify the list.

Iterator works on a separate copy, so no `ConcurrentModificationException` occurs.

---

# Q22. Can Iterator remove elements from CopyOnWriteArrayList? ⭐⭐⭐⭐

### Answer

No.

Calling `iterator.remove()` throws:

```java
UnsupportedOperationException
```

Unlike ArrayList, CopyOnWriteArrayList iterator does not support the remove operation.

---

# Q23. Difference between ArrayList and CopyOnWriteArrayList?

| ArrayList                              | CopyOnWriteArrayList                         |
| -------------------------------------- | -------------------------------------------- |
| Not Thread Safe                        | Thread Safe                                  |
| Fail-Fast iterator                     | Fail-Safe iterator                           |
| Throws ConcurrentModificationException | Never throws ConcurrentModificationException |
| No copy created on update              | Creates new copy on every update             |
| Iterator supports remove()             | Iterator does not support remove()           |

---

# Q24. What is addIfAbsent()?

### Answer

`addIfAbsent()` adds an element only if it is not already present in the list.

Example:

```java
list.addIfAbsent("A");
```

If `"A"` already exists, it will not be added again.

---

# Q25. What is addAllAbsent()?

### Answer

`addAllAbsent()` adds only those elements from another collection that are not already present.

It also returns the number of newly added elements.

---

# ⭐ Interview Favourite Question

### Why doesn't CopyOnWriteArrayList throw ConcurrentModificationException?

### Answer

Because every update operation happens on a **separate cloned copy** of the list.

The iterator continues to iterate over the old copy.

Therefore, modifications do not affect the iterator and no `ConcurrentModificationException` is thrown.

### Interview Answer

**ArrayList**

* Not thread-safe
* Fail-Fast iterator

**CopyOnWriteArrayList**

* Thread-safe

# Q27. Difference between CopyOnWriteArrayList and synchronizedList()? ⭐⭐⭐⭐

### Answer

| CopyOnWriteArrayList                     | synchronizedList()                     |
| ---------------------------------------- | -------------------------------------- |
| Creates cloned copy on every write       | Locks the entire list                  |
| Multiple threads can read simultaneously | Only one thread at a time              |
| Fail-Safe iterator                       | Fail-Fast iterator                     |
| No ConcurrentModificationException       | Throws ConcurrentModificationException |
| Iterator.remove() not supported          | Iterator.remove() supported            |

---

# Q28. What is CopyOnWriteArraySet? ⭐⭐⭐⭐

### Answer

CopyOnWriteArraySet is a **thread-safe implementation of Set**.

It is internally implemented using **CopyOnWriteArrayList**.

Features:

* Thread-safe
* Insertion order preserved
* Duplicate elements are not allowed
* Multiple threads can read simultaneously
* Every write operation creates a cloned copy

---

# Q29. When should we use CopyOnWriteArraySet?

### Answer

Use CopyOnWriteArraySet when:

* Read operations are more.
* Write operations are fewer.
* Thread safety is required.

Avoid it if there are frequent updates because every update creates a cloned copy.

---

# Q30. Difference between CopyOnWriteArraySet and synchronizedSet()? ⭐⭐⭐⭐

| CopyOnWriteArraySet                | synchronizedSet()                      |
| ---------------------------------- | -------------------------------------- |
| Thread-safe using cloned copy      | Thread-safe using locking              |
| Fail-Safe iterator                 | Fail-Fast iterator                     |
| No ConcurrentModificationException | Throws ConcurrentModificationException |
| Iterator supports only read        | Iterator supports read and remove      |

---

# Q31. What is a Fail-Fast Iterator? ⭐⭐⭐⭐⭐

### Answer

A Fail-Fast iterator throws **ConcurrentModificationException** if the collection is structurally modified while iterating.

It uses an internal **modCount** (called MOD in your notes) to detect changes.

Examples:

* ArrayList
* HashMap
* HashSet
* Vector

---

# Q32. What is a Fail-Safe Iterator? ⭐⭐⭐⭐⭐

### Answer

A Fail-Safe iterator works on a **separate cloned copy** of the collection.

If another thread modifies the original collection, the iterator is not affected.

Therefore it never throws `ConcurrentModificationException`.

Examples:

* ConcurrentHashMap
* CopyOnWriteArrayList
* CopyOnWriteArraySet

---

# Q33. Difference between Fail-Fast and Fail-Safe Iterator ⭐⭐⭐⭐⭐

| Fail-Fast                                     | Fail-Safe                                                              |
| --------------------------------------------- | ---------------------------------------------------------------------- |
| Throws ConcurrentModificationException        | Never throws ConcurrentModificationException                           |
| No cloned copy                                | Uses cloned copy                                                       |
| Better memory usage                           | Extra memory required                                                  |
| Faster                                        | Slightly slower due to copy creation                                   |
| Examples: ArrayList, HashMap, HashSet, Vector | Examples: ConcurrentHashMap, CopyOnWriteArrayList, CopyOnWriteArraySet |

---

# Q34. Why does a Fail-Safe Iterator not throw ConcurrentModificationException?

### Answer

Because it iterates over a **cloned copy** of the collection.

Any modification happens on the original collection, not on the copied one.

So the iterator continues safely without any exception.
