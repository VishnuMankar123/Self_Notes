# 🎓 Java 8 CompletableFuture – Q&A Notes

*(runAsync() & supplyAsync())*

---

## 👨‍🏫 Teacher: Java 8 me **CompletableFuture** kya hota hai?

### 👨‍🎓 Student:

**CompletableFuture** Java 8 ka ek **asynchronous programming** feature hai
jo hume **background thread** me kaam karne deta hai bina main thread block kiye.

👉 Matlab:

* Long-running task background me chalega
* Main thread free rahega
* Result baad me milega

---

## 👨‍🏫 Teacher: CompletableFuture ki zarurat kyun padi?

### 👨‍🎓 Student:

Pehle hum:

* **Thread**
* **Runnable**
* **Callable**
* **Future**

use karte the, lekin unme problems thi:

❌ Blocking calls
❌ No proper chaining
❌ Poor exception handling

👉 **CompletableFuture** ne ye problems solve kar di.

---

## 👨‍🏫 Teacher: Future aur CompletableFuture me difference?

### 👨‍🎓 Student:

| Feature            | Future        | CompletableFuture   |
| ------------------ | ------------- | ------------------- |
| Blocking           | Yes (`get()`) | Mostly Non-blocking |
| Chaining           | ❌             | ✅                   |
| Callback           | ❌             | ✅                   |
| Exception handling | Weak          | Strong              |
| Async flow         | Limited       | Powerful            |

---

## 👨‍🏫 Teacher: CompletableFuture create kaise karte hain?

### 👨‍🎓 Student:

2 main tareeke hote hain:

1️⃣ **runAsync()**
2️⃣ **supplyAsync()**

---

# 🚀 runAsync()

## 👨‍🏫 Teacher: **runAsync()** kab use karte hain?

### 👨‍🎓 Student:

Jab:

* Sirf task run karna ho
* **Koi result return nahi chahiye**

👉 Return type: **CompletableFuture<Void>**

---

### ✅ Example: runAsync()

```java
CompletableFuture.runAsync(() -> {
    System.out.println("Task running in background");
});
```

✔ Background thread me chalega
✔ Main thread block nahi hoga

---

### 👨‍🏫 Teacher: Executor ke sath runAsync?

### 👨‍🎓 Student:

Haan, custom thread pool ke sath bhi use kar sakte hain:

```java
ExecutorService executor = Executors.newFixedThreadPool(5);

CompletableFuture.runAsync(() -> {
    System.out.println("Async task");
}, executor);
```

---

# 🎁 supplyAsync()

## 👨‍🏫 Teacher: **supplyAsync()** kab use hota hai?

### 👨‍🎓 Student:

Jab:

* Background me kaam ho
* **Result return karna ho**

👉 Return type: **CompletableFuture<T>**

---

### ✅ Example: supplyAsync()

```java
CompletableFuture<String> future =
    CompletableFuture.supplyAsync(() -> {
        return "Hello World";
    });

System.out.println(future.get());
```

✔ Background execution
✔ Result baad me milega

---

## 👨‍🏫 Teacher: supplyAsync() vs runAsync() difference?

### 👨‍🎓 Student:

| Feature      | runAsync                | supplyAsync          |
| ------------ | ----------------------- | -------------------- |
| Return value | ❌                       | ✅                    |
| Return type  | CompletableFuture<Void> | CompletableFuture<T> |
| Use case     | Fire-and-forget         | Result required      |

# 🔹 thenApply()

## 👨‍🏫 Teacher: **thenApply()** kya karta hai?

### 👨‍🎓 Student:

* Result ko **input** ke roop me leta hai
* Usko **modify / transform** karta hai
* **Naya result return** karta hai

👉 Use jab:

* Data ko process / change karna ho

---

### ✅ Example: thenApply()

```java
CompletableFuture<String> future =
    CompletableFuture.supplyAsync(() -> "hello")
        .thenApply(result -> result.toUpperCase());

System.out.println(future.get());
```

🟢 Output:

```

```

---

### 🧠 Samajhne ka simple logic

* supplyAsync → `"hello"`

👉 **Input bhi hai + Output bhi**

# 🔹 thenAccept()

## 👨‍🏫 Teacher: **thenAccept()** kya karta hai?

### 👨‍🎓 Student:

* Result ko **consume** karta hai
* **Koi value return nahi karta**

👉 Use jab:

* Sirf print / save / log karna ho

---

### ✅ Example: thenAccept()

```java
CompletableFuture.supplyAsync(() -> "Java")
        .thenAccept(result -> {
            System.out.println(result);
        });
```

🟢 Output:

```
Java
```

---

### 🧠 Important point

* Input ✔
* Output ❌

Return type:

```
CompletableFuture<Void>
```

# 🔹 thenRun()

## 👨‍🏫 Teacher: **thenRun()** kya karta hai?

### 👨‍🎓 Student:

* Result ka **use bhi nahi karta**
* Sirf ek **next task run** karta hai

👉 Use jab:

* Bas koi final action chahiye
* Result se matlab nahi

---

### ✅ Example: thenRun()

```java
CompletableFuture.supplyAsync(() -> "Done")
        .thenRun(() -> {
            System.out.println("Task completed");
        });
```

🟢 Output:

```
Task completed
```

---

### 🧠 Important point

* Input ❌
* Output ❌

Sirf notification / trigger ke liye

# 🆚 thenApply vs thenAccept vs thenRun

| Method         | Input | Output | Use case           |
| -------------- | ----- | ------ | ------------------ |
| **thenApply**  | ✔     | ✔      | Transform data     |
| **thenAccept** | ✔     | ❌      | Consume data       |
| **thenRun**    | ❌     | ❌      | Just run next task |

## 🔹 1. thenCompose()

### 👨‍🏫 Teacher: **thenCompose()** kya hota hai?

### 👨‍🎓 Student:

* Jab ek async task ka result **dusra async task start** kare
* Aur dono ko **flat chain** me chahiye

👉 **Future ke andar Future** ko flatten karta hai

---

### ❌ Problem (without thenCompose)

```java
CompletableFuture<CompletableFuture<String>> future =
    CompletableFuture.supplyAsync(() -> "userId")
        .thenApply(id -> getUserNameAsync(id));
```

😵 Output:

```
CompletableFuture<CompletableFuture<String>>
```

---

### ✅ Solution (thenCompose)

```java
CompletableFuture<String> future =
    CompletableFuture.supplyAsync(() -> "userId")
        .thenCompose(id -> getUserNameAsync(id));

System.out.println(future.get());
```

-------------------------------------------------------------------------------------------------
Core Difference
✅ thenApply

👉 Used when next step is NORMAL (non-async)

✅ thenCompose

👉 Used when next step is ASYNC (returns another CompletableFuture)

🧠 Simple Analogy
thenApply

👉 Like:

“Take result → transform it”

thenCompose

👉 Like:

“Take result → call another async API”

Code Example

🔹 thenApply (WRONG for async)
CompletableFuture<CompletableFuture<String>> future =
    CompletableFuture.supplyAsync(() -> "userId")
        .thenApply(id -> getUserNameAsync(id)); // returns CF

// Nested future 😬

👉 Problem:

You get nested future
Hard to handle

🔹 thenCompose (CORRECT)
CompletableFuture<String> future =
    CompletableFuture.supplyAsync(() -> "userId")
        .thenCompose(id -> getUserNameAsync(id));

System.out.println(future.get());

👉 Output:

Clean → CompletableFuture<String>

No nesting
🧠 Visual Understanding
thenApply
Future<A> → function → Future<Future<B>>
thenCompose
Future<A> → async function → Future<B>

Interview One-Liner

thenApply is used for synchronous transformation, while thenCompose is used to chain asynchronous operations and avoids nested futures.
-------------------------------------------------------------------------------------------------

### 🧠 Real-life Example

* **Login API** → userId
* **User API** → user details

👉 One depends on another → **thenCompose**

---

### 🔑 One-liner

> **thenCompose = async dependency (flatMap)**

---

# 🔹 2. thenCombine()

### 👨‍🏫 Teacher: **thenCombine()** kya karta hai?

### 👨‍🎓 Student:

* **Do independent async tasks** ko combine karta hai
* Dono ke result milke **naya result banate hain**

---

### ✅ Example: thenCombine()

```java
CompletableFuture<String> f1 =
    CompletableFuture.supplyAsync(() -> "Hello");

CompletableFuture<String> f2 =
    CompletableFuture.supplyAsync(() -> "World");

CompletableFuture<String> result =
    f1.thenCombine(f2, (a, b) -> a + " " + b);

System.out.println(result.get());
```

🟢 Output:

```
Hello World
```

---

### 🧠 Use case

* Price service + Tax service
* User API + Address API

👉 Independent calls → **thenCombine**

---

### 🔑 One-liner

> **thenCombine = parallel + merge result**


---

# 🔹 3. allOf()

### 👨‍🏫 Teacher: **allOf()** kya hota hai?

### 👨‍🎓 Student:

* Jab **multiple futures** complete hone chahiye
* Tab next step execute hota hai

---

### ✅ Example: allOf()

```java
CompletableFuture<Void> all =
    CompletableFuture.allOf(f1, f2, f3);

all.thenRun(() -> {
    System.out.println("All tasks completed");
});
```

---

### 🧠 Real use

* Multiple API calls
* Sab ka data chahiye → report generate

---

### ⚠️ Note

* **Result direct nahi milta**
* Individual future se `get()` karna padta hai

---

# 🔹 4. anyOf()

### 👨‍🏫 Teacher: **anyOf()** ka use?

### 👨‍🎓 Student:

* Jaise hi **koi ek future complete ho jaye**, result mil jata hai
* Baaki cancel / ignore

---

### ✅ Example: anyOf()

```java
CompletableFuture<Object> any =
    CompletableFuture.anyOf(f1, f2, f3);

System.out.println(any.get());
```

---

### 🧠 Real-life use

* Multiple mirror servers
* Jo pehle response de → use kar lo

---

### 🔑 Difference

| allOf         | anyOf            |
| ------------- | ---------------- |
| Waits for all | Waits for first  |
| Batch jobs    | Fastest response |

---

# 🔹 5. Exception Handling – exceptionally()

### 👨‍🏫 Teacher: Async me exception kaise handle karein?

### 👨‍🎓 Student:

**exceptionally()** use karte hain

---

### ✅ Example: exceptionally()

```java
CompletableFuture<Integer> future =
    CompletableFuture.supplyAsync(() -> 10 / 0)
        .exceptionally(ex -> {
            System.out.println("Error: " + ex.getMessage());
            return 0;
        });

System.out.println(future.get());
```

🟢 Output:

```
Error: / by zero
0
```

---

### 🧠 Benefit

* App crash nahi hota
* Graceful fallback milta hai

---

# 🔥 Bonus: handle()

```java
future.handle((result, ex) -> {
    if (ex != null) return "Failed";
    return result;
});
```

✔ Success + Failure dono handle

# 🧠 Quick Decision Guide

| Situation        | Use           |
| ---------------- | ------------- |
| Async dependency | thenCompose   |
| Parallel merge   | thenCombine   |
| Wait for all     | allOf         |
| Fastest one      | anyOf         |
| Error handling   | exceptionally |

---

# 🎯 Interview Gold Lines

* **thenCompose avoids nested futures**
* **thenCombine runs tasks in parallel**
* **allOf is barrier synchronization**
* **anyOf improves latency**
* **exceptionally provides fallback**

## 🔥 Why this is BEST PRACTICE

❌ **Bad practice**

```java
CompletableFuture.supplyAsync(() -> task)
```

(Default ForkJoinPool → no control)

✅ **Good practice**

```java
CompletableFuture.supplyAsync(() -> task, plantExecutor)
```

✔ Controlled threads
✔ Rate-limited APIs safe
✔ No server crash
✔ Predictable performance
