# Java 8 CompletableFuture Interview Questions & Answers

# 1. What is CompletableFuture?

### Answer

CompletableFuture is a Java 8 feature used for **asynchronous programming**.

It allows a task to run in the background without blocking the main thread and provides the result once the task is completed.

### Interview One-Liner

> CompletableFuture is an advanced version of Future that supports asynchronous execution, chaining, callbacks, and exception handling.

---

# 2. Why was CompletableFuture introduced?

### Answer

Before Java 8, we used:

* Thread
* Runnable
* Callable
* Future

These had several limitations:

* Blocking calls
* No callback support
* Difficult task chaining
* Poor exception handling

CompletableFuture solves all these problems.

---

# 3. What is asynchronous programming?

### Answer

In asynchronous programming, a task runs in the background while the main thread continues executing other work.

Example:

Instead of waiting for an API response, the application continues processing other requests.

---

# 4. What is the difference between synchronous and asynchronous programming?

### Answer

**Synchronous**

* Executes one task at a time
* Waits until the current task finishes

**Asynchronous**

* Executes tasks in the background
* Doesn't block the main thread

Example:

Food delivery app.

* Synchronous → Wait at restaurant until food is ready.
* Asynchronous → Place order and continue your work.

---

# 5. What are the ways to create a CompletableFuture?

### Answer

There are mainly two methods:

* runAsync()
* supplyAsync()

---

# 6. What is runAsync()?

### Answer

runAsync() is used when we want to execute a task asynchronously but do not need any return value.

Return Type

```java
CompletableFuture<Void>
```

Example

```java
CompletableFuture.runAsync(() ->
    System.out.println("Background Task"));
```

---

# 7. When should we use runAsync()?

### Answer

Use runAsync() when:

* Sending emails
* Writing logs
* Cache refresh
* Notifications

Basically, **Fire-and-Forget** operations.

---

# 8. What is supplyAsync()?

### Answer

supplyAsync() executes a task asynchronously and returns a result.

Return Type

```java
CompletableFuture<T>
```

Example

```java
CompletableFuture<String> future =
CompletableFuture.supplyAsync(() -> "Hello");
```

---

# 9. Difference between runAsync() and supplyAsync()

| runAsync()              | supplyAsync()        |
| ----------------------- | -------------------- |
| No return value         | Returns value        |
| CompletableFuture<Void> | CompletableFuture<T> |
| Fire and Forget         | Result Required      |

---

# 10. What is Future?

### Answer

Future represents the result of an asynchronous computation.

However, Future has limitations:

* Blocking get()
* No callbacks
* No chaining
* Poor exception handling

CompletableFuture is a better implementation.

---

# 11. Difference between Future and CompletableFuture?

### Answer

Future

* Blocking
* No callback
* No chaining

CompletableFuture

* Non-blocking
* Callback support
* Task chaining
* Better exception handling

---

# 12. Why is get() not recommended?

### Answer

get() blocks the current thread until the result is available.

Because of blocking behavior, methods like

* thenApply()
* thenAccept()
* thenRun()

are preferred.

---

# 13. Difference between get() and join()?

### Answer

get()

* Throws Checked Exception
* Blocks

join()

* Throws Unchecked Exception
* Cleaner syntax

Most developers prefer join().

---

# 14. What is thenApply()?

### Answer

thenApply() transforms the result and returns another value.

Example

```java
CompletableFuture.supplyAsync(() -> "java")
.thenApply(String::toUpperCase);
```

Output

```
JAVA
```

---

# 15. When should we use thenApply()?

### Answer

When we want to modify or transform the result.

Example

* Convert to uppercase
* Calculate tax
* Format response

---

# 16. What is thenAccept()?

### Answer

thenAccept() consumes the result but doesn't return anything.

Example

```java
.thenAccept(System.out::println);
```

---

# 17. What is thenRun()?

### Answer

thenRun() executes another task after completion but doesn't receive or return any value.

Example

```java
.thenRun(() ->
System.out.println("Completed"));
```

---

# 18. Difference between thenApply(), thenAccept(), thenRun()

| Method     | Input | Output |
| ---------- | ----- | ------ |
| thenApply  | Yes   | Yes    |
| thenAccept | Yes   | No     |
| thenRun    | No    | No     |

---

# 19. What is method chaining in CompletableFuture?

### Answer

Method chaining means executing multiple operations one after another.

Example

```java
supplyAsync()
.thenApply()
.thenAccept();
```

---

# 20. What is thenCompose()?

### Answer

thenCompose() chains dependent asynchronous operations.

It avoids nested CompletableFuture objects.

---

# 21. Difference between thenApply() and thenCompose()?

### Answer

thenApply()

Used when next step is synchronous.

thenCompose()

Used when next step itself returns another CompletableFuture.

Interview Line

> thenApply is for synchronous transformation, while thenCompose is for chaining asynchronous operations.

---

# 22. What problem does thenCompose() solve?

### Answer

It removes nested futures.

Without thenCompose

```java
CompletableFuture<CompletableFuture<String>>
```

With thenCompose

```java
CompletableFuture<String>
```

---

# 23. What is thenCombine()?

### Answer

thenCombine() combines the results of two independent asynchronous tasks.

Example

User Service

*

Address Service

↓

Combined Result

---

# 24. When do we use thenCombine()?

### Answer

When both tasks are independent.

Examples

* Product API
* Price API

Merge both responses.

---

# 25. What is CompletableFuture.allOf()?

### Answer

allOf() waits until all asynchronous tasks are completed.

Useful for

* Multiple API calls
* Batch processing

---

# 26. What is CompletableFuture.anyOf()?

### Answer

anyOf() returns the result of whichever task finishes first.

Useful for

* Mirror servers
* Fastest API response

---

# 27. Difference between allOf() and anyOf()

| allOf            | anyOf            |
| ---------------- | ---------------- |
| Waits for all    | Waits for first  |
| Batch processing | Fastest response |

---

# 28. How do you handle exceptions in CompletableFuture?

### Answer

Use

```java
exceptionally()
```

Example

```java
.exceptionally(ex -> 0);
```

---

# 29. What is handle()?

### Answer

handle() processes both success and failure.

Unlike exceptionally(), it works for both scenarios.

---

# 30. Why use a custom Executor instead of the default thread pool?

### Answer

Using a custom Executor provides better control over:

* Number of threads
* Queue size
* Performance
* Resource utilization

It prevents excessive thread creation.

---

# 31. What is ThreadPoolTaskExecutor?

### Answer

ThreadPoolTaskExecutor is Spring's implementation of a thread pool for executing asynchronous tasks efficiently.

---

# 32. What is Core Pool Size?

### Answer

Minimum number of threads always available.

---

# 33. What is Max Pool Size?

### Answer

Maximum number of threads that can be created during heavy load.

---

# 34. What is Queue Capacity?

### Answer

Maximum number of waiting tasks before creating additional threads.

---

# 35. Why set Thread Name Prefix?

### Answer

It helps identify threads during logging and debugging.

Example

```
plant-sync-1
plant-sync-2
```

---

# 36. Why use CompletableFuture in Microservices?

### Answer

To call multiple APIs in parallel and reduce response time.

Example

Instead of calling

* User API
* Order API
* Payment API

one after another,

they are executed simultaneously.

---

# 37. Explain your project where you used CompletableFuture.

### Answer

In my project, I used CompletableFuture to fetch multiple pages from an external API in parallel.

Each page was fetched using `supplyAsync()` with a custom `ThreadPoolTaskExecutor`. After all tasks completed using `allOf()`, I combined all results into a single list using `join()` and `flatMap()`. This reduced the overall API response time significantly.

---

# 38. Why did you use allOf() in your project?

### Answer

Because I had multiple asynchronous API calls running in parallel.

I wanted to process the data only after all API calls completed successfully.

---

# 39. Why did you use join() after allOf()?

### Answer

After `allOf()` confirmed that all tasks had completed, I used `join()` to retrieve the result from each `CompletableFuture`. Then I merged all lists using `flatMap()`.

---

# 40. Explain the complete flow of your CompletableFuture implementation.

### Answer

1. Generate page numbers.
2. Call each page asynchronously using `supplyAsync()`.
3. Execute tasks using a custom thread pool.
4. Wait for all tasks using `CompletableFuture.allOf()`.
5. Retrieve results using `join()`.
6. Merge all page data using `flatMap()`.
7. Return the final combined list.
