# Lecture Summary

👨‍🏫 **Teacher:** Aaj humne kya seekha?

👨‍🎓 **Student:**

* **Indexing** ka main purpose **data ko jaldi search karna** hai.
* Database ka data **Hard Disk** me permanently store hota hai.
* **CPU** direct Hard Disk se communicate nahi karta; pehle **RAM** me data load hota hai.
* Hard Disk ka data **Blocks/Pages** me divide hota hai.
* Agar data unordered ho, to multiple blocks read karne padte hain.
* Har block transfer se **I/O Cost** badhti hai.
* **Indexing block ke andar search ko directly fast nahi karti**, balki **jitne blocks read karne padte hain unki sankhya kam kar deti hai**.
* Kam blocks read hone ka matlab **kam I/O Cost** aur **faster query performance**.

---

## **Interview Questions (Quick Revision)**

1. **What is Indexing?**
   → Ek technique jo **I/O Cost kam karti hai** aur records ko efficiently locate karne me help karti hai.

2. **Why is database stored on Hard Disk instead of RAM?**
   → Kyunki Hard Disk **permanent (non-volatile)** hoti hai, jabki RAM **temporary (volatile)** hoti hai.

3. **Why doesn't the CPU access the Hard Disk directly?**
   → CPU bahut fast aur Hard Disk comparatively slow hoti hai, isliye data pehle RAM me load hota hai.

4. **What is a Block/Page?**
   → Hard Disk ka **fixed-size storage unit** jisme multiple records store hote hain.

5. **What is I/O Cost?**
   → Hard Disk aur RAM ke beech data transfer ka cost/time.

6. **What is the biggest advantage of Indexing?**
   → **Number of blocks accessed ko reduce karna**, jisse query execution fast ho jati hai.

**I/O Cost ko reduce karna** aur **kam blocks access karke searching ko fast banana**.

# 🎯 Final Revision (1 Minute)

- **Index Table bhi Hard Disk me store hoti hai.**
- **Index Entry = Key + Pointer**
- **Index Entry chhoti hoti hai, isliye ek block me zyada entries aati hain.**
- **Dense Index = Har Record ki Entry**
- **Sparse Index = Har Block ki Ek Entry**
- **Sparse sirf Sorted Data par banta hai.**
- **Sparse Search Cost = log₂(Index Blocks) + 1 = 7**
- **Dense Search Cost = log₂(Index Blocks) + 1 = 9**
- **Without Indexing = 1250 I/O**
- **Binary Search = 12 I/O**
- **With Indexing = 7–9 I/O**
- **Conclusion:** **Indexing dramatically reduce karti hai I/O Cost aur database searching ko bahut fast bana deti hai.**

# 🎯 Final Revision (1 Minute)

* **Indexes ke 3 types hote hain:** Primary, Clustered aur Secondary.
* **Primary Index** → Data **Sorted + Unique (Key)** hona chahiye.
* **Clustered Index** → Data **Sorted**, lekin duplicate values allowed (Non-Key).
* **Secondary Index** → Jab data **Unordered** ho, chahe key ho ya non-key.
* **Ordered = Sorted (Ascending ya Descending).**
* **Key = Unique Attribute.**
* **Non-Key = Duplicate Values Allowed.**
* **Exam aur Interview ka sabse important point:** Ye 4-condition wala table hamesha yaad rakho, kyunki isi par direct questions bahut frequently pooche jaate hain.

# Binary Search

**Binary Search** ek searching algorithm hai jo **sirf sorted (ordered)** data par kaam karta hai. Isme har step me search space aadhi (half) ho jati hai, isliye ye **Linear Search** se bahut fast hota hai.

## Example

Sorted Array:

```
10 20 30 40 50 60 70 80
```

Search karna hai: **70**

### Step 1

Middle element = **40**

```
10 20 30 [40] 50 60 70 80
```

70 > 40

➡️ Right half me search karenge.

---

### Step 2

Right half:

```
50 60 [70] 80
```

Middle = **60**

70 > 60

➡️ Right half me search karenge.

---

### Step 3

```
[70] 80
```

70 mil gaya.

✅ Total sirf **3 comparisons** me answer mil gaya.

---

## Time Complexity

* **Best Case:** **O(1)** (Element first comparison me mil jaye.)
* **Average Case:** **O(log N)**
* **Worst Case:** **O(log N)**

---

## Why is Binary Search Fast?

Har step me data ka **half part remove** ho jata hai.

Example:

```
10000 Records

↓

5000

↓

2500

↓

1250

↓

625

↓

312

↓

156

↓

78

↓

39

↓

19

↓

9

↓

4

↓

2

↓

1
```

Sirf lagbhag **14 comparisons** me record mil jata hai, kyunki:

```
log₂(10000) ≈ 14
```

---

## Binary Search in Database Indexing

Database me jab **Primary Index**, **Clustered Index**, **B-Tree**, ya **B+ Tree** index use hota hai, to searching approximately **O(log N)** time me hoti hai.

Without Index:

```
Table Scan

↓

Row1

↓

Row2

↓

Row3

↓

...

↓

Row10000
```

Time Complexity = **O(N)**

With Index:

```
Search Index

↓

Binary Search

↓

Pointer

↓

Required Block

↓

Record Found
```

Time Complexity ≈ **O(log N)**

---

## Interview Definition

**Binary Search** ek efficient searching algorithm hai jo **sorted data** par kaam karta hai. Har iteration me search space ko aadha kar deta hai, isliye iska time complexity **O(log N)** hota hai.

# Q1. Secondary Index kya hota hai?

👨‍🏫 **Teacher:** Secondary Index ka naam "Secondary" kyun hai?

👨‍🎓 **Student:** Sir kyunki database me pehle se ek index hota hai aur hum ek aur index banate hain.

✅ Bilkul sahi.

**Definition**

> **Secondary Index** ek additional index hota hai jo kisi dusre column par banaya jata hai taaki us column par searching fast ho sake.

---

# Q2. Secondary Index kab use hota hai?

**Sabse Important Rule**

Secondary Index tab use hota hai jab

✅ Data **Unordered (Not Sorted)** ho.

Chahe

* **Key**
* ya **Non-Key**

Dono cases me Secondary Index use hota hai.

# Q10. Primary aur Secondary Index me Difference

| Feature          | Primary Index | Secondary Index |
| ---------------- | ------------- | --------------- |
| Data             | Ordered       | Unordered       |
| Key              | Unique        | Key/Non-Key     |
| Dense/Sparse     | Sparse        | Dense           |
| Search           | Binary Search | Binary Search   |
| Extra Layer      | No            | Non-Key me Yes  |
| Additional Index | No            | Yes             |

# Primary vs Clustered vs Secondary

| Feature       | Primary | Clustered     | Secondary          |
| ------------- | ------- | ------------- | ------------------ |
| Data          | Ordered | Ordered       | Unordered          |
| Key           | Unique  | Non-Key       | Key/Non-Key        |
| Sparse        | Yes     | Yes           | No (Dense)         |
| Extra Pointer | No      | Block Hanger  | Intermediate Layer |
| Search        | log₂N+1 | log₂N + Extra | log₂N + Extra      |

---

# Memory Trick

| Index         | Memory Trick                 |
| ------------- | ---------------------------- |
| **Primary**   | Ordered + Unique + Sparse    |
| **Clustered** | Ordered + Duplicate + Sparse |
| **Secondary** | Unordered + Dense            |

# 🎯 Final Revision (1 Minute)

* **Secondary Index ek additional index hota hai.**
* **Jab original data unordered ho tab Secondary Index use hota hai.**
* **Secondary Index Key aur Non-Key dono columns par ban sakta hai.**
* **Original table unordered reh sakti hai, lekin Index Table hamesha sorted hoti hai taaki Binary Search use ho sake.**
* **Secondary Index hamesha Dense hota hai, kyunki har record ke liye pointer maintain karna padta hai.**
* **Non-Key case me duplicate values ke liye Intermediate Layer (Block of Record Pointers) use hoti hai.**
* **Key case ki searching ≈ log₂N + 1 hoti hai.**
* **Non-Key case me Intermediate Layer ki wajah se additional searching lagti hai, isliye time thoda aur badh jata hai.**
* **Exam ka sabse important point:** **Primary aur Clustered = Sparse**, **Secondary = Dense**.
