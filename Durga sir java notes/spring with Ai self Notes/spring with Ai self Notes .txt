**Large Language Model (LLM)** जैसे GPT में **token** बहुत important concept है।

### 🔹 Token क्या होता है?

* **Token मतलब text का छोटा टुकड़ा (unit of meaning)** जिसे model समझता और process करता है।
* ये हमेशा **पूरा word** नहीं होता, कभी-कभी word का हिस्सा भी हो सकता है।
* Model text को पहले tokens में तोड़ता है → फिर उन tokens पर calculation करता है।

### 🔹 Example

मान लो text है:

```
I love programming
```

इसे tokenize करने पर:

* "I" → 1 token
* " love" → 1 token (शुरुआत में space भी गिना जाता है)
* " programming" → 1 token

तो पूरे sentence के 3 tokens बनेंगे।

अगर हिंदी लें:

```
मुझे पढ़ना अच्छा लगता है
```

इसे model subword tokens में तोड़ेगा, जैसे:

* "मुझे"
* " पढ़"
* "ना"
* " अच्छा"
* " लगता"
* " है"

(कुल 6 tokens)

### 🔹 क्यों जरूरी है?

1. **Input/Output Limit** → हर LLM में token की limit होती है (जैसे GPT-4 में 128k tokens तक)।
2. **Cost Calculation** → API call का खर्च tokens पर आधारित होता है।
3. **Processing Efficiency** → Model words के बजाय tokens पर training करता है, जिससे अलग-अलग भाषाएँ और complex words handle हो जाते हैं।

### 🔹 ध्यान रखने वाली बात

* 1 token ≠ 1 word
* English में 1 token ≈ 4 characters (औसतन)
* 100 tokens ≈ 75 words (approx)

1. **Data collect karo**

   * Bahut bada text corpus chahiye (billions of tokens).
   * Sources: Wikipedia, books, research papers, code, social media (अगर policy allow करे)।

2. **Data cleaning & preprocessing**

   * Text को साफ करना (HTML tags, duplicates हटाना)।
   * Tokenizer banana (जैसे BPE, SentencePiece)।

3. **Model architecture design**

   * Mostly **Transformer** architecture use hota hai (Vaswani et al. 2017).
   * Decide: कितने layers, कितने attention heads, embedding size, hidden size।

4. **Training**

   * GPU/TPU clusters चाहिए (NVIDIA A100/ H100 level cards)।
   * Training में हफ्तों/महीनों लग सकते हैं।
   * Loss function: Cross-entropy (next token prediction)।

5. **Evaluation & testing**

   * Benchmarks pe test karo (perplexity, downstream tasks)।

⚠️ Problem: ये बहुत महंगा है (millions of dollars लग सकते हैं)।

## 🔹 2. Fine-tuning pre-trained LLM (सबसे practical तरीका)

Yeh aap easily kar सकते ho.

2. **Tokenizer load karo** (जो उस model ke साथ आता है)।

3. **Data prepare karo**

   * Apna domain-specific dataset बनाओ (जैसे finance, medical, coding, Hindi text)।

4. **Fine-tuning** techniques:

   * **Full fine-tuning** (पूरे model ko train karo → heavy compute chahiye)।
   * **LoRA / PEFT (Parameter Efficient Fine-Tuning)** → sirf कुछ parameters ko train karo (cheap & fast)।

5. **Training framework use karo**

   * HuggingFace Transformers + PyTorch
   * deepspeed / accelerate for distributed training

6. **Deploy karo**

   * Model ko API ke रूप में expose करो (FastAPI, Flask, LangChain)।

## 🔹 Embedding क्या होता है?

**Embedding = किसी शब्द/वाक्य/चीज़ का numerical (vector) representation**
मतलब:

* Text को numbers में बदलना
* ताकि model उस text को समझ सके और उस पर calculation कर सके

ये numbers randomly नहीं होते, बल्कि ऐसे बनाए जाते हैं कि **similar meanings वाले words करीब हों और अलग meanings वाले दूर हों**।

---

## 🔹 Example

मान लो हमारे पास 3 words हैं:

* "king"
* "queen"
* "apple"

अगर इन्हें embedding space (say 3D space) में map करें, तो result कुछ ऐसा होगा:

* **king → [0.8, 0.2, 0.1]**
* **queen → [0.79, 0.25, 0.15]**
* **apple → [0.1, 0.9, 0.7]**

👉 यहाँ "king" और "queen" एक-दूसरे के **पास होंगे**, लेकिन "apple" उनसे बहुत **दूर** होगा।

---

## 🔹 क्यों जरूरी है?

1. **Semantic meaning पकड़ना** → Words को सिर्फ spelling से नहीं, उनके meaning से represent करना।
2. **Similarity search** → अगर कोई "doctor" लिखे, तो "physician" भी पास आना चाहिए।
3. **Input for ML models** → Model सीधे words पर काम नहीं कर सकता, उसे numbers चाहिए।

---

## 🔹 Embedding कहाँ use होते हैं?

* **Search engines** → Similar documents ढूँढने के लिए
* **Recommendation system** → Similar products suggest करने के लिए
* **Chatbots / LLMs** → Context और semantic meaning समझने के लिए
* **Clustering** → Similar चीज़ों को group करने के लिए

---

## 🔹 Real-world Example

Sentence:

```
I love programming
```

Model embeddings बना सकता है:

* "I" → [0.12, -0.45, 0.87, ...]
* "love" → [0.91, 0.33, -0.12, ...]
* "programming" → [0.75, 0.65, -0.22, ...]

अब इन vectors पर model math कर सकता है।

---

👉 Short mein:
**Embedding = Text को ऐसे numbers (vectors) में बदलना जो meaning preserve करें।**

## 🌐 Types of AI / LLM-based Models

### 1️⃣ **Chat Models (Conversational)**

* Human jaisa baat karte hain.
* Based on **autoregressive (decoder-only)** models.
* Fine-tuned on dialogues, instructions, safety rules.
* ✅ Example: **ChatGPT, LLaMA-2-Chat, Mistral-Instruct, Vicuna, Claude**

---

### 2️⃣ **Speech-to-Text Models (ASR – Automatic Speech Recognition)**

* Voice ko text me convert karte hain.
* Audio input lete hain aur transcription output dete hain.
* ✅ Example: **Whisper (OpenAI), DeepSpeech (Mozilla), wav2vec 2.0 (Meta)**

---

### 3️⃣ **Text-to-Speech Models (TTS)**

* Text ko natural sounding voice me bolte hain.
* Use: Virtual assistants, audiobooks, accessibility.
* ✅ Example: **VALL-E (Microsoft), Tacotron, Coqui TTS, ElevenLabs**

---

### 4️⃣ **Multimodal Models**

* Ek hi model jo **text + image + audio + video** sab handle karta hai.
* Example: Image input + text output, ya text input + image output.
* ✅ Example: **GPT-4V (Vision), Gemini, LLaVA, Kosmos-1, CLIP**

---

### 5️⃣ **Code Models**

* Programming help karne ke liye trained hote hain.
* ✅ Example: **Codex (GitHub Copilot), StarCoder, CodeLLaMA**

---

### 6️⃣ **Domain-Specific Models**

* Special purpose models jo ek hi field ke liye optimized hote hain:

  * **Medical** → Med-PaLM
  * **Legal** → LawGPT
  * **Finance** → BloombergGPT

# Spring AI – Part 1: Introduction & Basic Concepts

Based on your YouTube video transcript • Teacher–Student Q&A • Simple Hinglish • Text-file revision notes

Is notes mein hum video ke important concepts ko simple Hindi wali English mein samjhenge, examples ke saath. Notes ka focus hai Spring AI kya hai, kaise kaam karta hai, REST API se iska kya relation hai, aur ye developers ki life kaise easy banata hai.

## Module 1: What is Spring AI?

Q1. Teacher: Spring AI kya hai?

Student: Spring AI ek Spring ecosystem ka project/module hai, jiski help se hum apni Java ya Spring Boot application mein AI models integrate kar sakte hain.

Simple words mein, agar humein apni Spring Boot application mein ChatGPT jaise AI model ka use karna hai, toh Spring AI humein us integration ko easy banane mein help karta hai.

Example:

Suppose hum ek Spring Boot application bana rahe hain jo user ke questions ka answer deti hai.

- User question poochta hai: "What is Java?"
- Spring Boot application question receive karti hai.
- Spring AI ki help se AI model ko request bheji jaati hai.
- AI model answer generate karta hai.
- Application user ko answer return karti hai.

Q2. Teacher: Kya Spring AI use karna compulsory hai AI integrate karne ke liye?

Student: Nahi. Spring AI use karna compulsory nahi hai. Hum directly AI provider ki REST API call karke bhi AI integrate kar sakte hain.

Lekin Spring AI ek abstraction layer provide karta hai, jisse integration aur AI-related tasks ko manage karna easier ho sakta hai.

Q3. Teacher: AI model kya hota hai?

Student: AI model ek trained system hota hai jo apne task ke according input process karke output generate karta hai.

Examples:

- LLM (Large Language Model): Text generate karna, questions ka answer dena, text summarize karna.
- Image Generation Model: Text prompt se image generate karna.
- Video Generation Model: Text ya other supported input se video generate karna.

Video mein main focus Spring applications ke andar AI models ko integrate karne par hai.

Q4. Teacher: LLM ka full form kya hai?

Student: LLM ka full form Large Language Model hai.

Ye text-related tasks perform kar sakta hai, jaise question answering, content generation aur summarization.

Example:

Input: `Explain Java in simple words.`

Output: AI Java ke baare mein ek understandable explanation generate karega.

## Module 2: Spring Boot and AI Model Communication

Q5. Teacher: Agar hum ChatGPT jaise AI model ko apni Spring Boot application se connect karna chahte hain, toh communication kaise hoga?

Student: AI provider generally APIs expose karta hai. Spring Boot application un APIs ko request bhej sakti hai, aur response receive kar sakti hai.

Basic flow:

User

Question enter karta hai

Spring Boot Application

Request process karti hai

Spring AI / API Integration

AI model ko request bhejta hai

AI Model

Answer generate karta hai

Response to User

Note: Actual implementation mein Spring AI request ko provider-specific integration ke through handle karta hai. Exact flow application ke design par depend karega.

Q6. Teacher: REST API kya hoti hai?

Student: REST API ek common way hai jiske through do applications HTTP ke through communicate kar sakti hain.

For example, hamari Spring Boot application kisi AI provider ke API endpoint ko request bhejti hai aur response receive karti hai.

Example:

```
Spring Boot Application
        |
        | HTTP Request
        v
AI Provider REST API
        |
        | AI Response
        v
Spring Boot Application
```

Q7. Teacher: Kya hum Spring AI ke bina AI use kar sakte hain?

Student: Haan. Hum Java ke HTTP client ya kisi suitable HTTP library se provider ki REST API call kar sakte hain.

Lekin phir request formatting, response parsing, provider-specific details aur related AI features ko manage karne ka kaam humein khud karna pad sakta hai.

Q8. Teacher: Direct REST API call karne mein kya problem aa sakti hai?

Student: Basic request-response implement karna possible hai, lekin real application mein kuch additional challenges hote hain:

1. Har provider ka API format alag ho sakta hai.
2. Request aur response ko properly handle karna padta hai.
3. AI prompts aur different message roles ko manage karna padta hai.
4. Application ke private data ko AI ke context mein dene ka solution chahiye ho sakta hai.
5. Chat history aur conversation context maintain karna pad sakta hai.
6. Embeddings aur RAG jaise features implement karne pad sakte hain.

Spring AI inmein se kai tasks ko standard APIs aur abstractions ke through easier banata hai.

## Module 3: What is Abstraction Layer in Spring AI?

Q9. Teacher: Spring AI mein Abstraction Layer ka kya meaning hai?

Student: Abstraction Layer ka meaning hai ki developer ko har AI provider ke internal implementation details ko directly handle karne ki zaroorat kam ho jaati hai.

Spring AI humein Java classes, interfaces aur APIs provide karta hai. Hum inka use karke AI model ke saath communicate kar sakte hain.

Behind the scenes, Spring AI provider-specific API communication handle karne mein help karta hai.

Real-life example:

Suppose aapko car drive karni hai.

- Aap steering use karte ho.
- Aapko engine ke andar fuel kaise burn ho raha hai, ye har baar manage nahi karna padta.
- Steering aur controls aapke liye driving ko easy banate hain.

Similarly, Spring AI AI model ke saath interaction ko simpler banane ke liye abstraction provide karta hai.

Q10. Teacher: Spring AI ko use karne ka main objective kya hai?

Student: Iska main objective Spring applications mein AI models ko integrate karna easy banana hai.

Important points:

- AI models ke saath communication simplify karna.
- Common programming abstractions provide karna.
- Different AI providers ke integrations support karna.
- Prompts, embeddings, RAG aur chat history jaise AI-related tasks ko manage karne mein help karna.

Q11. Teacher: Spring AI aur direct REST API call mein kya difference hai?

Student: Dono approaches se AI integrate kar sakte hain, lekin implementation ka effort different ho sakta hai.

| Direct REST API                                                       | Spring AI                                                             |
| --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| HTTP requests ko manually manage karna pad sakta hai.                 | Common AI abstractions provide karta hai.                             |
| Request/response handling developer ko implement karni pad sakti hai. | Supported integrations mein ye kaam simplify hota hai.                |
| Provider change karne par code changes ho sakte hain.                 | Provider abstraction ke through changes reduce ho sakte hain.         |
| AI-specific features manually implement karne pad sakte hain.         | Prompts, embeddings aur RAG jaise features ke liye support milta hai. |

Interview answer: Spring AI is a framework that simplifies integrating AI models into Spring applications by providing abstractions and support for AI-related capabilities.

## Module 6: Embeddings and RAG

Q18. Teacher: Embeddings kya hote hain?

Student: Embeddings text ya other supported data ko numerical vectors ke form mein represent karte hain. In vectors ka use semantic similarity aur information retrieval jaise tasks mein kiya ja sakta hai.

Simple example: Hum documents ko embeddings mein convert karke similar meaning wale content ko search kar sakte hain.

Example:

```
Document 1: Java is a programming language.
Document 2: Java is used for backend development.
Document 3: Mango is a fruit.
```

## Module 3: ChatClient and Dependency Injection

Q6. Teacher: ChatClient kya hota hai?

Student: Spring AI mein `ChatClient` ek high-level API hai jiska use chat model ke saath interact karne ke liye kiya ja sakta hai.

Iski help se hum user ka prompt AI model ko bhej sakte hain aur generated response receive kar sakte hain.

Basic flow:

```
User Question
     |
     v
Spring Boot Controller
     |
     v
Service / ChatClient
     |
     v
AI Model
     |
     v
Generated Response
```

Q7. Teacher: ChatClient ko use karne ke liye kya karna padta hai?

Student: Video ke according, basic process ye hai:

1. Required Spring AI dependency add karna.
2. AI provider ki required configuration set karna.
3. Spring AI ke available `ChatClient.Builder` bean ko inject karna.
4. Builder ki `build()` method se `ChatClient` banana.
5. `ChatClient` ke methods use karke AI model se interact karna.

Example — basic structure:

```
@Service
public class AiService {

    private final ChatClient chatClient;

    public AiService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String ask(String question) {
        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }
}
```

Note: Ye illustrative code hai. Isse run karne ke liye compatible Spring AI dependency, provider configuration aur required imports chahiye.

Q8. Teacher: ChatClient.Builder aur ChatClient mein kya difference hai?

Student:

- `ChatClient.Builder`: ChatClient ko configure aur construct karne ke liye use hota hai.
- `ChatClient`: Build hone ke baad prompts bhejne aur responses receive karne ke liye use hota hai.

Simple example:

```
ChatClient chatClient = builder.build();
```

Yahan `builder.build()` ek `ChatClient` return karta hai.

Q9. Teacher: Kya ChatClient ko normal service ki tarah use kar sakte hain?

Student: Haan. Hum ise apni service class mein inject karke business logic ke andar use kar sakte hain.

Jaise normal service kisi database ya doosri service ke saath kaam karti hai, waise hi AI service `ChatClient` ki help se AI model ke saath interact kar sakti hai.

Q26. Teacher: Complete controller ka code dikhao.

Student: Neeche video ke concept par based clean implementation hai:

```
package com.spring.ai.firstproject.controller;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/chat")
    public String chat(@RequestParam("q") String question) {

        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }
}
```

Package name ko apne actual project ke package ke according update karna. Ye example current compatible Spring AI setup assume karta hai.

Q27. Teacher: Is code ka execution flow explain karo.

Student:

1. User `/chat` endpoint ko request bhejta hai.
2. `@RequestParam("q")` question receive karta hai.
3. `chatClient.prompt()` prompt request prepare karta hai.
4. `.user(question)` user ka question set karta hai.
5. `.call()` synchronous model interaction perform karta hai.
6. `.content()` generated response ka text extract karta hai.
7. Controller response ko user ko return karta hai.

Q28. Teacher: `.call()` aur `.content()` ka kya role hai?

Student:

- `.call()` synchronous request-response interaction execute karta hai.
- `.content()` response object se generated text obtain karta hai.

Example:

```
String answer = chatClient.prompt()

        .call()
        .content();
```

Yahan `answer` mein model ka returned text store hoga.

## 8. Step 6 — Complete `ChatController.java`

Teacher: Ab user ke question ko AI model tak kaise bhejenge?

package com.spring.ollama.controller;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/chat")
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder chatClientBuilder) {
        this.chatClient = chatClientBuilder.build();
    }

    @GetMapping
    public ResponseEntity<String> chat(
            @RequestParam("q") String message) {

        String response = chatClient
                .prompt()
                .user(message)
                .call()
                .content();

        return ResponseEntity.ok(response);
    }
}
```

## 1. ChatClient API kya hai?

Teacher: Spring AI mein `ChatClient` kya hota hai?

Student: Sir, `ChatClient` ek high-level API hai jo hume AI model ke saath easily interact karne mein help karta hai.

Iski help se hum:

- AI ko prompt bhej sakte hain.
- AI ka response receive kar sakte hain.
- System aur user messages create kar sakte hain.
- Dynamic values prompt mein pass kar sakte hain.
- Model ke options configure kar sakte hain.
- Supported APIs ke through response streaming kar sakte hain.

Teacher: Isko high-level API kyun kehte hain?

Student: Kyunki hume har baar manually HTTP request, JSON parsing aur provider-specific communication handle nahi karna padta. `ChatClient` in details ko abstract karta hai.

### Example

```
String response = chatClient
        .prompt()
        .user("What is Spring Boot?")
        .call()
        .content();
```

Is code mein:

1. `prompt()` — prompt request start karta hai.
2. `user(...)` — user ka question set karta hai.
3. `call()` — AI model ko request execute karta hai.
4. `content()` — generated response ka text deta hai.

Yaad rakho: `ChatClient` application developer ke liye AI model use karne ka convenient interface hai.

## 2. ChatClient ek fluent API hai

Teacher: Fluent API ka meaning kya hai?

Student: Fluent API mein hum multiple method calls ko chain kar sakte hain, jisse code readable aur easy to understand hota hai.

Example:

```
String answer = chatClient
        .prompt()
        .user("Explain Java 17 features")
        .call()
        .content();
```

Agar hum isko simple English mein explain karein:

- Prompt banao.
- User ka message add karo.
- Model ko call karo.
- Response ka content nikalo.

Isi ko method chaining kehte hain.

Video mein `var` ka bhi mention hai.

```
var answer = chatClient
        .prompt()
        .user("What is Java?")
        .call()
        .content();
```

Java compiler `answer` ka type infer kar leta hai. `var` Java 10 se available hai.

## 3. ChatClient internal complexity ko hide karta hai

Teacher: Kya hume direct REST API call aur JSON parsing manually karni padti hai?

Student: Nahi sir, jab hum Spring AI ka configured `ChatClient` use karte hain, to framework request handling aur response conversion ki kaafi complexity manage karta hai.

Your Spring Boot Code

Simple Java method calls

ChatClient

High-level abstraction

Provider-specific integration

Model response

Example: Aap `chatClient.prompt().user("Hello").call().content()` likhte ho. Spring AI configured provider ke saath communication karne mein help karta hai.

## 4. ChatClient ke important features

Video mein `ChatClient` ke kuch important features discuss kiye gaye hain.

### 4.1 Different execution modes

Teacher: Kya ChatClient sirf normal response hi return karta hai?

Student: Nahi sir, Spring AI mein response ko normal synchronous way mein receive kar sakte hain aur supported APIs ke through streaming bhi kar sakte hain.

Normal response example:

```
String answer = chatClient
        .prompt()
        .user("Explain HashMap")
        .call()
        .content();
```

Ismein application response ka content return hone ka wait karti hai.

Streaming example:

```
Flux<String> answer = chatClient
        .prompt()
        .user("Explain HashMap")
        .stream()
        .content();
```

Is example mein `Flux` Project Reactor ka type hai. Response text pieces mein receive ho sakta hai, agar selected model aur provider streaming support karte hain.

Difference:

- Synchronous call: Complete result milne ke baad aage process karte hain.
- Streaming: Response ke available parts ko progressively process kar sakte hain.

### 4.2 Prompt building

Teacher: Prompt kya hota hai?

Student: Prompt wo instruction ya message hai jo hum AI model ko dete hain.

Example:

```

Give three examples.
```

ChatClient prompt ko build karne aur user message, system instructions aur additional options provide karne mein help karta hai.

### 4.3 System message aur user message

Teacher: System message aur user message mein kya difference hai?

Student: System message AI ka intended behavior guide karta hai, jabki user message actual question ya instruction hota hai.

Example:

```
System message:
You are an experienced Java teacher.
Explain concepts in simple Hinglish.

User message:
What is HashMap?
```

Is example mein system message answer ka style guide karta hai aur user message actual question deta hai.

Important: Model ka actual behavior provider aur model ki capabilities par depend karta hai.

### 4.4 Dynamic placeholders

Teacher: Kya prompt mein dynamic values pass kar sakte hain?

Student: Haan sir. Hum prompt template mein placeholders rakh sakte hain aur runtime par unki values provide kar sakte hain.

Example:

```

        .prompt()
        .user(u -> u
                .text("Explain {topic} in simple language")
                .param("topic", "Spring Boot"))
        .call()
        .content();
```

Yahan `{topic}` ek placeholder hai. Runtime par uski value `"Spring Boot"` pass ki ja rahi hai.

Benefit: Har question ke liye manually naya prompt string likhne ki zarurat kam ho jaati hai.

### 4.5 Model options aur temperature

Teacher: Temperature kya hota hai?

Student: Temperature model ke response generation mein randomness ko influence karta hai.

- Low temperature: Generally more predictable responses.
- High temperature: Generally more varied responses.

Example:

```

        .prompt()
        .user("Explain Java interfaces")
        .options(options -> options.temperature(0.2))
        .call()
        .content();
```

Exact API signatures aur supported options Spring AI version aur selected model ke according verify karne chahiye.

Yaad rakho: Low temperature se correctness guarantee nahi hoti, aur high temperature se har baar better creativity bhi guarantee nahi hoti.

## 9. Interview Revision — Questions and Answers

Q1. What is ChatClient in Spring AI?

Answer: ChatClient is a high-level fluent API in Spring AI that helps developers interact with AI models easily. It simplifies sending prompts and getting responses without manually handling HTTP requests and JSON parsing.

Q2. What is a fluent API?

Answer: A fluent API allows us to write method calls in a readable, chain-like structure.

Example:

```
chatClient.prompt()
          .user("What is Java?")
          .call()
          .content();
```

Q3. What does `call().content()` do?

Answer: `call()` executes the AI request and gets the response. `content()` extracts the response text from the result.

Q4. What is the difference between a system message and a user message?

Answer:

- System message: Defines the AI's behavior, role, or instructions.
- User message: Contains the actual question or request from the user.

Q5. What is ChatModel?

Answer: ChatModel is a lower-level Spring AI abstraction that provides a common interface for interacting with chat models.

Q6. Why are there different ChatModel implementations?

Answer: Different AI providers have different integrations. Spring AI provides implementations for different providers, such as OpenAI and Ollama, while keeping a common programming interface.

Q7. What is the difference between ChatClient and ChatModel?

Answer: ChatClient provides a convenient, fluent API for building AI interactions. ChatModel is the underlying abstraction for communicating with a chat model.

Q8. What is temperature in an AI model?

Answer: Temperature controls the randomness of generated responses. A lower temperature generally produces more predictable responses, while a higher temperature can produce more varied responses.

Q9. What is streaming in Spring AI?

Answer: Streaming allows the AI response to be received in chunks as it is generated, instead of waiting for the complete response.

Q10. Do we always need to inject ChatModel directly?

Answer: No. We can use `ChatClient.Builder` to create a `ChatClient`, which is often more convenient for application development. We can use `ChatModel` directly when we need lower-level control.

## 1. Basic Concepts

Q1. What is the internal working of ChatClient and ChatModel in Spring AI?

Spring AI mein `ChatClient` aur `ChatModel` milkar AI model ke saath communication karte hain.

- ChatClient: Prompt prepare karta hai aur AI interaction ko easy banata hai.
- ChatModel: Actual chat model/provider ke saath communication karne ki responsibility handle karta hai.

     v

     |
     v
ChatClient

     |
     v

Answer:

Normally, `ChatClient` internally `ChatModel` ka use karta hai. `ChatModel` provider-specific implementation ke through AI model ke saath communicate karta hai.

Developer generally `ChatClient` use karta hai, jabki actual provider integration ko `ChatModel` handle karta hai.

Q3. What is the difference between a high-level and a low-level abstraction?

Easy example:

## 7. Important Code Example

Neeche ek simple controller example hai jo video mein samjhaye gaye flow ko demonstrate karta hai.

```
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/chat")
    public String chat(@RequestParam String q) {
        return chatClient
                .prompt()
                .user(q)
                .call()
                .content();
    }
}
```

Example request:

```
GET http://localhost:8080/chat?q=Explain%20Spring%20AI
```

Expected result: AI model Spring AI ko explain karne wala response return karega. Exact response model par depend karega.

## 8. Interview Revision — Questions and Answers

Q1. What is the role of ChatClient in Spring AI?

Q3. Does ChatClient communicate with the model directly?

Q4. What is the difference between ChatClient and ChatModel?

Answer: A provider starter adds the required integration dependencies and can activate the relevant Spring AI auto-configuration.

Q7. Why does ChatModel have different implementations?

Q8. What is dependency injection?

Answer: Dependency Injection allows Spring to provide the required objects to a class rather than the class creating them manually.

Q9. Why do we use ChatClient.Builder?

Answer: We use ChatClient.Builder to configure and create a ChatClient instance.

Q10. When is direct ChatModel injection useful?

Answer: It can be useful when we need direct model access or want to configure multiple ChatClient instances with different model configurations.

Q11. What happens when we change the AI provider?

Answer: We generally change the provider dependency and configuration. Spring AI can then configure the appropriate ChatModel implementation, while much of the ChatClient-based application code remains unchanged.

Q12. Explain the request flow in Spring AI.

# MODULE 3: Tokens and Tokenization

Q11. What is a Token in AI?

Answer:

Token text ka ek unit hota hai jise language model process karta hai.

Token ho sakta hai:

- Ek complete word
- Word ka ek part
- Punctuation mark
- Characters ka koi sequence

Important: Har word ek token ho, ye zaroori nahi hai.

Q12. What is Tokenization?

Answer:

Tokenization woh process hai jisme input text ko tokens mein divide kiya jaata hai.

Example:

```
What is Java?
```

Ek possible tokenization:

```
"What" | "is" | "Java" | "?"
```

Is example mein 4 tokens hain. Actual tokenization selected model aur tokenizer par depend karti hai.

Q13. Can one word contain multiple tokens?

Answer:

Yes. Kuch words ek token mein represent hote hain, jabki kuch words multiple tokens mein divide ho sakte hain.

Example:

```
unbelievable
```

Kisi tokenizer mein ye word multiple subword tokens mein split ho sakta hai.

Isliye ek word ko hamesha ek token count nahi karna chahiye.

Q14. What is a Token ID?

Answer:

Tokenizer har token ko vocabulary mein ek numerical ID assign karta hai.

Conceptual example:

```
Token: Java
Token ID: 12345
```

Ye sirf illustrative example hai, actual ID tokenizer ki vocabulary par depend karti hai.

Model numerical representations ke through input process karta hai.

Q15. How does an LLM generate a response using tokens?

Answer:

Simplified flow:

1. User prompt enter karta hai.
2. Text tokens mein convert hota hai.
3. Tokens numerical representations mein convert hote hain.
4. Model input ko process karta hai.
5. Model next token predict karta hai.
6. Ye process repeatedly continue hota hai.
7. Generated tokens ko text mein convert karke response return kiya jaata hai.

```
User Prompt
     |
     v
Tokenization
     |
     v
Token IDs
     |
     v
Numerical Representations
     |
     v
Neural Network Processing
     |
     v
Next Token Prediction
     |
     v
Generated Tokens
     |
     v
Final Text Response
```

Ye simplified explanation hai. Actual LLM architecture aur generation process isse zyada complex hota hai.

Q16. Why are tokens important?

Answer:

Video mein tokens ki importance ke do main reasons bataye gaye hain:

1. Cost: API pricing input aur output tokens par depend kar sakti hai.
2. Context Window: Model ek request mein kitna input aur conversation context process kar sakta hai, uski limit hoti hai.

Q17. How does token count affect API cost?

Answer:

Bahut se paid AI APIs input aur output tokens ke basis par charge karti hain.

- Input tokens: Prompt aur model ko bheje gaye relevant context ke tokens.
- Output tokens: Model ke generated response ke tokens.

Example:

Maan lo kisi hypothetical model ki pricing hai:

- Input: $2 per million tokens
- Output: $8 per million tokens

Agar request mein 2,000 input tokens aur 1,000 output tokens hain:

Input cost = \\(2000/1000000 \times 2 = \\$0.004\\)

Output cost = \\(1000/1000000 \times 8 = \\$0.008\\)

Total = $0.012

Ye sirf example pricing hai, kisi current model ki actual pricing nahi.

Q18. Does more text generally mean more tokens?

Answer:

Generally, haan. Zyada text se usually token count badhta hai, jiski wajah se token-based API cost bhi badh sakti hai.

Lekin exact token count language, text structure aur tokenizer par depend karta hai.

Q19. What is a Tokenizer?

Answer:

Tokenizer ek tool ya component hai jo text ko tokens mein convert karta hai aur tokens ko text mein decode karne mein bhi help karta hai.

       |

# MODULE 7: Structured Output

Q35. What is Structured Output in Spring AI?

Answer:

Structured output ka matlab hai AI response ko defined structure mein receive karna, jaise JSON format ya Java DTO.

Normal text response ke bajay application ko expected fields ke saath data chahiye ho sakta hai.

Example: User object with name and email.

Q36. Why is plain text output a problem in Java applications?

Answer:

AI model ka response string ke roop mein aa sakta hai, chahe woh JSON jaisa dikhe.

Example:

```
{"name":"Rahul","email":"rahul@example.com"}
```

Agar ye Java `String` hai, to ye automatically Java object nahi ban jaata.

Application ko response ko parse aur validate karna pad sakta hai.

Q37. What problems can occur with AI-generated JSON?

Answer:

AI-generated output mein issues ho sakte hain:

- Required field missing ho
- JSON syntax invalid ho
- Field ka data type incorrect ho
- Extra text JSON ke saath aa jaye
- Values expected format mein na hon

Isliye structured output ko validate karna important hai.

Q38. How does Spring AI help with structured output?

Answer:

Spring AI mein structured output conversion features available hain. Ye model ko expected output structure ke baare mein guide karne aur response ko Java types mein convert karne mein help kar sakte hain.

Exact converter aur API selected Spring AI version par depend karte hain.

Q39. What is a DTO?

Answer:

DTO ka full form Data Transfer Object hai.

DTO ek Java class hoti hai jiska use structured data ko represent aur transfer karne ke liye kiya jaata hai.

Example:

```
public class UserDto {

    private String name;
    private String email;

    public UserDto() {
    }

    public UserDto(String name, String email) {
        this.name = name;
        this.email = email;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getEmail() {
        return email;
    }

    public void setEmail(String email) {
        this.email = email;
    }
}
```

Q40. What is the benefit of converting AI output into a Java object?

Answer:

Java object ke through application fields ko directly access kar sakti hai.

Example:

```

# MODULE 9: Interview Revision — Questions and Answers

Q1. What is an AI model?

Answer: An AI model is a trained system that processes input and generates output based on learned patterns.

Q2. What is an LLM?

Answer: LLM stands for Large Language Model. It is an AI model designed primarily for language-related tasks.

Q3. What is a prompt?

Answer: A prompt is the question, instruction or context provided to an AI model.

Q4. What is a prompt placeholder?

Answer: A placeholder is a variable-like part of a prompt whose value is supplied dynamically.

Q5. What is a token?

Answer: A token is a unit of text processed by a language model. It can represent a word, part of a word or punctuation.

Q6. What is tokenization?

Answer: Tokenization is the process of dividing input text into tokens.

Q7. Why do tokens matter?

Answer: Tokens matter because they affect token-based API costs and the amount of information a model can process.

Q8. What is a context window?

Answer: A context window is the maximum amount of tokenized information a model can handle within its supported context limit.

Q9. What is an embedding?

Answer: An embedding is a numerical vector representation of an item, such as text, designed to capture useful features or semantic relationships.

Q10. What is semantic search?

Answer: Semantic search retrieves information based on meaning and similarity rather than relying only on exact keyword matches.

Q11. What is a vector database?

Answer: A vector database stores and searches vector representations, often for similarity-based retrieval.

Q12. What is RAG?

Answer: RAG stands for Retrieval-Augmented Generation. It retrieves relevant information and provides it to an AI model as context for generating an answer.

Q13. What is structured output?

Answer: Structured output is AI-generated data returned in an expected format, such as JSON or a Java DTO.

Q14. Why do we use DTOs?

Answer: DTOs represent structured data in Java and make it easier for applications to access and transfer fields.

Q15. Does structured output remove the need for validation?

Answer: No. Applications should still validate required fields, data types and business rules.

# Spring AI Part 8: How to Use Multiple AI Models in One Spring Boot Project

## MODULE 1: Why Do We Need Multiple AI Models?

Q1. Why do we need to use multiple AI models in a single Spring Boot application?

Answer:

Ek Spring Boot application mein multiple AI models use karne ke kuch important reasons hain:

1. Task Specialization: Different models different tasks ke liye useful ho sakte hain.
2. Fallback Mechanism: Agar ek model unavailable ho, to doosre model ko use kar sakte hain.
3. Experimentation: Different models ki performance compare aur test kar sakte hain.
4. User Choice: User ko option de sakte hain ki woh kis model se response lena chahta hai.
5. Complementary Strengths: Ek model ka output doosre model se verify ya improve karwa sakte hain.

Example:

```
Spring Boot Application
        |
        |---- OpenAI Model
        |
        |---- Ollama Model
        |
        |---- Other AI Model
```

Q2. What is Task Specialization?

Answer:

Task Specialization ka matlab hai kisi specific task ke liye suitable model choose karna.

Example:

- Model A: Complex reasoning
- Model B: Fast responses
- Model C: Code generation

Ye sirf illustrative examples hain. Actual capability model ke version aur configuration par depend karegi.

Q3. What is a Fallback Mechanism in AI applications?

Answer:

Fallback Mechanism ka matlab hai jab primary model se response nahi milta, tab application alternative model use karne ki koshish karti hai.

Example:

```
User Request
     |
     v
Primary Model: OpenAI
     |
     |-- Success --> Return Response
     |
     |-- Failure
            |
            v
       Backup Model: Ollama
            |
            v
       Return Response
```

Important: Sirf multiple models configure karne se fallback automatically implement nahi hota. Iske liye application mein failure handling aur retry/fallback logic likhna padta hai.

Experimentation mein hum different models ko same ya similar tasks dekar unki quality, response time aur cost compare karte hain.

Example:

```

Ollama  --> Response B
```

Phir hum compare kar sakte hain ki kaunsa response hamare use case ke liye better hai.

Q5. What are Complementary Strengths?

Answer:

Complementary Strengths ka matlab hai different models ki useful capabilities ko ek application mein combine karna.

Example:

1. Model A draft answer generate karta hai.
2. Model B answer review karta hai.
3. Application final result user ko return karti hai.

Is approach se cost aur response time badh sakte hain, aur review karne wala model bhi galti kar sakta hai. Isliye output validation useful hai.

## MODULE 5: Create Multiple ChatClient Beans

Q15. How can we create separate ChatClient beans for OpenAI and Ollama?

Answer:

Video mein configuration class banakar dono models ke liye alag `ChatClient` beans create kiye gaye hain.

Conceptual Java example:

```
@Configuration
public class AiConfig {

    @Bean("openAiChatClient")
    public ChatClient openAiChatClient(
            OpenAiChatModel openAiChatModel) {

        return ChatClient.builder(openAiChatModel).build();
    }

    @Bean("ollamaChatClient")
    public ChatClient ollamaChatClient(
            OllamaChatModel ollamaChatModel) {

        return ChatClient.builder(ollamaChatModel).build();
    }
}
```

Yahan:

- `@Configuration` configuration class define karta hai.
- `@Bean` Spring container mein object register karta hai.
- `openAiChatClient` OpenAI model use karta hai.
- `ollamaChatClient` Ollama model use karta hai.

Note: Model class names aur builder methods ko apne Spring AI version ke according verify karein. Agar same provider ki multiple configurations chahiye, to named model beans ya custom configuration ki zaroorat ho sakti hai.

Q16. What is the purpose of bean names?

Answer:

Bean names multiple beans ko uniquely identify karne mein help karte hain.

Example:

```
@Bean("openAiChatClient")
```

Aur:

```
@Bean("ollamaChatClient")
```

Dono beans ka type `ChatClient` hai, lekin names different hain.

Q17. What is `@Qualifier` in Spring?

Answer:

`@Qualifier` ka use tab hota hai jab same type ke multiple Spring beans available hon aur humein specific bean inject karna ho.

Example:

```
@RestController
public class ChatController {

    private final ChatClient openAiChatClient;
    private final ChatClient ollamaChatClient;

    public ChatController(
            @Qualifier("openAiChatClient")
            ChatClient openAiChatClient,

            @Qualifier("ollamaChatClient")
            ChatClient ollamaChatClient) {

        this.openAiChatClient = openAiChatClient;
        this.ollamaChatClient = ollamaChatClient;
    }
}
```

Is example mein:

- `openAiChatClient` naam ka bean first parameter mein inject hota hai.
- `ollamaChatClient` naam ka bean second parameter mein inject hota hai.

Q18. Why is `@Qualifier` important when multiple ChatClient beans exist?

Answer:

Agar multiple `ChatClient` beans hain aur Spring ko ye clear nahi hai ki kaunsa bean inject karna hai, to bean selection ambiguity aa sakti hai.

`@Qualifier` explicitly batata hai ki kaunsa bean chahiye.

## MODULE 6: Use Both ChatClients in a Controller

Q19. How can we use OpenAI and Ollama from the same controller?

Answer:

Hum dono clients ko inject karke different endpoints bana sakte hain.

Example:

```
@RestController
@RequestMapping("/chat")
public class ChatController {

    private final ChatClient openAiChatClient;
    private final ChatClient ollamaChatClient;

    public ChatController(
            @Qualifier("openAiChatClient")
            ChatClient openAiChatClient,

            @Qualifier("ollamaChatClient")
            ChatClient ollamaChatClient) {

        this.openAiChatClient = openAiChatClient;
        this.ollamaChatClient = ollamaChatClient;
    }

    @GetMapping("/openai")
    public String askOpenAI(@RequestParam String q) {
        return openAiChatClient
                .prompt()
                .user(q)
                .call()
                .content();
    }

    @GetMapping("/ollama")
    public String askOllama(@RequestParam String q) {
        return ollamaChatClient
                .prompt()
                .user(q)
                .call()
                .content();
    }
}
```

Example requests:

```
http://localhost:8080/chat/openai?q=Explain Java
```

```
http://localhost:8080/chat/ollama?q=Explain Java
```

First request OpenAI-configured client use karegi, aur second request Ollama-configured client use karegi.

Q20. What is the advantage of using named ChatClient beans?

Answer:

Named beans ke through application clearly identify kar sakti hai ki kaunsa client kis model ko use karta hai.

Advantages:

- Model selection easy hota hai.
- Configuration centralized hoti hai.
- Service classes mein clients reuse kiye ja sakte hain.
- Same application mein multiple model configurations maintain kar sakte hain.

## MODULE 3: Prompt Pass Karne Ke 3 Tarike

Q7. Teacher: ChatClient mein prompt pass karne ke kitne tarike video mein bataye gaye hain?

Answer: Jab humein system aur user messages ko separately configure karna ho, tab empty `prompt()` se start kar sakte hain.

```
String response = chatClient.prompt()
        .system("You are an expert in cricket.")
        .user("Tell me about Virat Kohli.")
        .call()
        .content();
```

Yahan do messages hain:

- System message: AI ko guide karta hai ki use kis tarah respond karna chahiye.
- User message: Actual question ya instruction deta hai.

Q9. Teacher: System message aur User message mein difference kya hai?

Answer:

| System Message                                | User Message                          |
| --------------------------------------------- | ------------------------------------- |
| AI ka behaviour guide karta hai.              | Actual question ya task deta hai.     |
| Role, tone ya expertise define kar sakta hai. | User ki requirement batata hai.       |
| Example: `You are an expert in cricket.`      | Example: `Tell me about Virat Kohli.` |

System message response ko guide karta hai, lekin output ki accuracy guarantee nahi karta.

Q10. Teacher: Direct string prompt ka example do.

Answer: Video mein string ko directly prompt ke roop mein pass karne ka tarika bhi bataya gaya hai.

Version ke hisaab se API available ho to example:

```
String response = chatClient.prompt("Tell me about Java")
        .call()
        .content();
```

Is approach mein simple prompt bhejne ke liye alag se `.user()` call likhne ki zaroorat nahi pad sakti.

Q11. Teacher: `Prompt` object kya represent karta hai?

Answer: `Prompt` ek object hai jo AI request ke messages aur prompt-related information ko represent karta hai. Agar prompt pehle se kisi variable mein bana hua hai, to use ChatClient ko pass kar sakte hain.

Conceptual example:

```
Prompt prompt = new Prompt(
        new UserMessage("Tell me about Java")
);

String response = chatClient.prompt(prompt)
        .call()
        .content();
```

Yeh example Spring AI ke commonly used types ko illustrate karta hai; constructor aur method signatures apne project ki version ke saath verify karein.

Q12. Teacher: `Message` aur `Prompt` mein kya difference hai?

Answer:

- Message: Ek individual message represent karta hai, jaise user message ya system message.
- Prompt: AI request ke liye ek ya multiple messages ko represent kar sakta hai.

Example:

```
System Message: You are a Java teacher.
User Message: Explain HashMap.
Prompt: System Message + User Message
```

Is tarah AI ko question ke saath required context bhi diya ja sakta hai.

## MODULE 4: Call, Content Aur ChatResponse

Q13. Teacher: `call()` ka kya kaam hai?

Answer: `call()` synchronous AI interaction execute karne ke liye use hota hai. Iske baad hum response ko alag-alag forms mein retrieve kar sakte hain.

```
chatClient.prompt()
        .user("Explain Java")
        .call()
        .content();
```

Q14. Teacher: `content()` kya return karta hai?

Answer: `content()` AI ke response ka text return karta hai, yani jab humein sirf answer chahiye tab ye convenient hai.

```
String answer = chatClient.prompt()
        .user("What is Spring Boot?")
        .call()
        .content();
```

Agar sirf text chahiye, to generally itna kaafi hai.

Q15. Teacher: Kya AI response hamesha sirf String hota hai?

Answer: Nahi. Application mein kabhi sirf text chahiye hota hai, lekin kabhi response ke saath metadata, token usage, model information ya doosri details bhi chahiye hoti hain.

Video mein isliye `ChatResponse` ka concept explain kiya gaya hai.

Q16. Teacher: `ChatResponse` kya hai?

Answer: `ChatResponse` AI model se aane wale response ko structured form mein represent karta hai. Ismein generated output ke saath metadata aur generations ki information ho sakti hai.

Video mein dikhaya gaya conceptual flow:

```
ChatClient
    |
    v
call()
    |
    v
ChatResponse
    |
    +----> Result / Generation
    |          |
    |          v
    |      AssistantMessage
    |          |
    |          v
    |        Text
    |
    +----> Metadata
```

Q17. Teacher: `Generation` kya hota hai?

Answer: Video mein `Generation` ko generated assistant output ke ek result ke roop mein explain kiya gaya hai. `ChatResponse` mein ek ya multiple generations represent ho sakti hain, depending on the response and API structure.

Q18. Teacher: `AssistantMessage` kya hai?

Answer: Ye AI assistant ki taraf se generate hua message represent karta hai. Is message se actual text retrieve kiya ja sakta hai.

Video mein dikhaya gaya detailed extraction flow:

```
ChatResponse
    |
    v
getResult()
    |
    v
Generation
    |
    v
getOutput()
    |
    v
AssistantMessage
    |
    v
getText()
    |
    v
Actual Response Text
```

Conceptually, commonly used API pattern:

```
ChatResponse response = chatClient.prompt()
        .user("Tell me about Java")
        .call()
        .chatResponse();

String answer = response.getResult()
        .getOutput()
        .getText();
```

Iske exact method names aur availability ko apne Spring AI version mein verify karein. Agar sirf String chahiye, to `.content()` wala simpler approach use kar sakte hain.

## MODULE 5: Metadata, Token Usage Aur Rate Limits

Q19. Teacher: Response metadata kya hota hai?

Answer: Metadata response ke baare mein additional information hoti hai. Video mein `ChatResponse` ke metadata se chat ID, token usage, model information aur rate-limit information access karna dikhaya gaya hai.

Q20. Teacher: Token usage kya hota hai?

Answer: AI model input aur output ko process karne ke liye tokens use karta hai.

Video mein example:

- Prompt tokens: `15`
- Completion tokens: `548`
- Total tokens: `563`

Calculation:

```
Total Tokens = Prompt Tokens + Completion Tokens
Total Tokens = 15 + 548 = 563
```

Ye video ka example hai, fixed token usage nahi. Actual tokens prompt aur response ke size par depend karte hain.

Q21. Teacher: Prompt tokens aur Completion tokens mein kya difference hai?

Answer:

- Prompt tokens: Model ko input mein bheje gaye text aur applicable context ke tokens.
- Completion tokens: Model ne response generate karte waqt use kiye tokens.
- Total tokens: Input aur output token usage ka total, as reported by the provider/API.

Q22. Teacher: Token usage important kyun hai?

Answer: Hosted AI providers ke case mein token usage billing aur cost estimation ke liye important ho sakta hai. Token usage monitor karke hum AI requests ki cost samajh sakte hain.

Example:

```
Request 1 → 500 total tokens
Request 2 → 1,000 total tokens
Request 3 → 2,000 total tokens
```

Agar provider token-based billing use karta hai, to actual cost uske pricing rules aur input/output token rates par depend karegi.

Important: Local Ollama model ke liye hosted API jaisi per-token billing zaroori nahi hoti. Video ka charging example external provider, jaise OpenAI, ke context mein hai.

Q23. Teacher: Rate limit kya hoti hai?

Answer: Rate limit batati hai ki kisi time window mein API ko kitni requests ya tokens use karne ki permission hai.

Video mein example:

```
Request Limit: 500
Requests Remaining: 499
```

Ye sirf illustrative output hai. Actual limits provider, account, model aur time window ke hisaab se change hoti hain.

Q24. Teacher: Metadata kaise retrieve karenge?

Answer: Video mein `ChatResponse` ke metadata ko access karne ke liye `getMetadata()` approach explain ki gayi hai.

Conceptual example:

```
ChatResponse response = chatClient.prompt()
        .user("Tell me about Java")
        .call()
        .chatResponse();

var metadata = response.getMetadata();

System.out.println(metadata);
```

Specific fields, jaise token usage, model information aur rate limits, provider aur Spring AI version ke hisaab se available ho sakte hain.

Q25. Teacher: Agar sirf answer chahiye aur metadata nahi, to kya karein?

Answer: Directly `.content()` use karein.

```
String answer = chatClient.prompt()
        .user("Explain Java Collections")
        .call()
        .content();
```

Isse code short aur readable rehta hai.

## MODULE 6: AI Response Ko Java Object Mein Convert Karna

Q26. Teacher: AI response ko POJO mein convert karne ki zaroorat kyun hoti hai?

Answer: Kabhi AI ka answer plain text mein chahiye hota hai, lekin application ko structured data chahiye hota hai.

Example, AI se Java ke baare mein answer aaya:

```
Title: Java Programming Language
Content: Java is an object-oriented programming language.
Created Year: 1995
```

Agar humein is information ko application mein alag fields mein use karna hai, to ise Java object mein map karna useful hai.

Q27. Teacher: POJO kya hota hai?

Answer: POJO (Plain Old Java Object) ek simple Java class hoti hai jo data represent kar sakti hai.

Example:

```
public class Tutorial {

    private String title;
    private String content;
    private String createdYear;

    public Tutorial() {
    }

    public String getTitle() {
        return title;
    }

    public void setTitle(String title) {
        this.title = title;
    }

    public String getContent() {
        return content;
    }

    public void setContent(String content) {
        this.content = content;
    }

    public String getCreatedYear() {
        return createdYear;
    }

    public void setCreatedYear(String createdYear) {
        this.createdYear = createdYear;
    }
}
```

Video mein similar model class banayi gayi thi, jismein title, content aur created year fields thi.

Q28. Teacher: ChatClient ke `entity()` method ka use kya hai?

Answer: Video mein `entity()` method use karke AI response ko specified Java class ke object mein convert karna dikhaya gaya hai.

Example:

```
Tutorial tutorial = chatClient.prompt()
        .user("Tell me about Java")
        .call()
        .entity(Tutorial.class);
```

Ab response ko `Tutorial` object ke roop mein receive karne ka intention hai, jisse hum fields access kar sakte hain:

```
System.out.println(tutorial.getTitle());
System.out.println(tutorial.getContent());
System.out.println(tutorial.getCreatedYear());
```

Important: Ye object conversion automatic aur guaranteed accurate nahi maana jaana chahiye. AI output ko validate karna zaroori hai. Exact `entity()` API aur mapping support Spring AI version aur configured converters par depend kar sakte hain.

Q29. Teacher: Kya AI response ko Controller se directly return kar sakte hain?

Answer: Haan. Agar service ek `Tutorial` object return karti hai, to Spring MVC us object ko configured JSON converter ke through JSON response mein serialize kar sakta hai.

Example:

```
@GetMapping("/tutorial")
public Tutorial getTutorial(@RequestParam String q) {
    return chatService.chat(q);
}
```

Yahan example ke liye `chatService.chat(q)` ka return type `Tutorial` hona chahiye. Agar service abhi `String` return karti hai, to interface aur implementation ke return types ko bhi update karna padega.

Possible JSON response:

```
{
  "title": "Java Programming Language",
  "content": "Java is an object-oriented programming language.",
  "createdYear": "1995"
}
```

Ye illustrative output hai, guaranteed AI response nahi.

Q30. Teacher: Video mein `entity()` ka return type kaise change kiya gaya?

Answer: Pehle service `String` return kar rahi thi. Jab AI response ko `Tutorial` object mein map karna tha, to service interface, implementation aur controller ke return types ko `Tutorial` mein change kiya gaya.

```
public interface ChatService {
    Tutorial chat(String query);
}
```

Implementation ka relevant method:

```
@Override
public Tutorial chat(String query) {
    return chatClient.prompt()
            .user(query)
            .call()
            .entity(Tutorial.class);
}
```

Controller:

```
@GetMapping("/tutorial")
public Tutorial tutorial(@RequestParam String q) {
    return chatService.chat(q);
}
```

Isse poora flow consistent rehta hai:

```
Controller → Service → ChatClient → Tutorial Object → JSON Response
```

## MODULE 7: List of Java Objects Return Karna

Q31. Teacher: Agar humein ek object ke bajay multiple objects chahiye, to kya karenge?

Answer: Java mein `List<Tutorial>` use karenge. Example: AI se five programming languages ki details mangni hain aur har language ka title, content aur created year chahiye.

Expected structure:

```
List<Tutorial>
    |
    |-- Tutorial 1: Python
    |-- Tutorial 2: Java
    |-- Tutorial 3: JavaScript
    |-- Tutorial 4: C++
    |-- Tutorial 5: Ruby
```

Ye video ke example mein dikhayi gayi list mapping ki concept hai. Names aur dates actual model output ke hisaab se different ho sakte hain.

Q32. Teacher: `List<Tutorial>` aur `Tutorial` mein kya difference hai?

Answer:

- `Tutorial` ek single object represent karta hai.
- `List<Tutorial>` multiple `Tutorial` objects ka collection represent karti hai.

Example:

```
Tutorial tutorial;
```

Ek tutorial.

```
List<Tutorial> tutorials;
```

Multiple tutorials.

Q33. Teacher: Java mein `List<Tutorial>` ke liye sirf `Tutorial.class` kyun sufficient nahi hai?

Answer: Java generics ki wajah se runtime par `List<Tutorial>` aur `List<String>` jaise parameterized types ki complete type information normal `List.class` se preserve nahi hoti. Isliye video mein `ParameterizedTypeReference` use kiya gaya.

Conceptual example:

```
List<Tutorial> tutorials = chatClient.prompt()
        .user("List five programming languages with title, content and created year.")
        .call()
        .entity(new ParameterizedTypeReference<List<Tutorial>>() {});
```

Is example ka purpose ye batana hai ki expected response type `List<Tutorial>` hai. Exact overload aapke Spring AI version ke saath verify karein.

Q34. Teacher: `ParameterizedTypeReference` kya karta hai?

Answer: Ye generic type ki information represent karne mein help karta hai, jaise `List<Tutorial>`. Sirf `List.class` pass karne se list ke andar expected element type ki information nahi milti.

Example:

```
new ParameterizedTypeReference<List<Tutorial>>() {}
```

Iska meaning hai: “Mujhe ek list chahiye jiske elements `Tutorial` type ke hon.”

Q35. Teacher: List of objects ke liye interface aur service kaise change honge?

Answer: Return type ko `List<Tutorial>` karenge.

Interface:

```
import java.util.List;

public interface ChatService {
    List<Tutorial> chat(String query);
}
```

Implementation ka relevant method:

```
@Override
public List<Tutorial> chat(String query) {
    return chatClient.prompt()
            .user(query)
            .call()
            .entity(new ParameterizedTypeReference<List<Tutorial>>() {});
}
```

Controller:

```
@GetMapping("/tutorials")
public List<Tutorial> tutorials(@RequestParam String q) {
    return chatService.chat(q);
}
```

Is code mein `Tutorial` class aur required imports available hone chahiye. Agar aapke Spring AI version mein `entity()` ka supported overload alag hai, to us version ke API ke according code adjust karein.

Q36. Teacher: Kya hum kisi bhi topic ki list maang sakte hain?

Answer: Haan, prompt mein topic aur expected information specify kar sakte hain.

Examples:

```
List five programming languages.
```

```
List five Java programming books with title, content and published year.
```

```
List five Indian cricketers with title, content and career start year.
```

Lekin AI ke generated facts ko verify karna zaroori hai. Video mein bhi ek example ke liye incorrect year ka response observe kiya gaya tha. Structured output ka matlab automatically factually correct output nahi hai.

# MODULE 9: Important Interview Questions with Answers

Q39. Teacher: ChatClient kya hai?

Answer: `ChatClient` Spring AI ka high-level fluent API hai jo AI model ke saath interaction karne ke liye use hota hai.

Q40. Teacher: Fluent API ka main benefit kya hai?

Answer: Fluent API method chaining se code ko readable aur concise banati hai.

Q41. Teacher: `prompt()` aur `call()` mein kya difference hai?

Answer: `prompt()` request banane aur configure karne ke liye use hota hai. `call()` synchronous request execute karta hai.

Q42. Teacher: System message ka kya use hai?

Answer: System message model ko desired behaviour, role, tone ya instructions ke baare mein guide karta hai.

Q43. Teacher: User message kya hota hai?

Answer: User message actual question ya instruction hota hai jiska model ko response generate karna hota hai.

Q44. Teacher: `content()` kya return karta hai?

Answer: Ye generated response ka text return karta hai.

Q45. Teacher: `ChatResponse` kya represent karta hai?

Answer: Ye AI response ko structured form mein represent karta hai, jismein generated output aur metadata jaise details ho sakti hain.

Q46. Teacher: `Generation` kya represent karta hai?

Answer: Ye generated assistant output ke ek result ko represent karta hai.

Q47. Teacher: `AssistantMessage` kya hota hai?

Answer: Ye AI assistant ki taraf se generate kiya gaya message represent karta hai.

Q48. Teacher: Metadata kya hota hai?

Answer: Metadata response ke baare mein additional information hoti hai, jaise token usage aur model-related details, jo provider aur API support par depend karti hain.

Q49. Teacher: Prompt tokens aur completion tokens kya hote hain?

Answer: Prompt tokens input processing se related hote hain, jabki completion tokens generated output se related hote hain.

Q50. Teacher: `entity()` method ka kya use hai?

Answer: Iska use AI response ko specified Java type, jaise `Tutorial`, mein map karne ke liye kiya ja sakta hai, jab configured Spring AI API aur converters isko support karte hain.

Q51. Teacher: POJO kya hai?

Answer: POJO ek simple Java object hai jo application ka data represent kar sakta hai.

Q52. Teacher: `Tutorial.class` kyun pass karte hain?

Answer: Taaki expected response type `Tutorial` specify kiya ja sake.

Q53. Teacher: `List<Tutorial>` ko map karne ke liye `ParameterizedTypeReference` kyun use hota hai?

Answer: Ye `List<Tutorial>` jaise generic type ki information represent karne mein help karta hai.

Q54. Teacher: AI response ko Java object mein map karne ka kya benefit hai?

Answer: Data ko fields ke through access kar sakte hain aur application mein structured form mein use kar sakte hain, instead of manually parsing plain text.

Q55. Teacher: Kya structured output hamesha correct hota hai?

Answer: Nahi. Object ka format sahi hone ke baad bhi uske values incorrect ya incomplete ho sakte hain. Validation aur factual verification zaroori hai.

Q56. Teacher: `ChatClient` ko Service class mein rakhne ka kya benefit hai?

Answer: Isse controller aur AI logic separate rehte hain. Code ko test, maintain aur reuse karna easier hota hai.
