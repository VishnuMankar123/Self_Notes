## 1. Important downstream collectors

| No. | Collector             | Use case                               | Return type               |
| --- | --------------------- | -------------------------------------- | ------------------------- |
| 1   | `toList()`            | Elements ki List                       | `List<T>`                 |
| 2   | `toSet()`             | Unique elements                        | `Set<T>`                  |
| 3   | `toCollection()`      | Specific collection, e.g. `TreeSet`    | Collection type           |
| 4   | `counting()`          | Count                                  | `Long`                    |
| 5   | `summingInt()`        | Integer values ka sum                  | `Integer`                 |
| 6   | `summingLong()`       | Long values ka sum                     | `Long`                    |
| 7   | `summingDouble()`     | Decimal values ka sum                  | `Double`                  |
| 8   | `averagingInt()`      | Integer values ka average              | `Double`                  |
| 9   | `averagingLong()`     | Long values ka average                 | `Double`                  |
| 10  | `averagingDouble()`   | Decimal values ka average              | `Double`                  |
| 11  | `summarizingInt()`    | Count, sum, min, avg, max              | `IntSummaryStatistics`    |
| 12  | `summarizingLong()`   | Count, sum, min, avg, max              | `LongSummaryStatistics`   |
| 13  | `summarizingDouble()` | Count, sum, min, avg, max              | `DoubleSummaryStatistics` |
| 14  | `minBy()`             | Minimum element                        | `Optional<T>`             |
| 15  | `maxBy()`             | Maximum element                        | `Optional<T>`             |
| 16  | `mapping()`           | Element ka field transform karna       | Downstream par depend     |
| 17  | `collectingAndThen()` | Collection ke baad finishing operation | Finisher par depend       |
| 18  | `joining()`           | Strings ko join karna                  | `String`                  |
| 19  | `reducing()`          | Custom reduction                       | Depends on overload       |

Correction: Upar ke table mein 19 methods/patterns hain, 13 nahi. Ye commonly useful Java 8 collectors ki practical list hai; ise Java ke har possible downstream collector ki exhaustive list mat samajhna.

## 2. Kaun-se collectors nesting ke liye use hote hain?

Ye sabse important pattern hai:

```
Map<String, Long> result =
    employees.stream()
        .collect(Collectors.groupingBy(
            Employee::getDepartment,
            Collectors.counting()
        ));
```

Yahan:

- `groupingBy()` — outer collector
- `counting()` — downstream collector

Isi tarah:

```
groupingBy(Employee::getDepartment, toList())
groupingBy(Employee::getDepartment, summingDouble(Employee::getSalary))
groupingBy(Employee::getDepartment, averagingDouble(Employee::getSalary))
groupingBy(Employee::getDepartment, maxBy(Comparator.comparing(Employee::getSalary)))
```

## 3. Advanced nesting ke liye

Java 8 mein `mapping()`, `collectingAndThen()` aur `reducing()` jaise collectors ko doosre collectors ke saath combine kar sakte ho.

Example:

```
Map<String, List<String>> result =
    employees.stream()
        .collect(Collectors.groupingBy(
            Employee::getDepartment,
            Collectors.mapping(
                Employee::getName,
                Collectors.toList()
            )
        ));
```

Isme nesting hai:

```
groupingBy()
    └── mapping()
            └── toList()
```

Java version yaad rakho: `filtering()`, `flatMapping()` Java 9 mein aaye, aur `teeing()` Java 12 mein. Ye Java 8 ke collectors nahi hain.

# 1. Sabse pehle `collect()` kya hai?

Java Stream me hum data ko process karte hain:

```java
List<Employee> employees
        ↓
stream()
        ↓
filter()
        ↓
map()
        ↓
sorted()
        ↓
collect()
```

`collect()` ka kaam hai:

> **Stream ke processed data ko final result/container me convert karna.**

Example:

```java
List<String> names = employees.stream()
        .map(Employee::getName)
        .collect(Collectors.toList());
```

Yaha:

```text
employees
   ↓
stream()
   ↓
getName()
   ↓
String stream
   ↓
collect(toList())
   ↓
List<String>
```

### Important

`map()` result ko transform karta hai.

`filter()` data select karta hai.

`sorted()` data arrange karta hai.

`collect()` **final result ko collect karta hai.**

# 10. `toList()` vs `toSet()`

Very important:

| Requirement              | Collector  |
| ------------------------ | ---------- |
| List chahiye             | `toList()` |
| Duplicate preserve karna | `toList()` |
| Unique values chahiye    | `toSet()`  |
| Duplicate remove karna   | `toSet()`  |

Example:

```java
List<Integer> list =
    numbers.stream()
           .collect(Collectors.toList());
```

Duplicates remain kar sakte hain.

```java
Set<Integer> set =
    numbers.stream()
           .collect(Collectors.toSet());
```

Duplicates eliminate ho jate hain.

# 26. Interview question

### Q: `collect()` kya hai?

**Answer:**

> `collect()` is a terminal operation of Stream API used to accumulate stream elements into a final result such as List, Set, Map, String, or grouped result using a Collector.

Simple Hinglish:

> `collect()` stream ke processed elements ko final result/container me convert karta hai.

---

# 27. Interview Question

### Q: `Collector` aur `Collectors` difference?

**Answer:**

> `Collector` is an interface that defines how stream elements are accumulated, whereas `Collectors` is a utility class that provides predefined Collector implementations such as `toList()`, `toSet()`, `groupingBy()`, `counting()`, etc.

Short:

```text
Collector  → interface
Collectors → utility class
```

# 1. `toMap()` kya karta hai?

Simple language:

> Stream ke elements ko **Map<Key, Value>** me convert karta hai.

Basic syntax:

```java
Collectors.toMap(
    keyMapper,
    valueMapper
)
```

Example:

```java
Map<Integer, String> result =
        employees.stream()
                .collect(Collectors.toMap(
                        Employee::getId,
                        Employee::getName
                ));
```

Flow:

```text
Employee
   ↓
getId()       → Key
getName()     → Value
   ↓
toMap()
   ↓
Map<Integer, String>
```

```java

```

Formula:

```text
toMap(
    KEY,
    VALUE
)
```

# 31. `toMap()` vs `groupingBy()` — Interview Answer

> `toMap()` is used when each key should map to a single value, while `groupingBy()` is used when multiple stream elements need to be grouped under the same key.

# 32. 🔥 Interview Question

### Q: What happens if duplicate keys occur in `Collectors.toMap()`?

Answer:

> The two-argument `toMap()` throws an `IllegalStateException` when duplicate keys are encountered. We can handle duplicates using the third argument, which is a merge function.

Example:

```java
Collectors.toMap(
    Employee::getId,
    Employee::getName,
    (oldValue, newValue) -> newValue
)
```

# 33. 🔥 Interview Question

### Q: Why do we use merge function?

Because:

```text
Key same
  ↓
Two values
  ↓
Which value should Map keep?
```

Merge function decides that.

Examples:

```java
(a, b) -> a
```

Keep old.

```java
(a, b) -> b
```

Keep new.

```java
(a, b) -> a + b
```

Combine.

Haan. **`mergeFunction` ko properly samajhna bahut important hai**, kyunki `toMap()` ka actual power yahin se aata hai.

# ⭐ One formula to remember

```java
Collectors.toMap(
    KEY,
    VALUE,
    (OLD_VALUE, NEW_VALUE) -> FINAL_VALUE
);
```

Bas **FINAL_VALUE** ke liye tumhari requirement ke according logic lagana hai.

```text
FIRST          → oldValue
LATEST         → newValue
SUM            → old + new
MAX            → max(old,new)
MIN            → min(old,new)
COUNT          → old + 1 / Integer::sum
COMBINE STRING → old + new
BEST OBJECT    → compare fields
LIST           → addAll
SET            → addAll
```

### Ek bahut important distinction

`mergeFunction` **har element par nahi chalta**.

Ye **sirf duplicate key encounter hone par** relevant hota hai.

Example:

```text
101 → Vishnu    ← first 101, no merge
102 → Rahul     ← first 102, no merge
101 → Amit      ← duplicate 101 → MERGE
103 → Sneha     ← first 103, no merge

```

Isliye `mergeFunction` ko samajhne ka best phrase hai:

> **"Same key ke multiple values ko ek final value me merge karna."**

# 16. The most important concept: Downstream Collector

Suppose:

```java
groupingBy(Employee::getDepartment, ???)
```

The `???` is your requirement.

| Requirement                | Downstream            |
| -------------------------- | --------------------- |
| Employee list              | `toList()`            |
| Unique employees/values    | `toSet()`             |
| Count                      | `counting()`          |
| Sum int                    | `summingInt()`        |
| Sum long                   | `summingLong()`       |
| Sum double                 | `summingDouble()`     |
| Average int                | `averagingInt()`      |
| Average long               | `averagingLong()`     |
| Average double             | `averagingDouble()`   |
| Maximum                    | `maxBy()`             |
| Minimum                    | `minBy()`             |
| Extract field              | `mapping()`           |
| Transform after collecting | `collectingAndThen()` |

This is the **core of grouping questions**.

Important:

Ye `stream().filter()` se different behavior de sakta hai.

```java

    .filter(Employee::isActive)
    .collect(groupingBy(...));
```

Inactive employees ke departments **map me appear hi nahi karenge**.

### Downstream filtering:

```java
groupingBy(
    department,
    filtering(...)
)
```

Department group create ho sakta hai, aur us group ki list empty ho sakti hai.

Ye distinction interview me useful hai.

# PART 4 — `partitioningBy()` MASTER GUIDE 🔥

Ab tak tumne:

```text
Part 1 → collect(), toList(), toSet(), toCollection(), joining()
Part 2 → toMap(), duplicate key, mergeFunction
Part 3 → groupingBy(), downstream collectors
```

Ab **`partitioningBy()`**. Ye `groupingBy()` ka alternative nahi hai in general; iska use specifically **2 groups — `true` aur `false`** banane ke liye hota hai.

Tumhare uploaded notes me bhi basic distinction diya hai: `groupingBy()` multiple groups/any key ke liye, aur `partitioningBy()` sirf Boolean `true/false` groups ke liye.

# 1. `partitioningBy()` kya karta hai?

Simple language:

> Ek condition ke basis par data ko **2 groups** me divide karta hai.

```text
                 Employees
                     ↓
              Condition?
              /         \
           true         false
            ↓             ↓
        Group 1        Group 2
```

Example:

> Employees ko Active aur Inactive me divide karo.

```text
Active
 ├── Vishnu
 ├── Amit
 └── Rahul

Inactive
 ├── Sneha
 └── Akash
```

```java
)
```

```java

    Employee::isActive,
    maxBy(Comparator.comparing(Employee::getSalary))
)
```

# 16. Your previous question — "Double ki jagah Integer chahiye"

Suppose:

```java
Map<String, Double> result =
        employees.stream()
                .collect(Collectors.groupingBy(
                        Employee::getDepartment,
                        Collectors.summingDouble(
                                Employee::getSalary
                        )
                ));
```

Naturally result:

```java
Map<String, Double>
```

because:

```java
summingDouble()
```

returns `Double`.

### If you genuinely need Integer

You need to decide **what conversion means**.

For example:

```java
Map<String, Integer> result =
        employees.stream()
                .collect(Collectors.groupingBy(
                        Employee::getDepartment,
                        Collectors.summingInt(
                                e -> (int) e.getSalary()
                        )
                ));
```

But **careful**:

```text
75000.50
```

becomes:

```text
75000
```

fractional part lost.

So don't change Double → Integer just to satisfy the return type unless that loss is acceptable.

# 17. `summingInt()` vs casting

Suppose salary is:

```java

```

You can technically:

```java

```

But this means:

```text
salary
75000.99
      ↓
(int)
      ↓
75000
```

Therefore:

> **Choose the Collector based on the actual data type and business requirement, not just the desired variable type.**

# 1. `maxBy()` kya karta hai?

Simple:

> Given objects me se **maximum value wala object** find karta hai.

Syntax:

```java
Collectors.maxBy(comparator)
```

Example:

```java
Optional<Employee> result =
        employees.stream()
                 .collect(
                     Collectors.maxBy(
                         Comparator.comparing(
                             Employee::getSalary
                         )
                     )
                 );
```

Meaning:

```text
Employees
    ↓
salary compare
    ↓
highest salary employee
    ↓
Optional<Employee>
```

---

# 2. `minBy()` kya karta hai?

Exactly opposite.

> Given objects me se **minimum value wala object** find karta hai.

```java
Optional<Employee> result =
        employees.stream()
                 .collect(
                     Collectors.minBy(
                         Comparator.comparing(
                             Employee::getSalary
                         )
                     )
                 );
```

Meaning:

```text
Employees
    ↓
salary compare
    ↓
lowest salary employee
```

---

# 3. `maxBy()` ka input kya hai?

Input:

```java
Comparator<Employee>
```

Example:

```java
Comparator.comparing(Employee::getSalary)
```

So:

```text
Employee
   ↓
getSalary()
   ↓
compare salaries
   ↓
max
```

---

# 4. Output kya hai?

Bahut important:

```java
Optional<Employee>
```

Not:

```java
Employee
```

Why?

Because stream empty ho sakti hai.

Example:

```text
employees = []
```

Highest employee kaun?

```text
koi nahi
```

So Java directly `null` return karne ke bajay:

```java
Optional<Employee>
```

return karta hai.

# 8. `maxBy()` vs `max()`

Ye interview me pucha ja sakta hai.

Stream ka:

```java

```

aur Collector ka:

```java
Collectors.maxBy(comparator)
```

conceptually same maximum element find karte hain, but **use context different hai**.

### Direct stream operation:

```java
Optional<Employee> result =
        employees.stream()
                 .max(
                     Comparator.comparing(
                         Employee::getSalary
                     )
                 );
```

### Collector:

```java
Optional<Employee> result =
        employees.stream()
                 .collect(
                     Collectors.maxBy(
                         Comparator.comparing(
                             Employee::getSalary
                         )
                     )
                 );
```

### Important practical point

Agar **whole stream ka max** chahiye:

```java
stream.max()
```

zyada direct hai.

Agar `groupingBy()` / `partitioningBy()` ke **andar maximum** chahiye:

```java
Collectors.maxBy()
```

bahut useful hai.

# 17. Descending Comparator ka trap ⚠️

Suppose:

```java
Comparator.comparing(Employee::getSalary)
```

normal ascending comparison hai.

`maxBy()`:

```java
maxBy(
    Comparator.comparing(Employee::getSalary)
)
```

→ highest salary.

But agar:

```java
Comparator.comparing(Employee::getSalary)
    .reversed()
```

use kiya:

```java
maxBy(
    Comparator.comparing(Employee::getSalary)
             .reversed()
)
```

comparison ordering reverse ho gayi.

Isliye `minBy()` / `maxBy()` ke saath comparator direction ko consciously choose karo.

# 20. Very important — `Optional` remove kaise kare?

Suppose:

```java
Map<String, Optional<Employee>> result
```

But interviewer wants:

```java
Map<String, Employee>
```

Tab `collectingAndThen()` useful hai.

Pattern:

```java
groupingBy(
    key,
    collectingAndThen(
        maxBy(...),
        Optional::get
    )
)
```

---

# 21. Example 🔥

Department-wise highest salary employee:

```java
Map<String, Employee> result =
        employees.stream()
                 .collect(
                     Collectors.groupingBy(
                         Employee::getDepartment,
                         Collectors.collectingAndThen(
                             Collectors.maxBy(
                                 Comparator.comparing(
                                     Employee::getSalary
                                 )
                             ),
                             Optional::get
                         )
                     )
                 );
```

Now output:

```java
Map<String, Employee>
```

instead of:

```java
Map<String, Optional<Employee>>
```

---

# 22. But `Optional::get` ka danger ⚠️

Agar kisi group me employee nahi hai, `Optional::get` fail kar sakta hai.

So safer approach depends on your business requirement.

For example:

```java
.collect(
    Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.collectingAndThen(
            Collectors.maxBy(
                Comparator.comparing(Employee::getSalary)
            ),
            optional -> optional.orElse(null)
        )
    )
);
```

Now result:

```java
Map<String, Employee>
```

and empty result can become `null`.

But whether `null` is appropriate depends on the requirement.

```java
)
```

Agar question:

> Department-wise highest salary

# 4. Ye `mapping()` actually kar kya raha hai?


Lekin:

```text

       ↓

       ↓
List<String>
```

# 22. Order samajhna very important hai

Ye:

```java

    Employee::isActive,
    mapping(
        Employee::getName,
        toList()
    )
```

means:

> **Outer collector pehle logically process hota hai, downstream collector next. Type ko hamesha track karo.**

Suppose employees:

```text

Rahul → [Java, Kafka]
Neha  → [SQL, Java]
```

> Department-wise all skills chahiye.

Without flattening:

```text

```

But we want:

```text

```

That's where:

```java
flatMapping()
```

comes in.

Suppose:

```java

}
```

```java

```

returns:



# 42. 🔥 Master Pattern

Ab ye pattern samajh lo:

```java
groupingBy(
    KEY,
    DOWNSTREAM_COLLECTOR
)
```

`DOWNSTREAM_COLLECTOR` kuch bhi ho sakta hai:

```text
counting()
summingDouble()
averagingDouble()
summarizingDouble()
minBy()
maxBy()
mapping()
filtering()
flatMapping()
```

Aur inko **nest** bhi kar sakte ho.

Example:

```java
groupingBy(
    department,
    filtering(
        active,
        mapping(
            name,
            toSet()
        )
    )
)
```

Ya:

```java
groupingBy(
    department,
    filtering(
        active,
        flatMapping(
            skills,
            toSet()
        )
    )
)
```

# 🧠 PART 8 — FINAL REVISION

### `mapping()`

> **Mujhe object ka specific field chahiye.**

```java
mapping(
    Employee::getName,
    toList()
)
```

---

### `filtering()`

> **Group ke andar condition lagani hai.**

```java
filtering(
    Employee::isActive,
    toList()
)
```

---

### `flatMapping()`

> **Object ke andar collection hai aur mujhe usko flatten karna hai.**

```java
flatMapping(
    e -> e.getSkills().stream(),
    toSet()
)
```

## ⭐ Interview Recognition Trick

Question me ye words dekho:

```text
"names" / "cities" / "salary values"
        ↓
    mapping()

"active employees within each department"
        ↓
    filtering()

"all skills / all tags / nested lists"
        ↓
    flatMapping()
```

Aur agar question bole:

```text
Department-wise
```

to immediately socho:

```java
groupingBy()
```

Then second requirement identify karo:

```text
count       → counting()
sum         → summing*
average     → averaging*
all stats   → summarizing*
highest     → maxBy()
lowest      → minBy()
field       → mapping()
condition   → filtering()
nested list → flatMapping()
```

### 🔥 Is point par tumhara Collector decision tree kaafi strong ho gaya hai:

```text
                 groupingBy()
                      │
        ┌─────────────┼──────────────┐
        ↓             ↓              ↓
    calculation    selection      transformation
        │             │              │
 count/sum/avg    min/max       mapping
 summarizing                     filtering
                                 flatMapping
```

**Next Part 9** me hum `collectingAndThen()` ko deeply karenge — ye `Collectors` ka bahut important finishing collector hai, jisse `Optional` remove karna, result ko `unmodifiable` banana, `List → Set`, `List → custom result`, aur `groupingBy() + maxBy() + collectingAndThen()` jaise interview patterns solve kar sakte ho.

===================================================================================================================
`Collectors.collectingAndThen(collector, finisher)` mein finisher ki koi fixed list nahi hai. Tum koi bhi suitable Java `Function` ya method reference use kar sakte ho, bas uska input type `collector` ke output type se match hona chahiye.

```
Collectors.collectingAndThen(
    collector,
    finisher
)
```

- Collector: pehle result banata hai.
- Finisher: us result ko transform karke final output deta hai.

## 1. Most useful finishers — Interview ke liye

Neeche examples mein `employees` ka type `List<Employee>` maana hai.

### 1. `List::size` — List se count nikalna

```
Integer count = employees.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.toList(),
        List::size
    ));
```

Input → Output

`List<Employee>` → `Integer`

Use case: collection banane ke baad uska size chahiye. Sirf count chahiye to `Collectors.counting()` simpler hai.

### 2. `Set::size` — Unique elements count

```
Integer count = employees.stream()
    .map(Employee::getDepartment)
    .collect(Collectors.collectingAndThen(
        Collectors.toSet(),
        Set::size
    ));
```

`Set<String>` → `Integer`

Use case: unique departments kitne hain.

### 3. `Optional::get` — Optional se value nikalna

```
Employee highestPaid = employees.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.maxBy(
            Comparator.comparing(Employee::getSalary)
        ),
        Optional::get
    ));
```

`Optional<Employee>` → `Employee`

Warning: Stream empty hui to `Optional::get` exception dega. Safe version:

```
optional -> optional.orElse(null)
```

Ya requirement ke according `orElseThrow()` use karo.

### 4. `String::toUpperCase` — String transform karna

```
String names = employees.stream()
    .map(Employee::getName)
    .collect(Collectors.collectingAndThen(
        Collectors.joining(", "),
        String::toUpperCase
    ));
```

`String` → `String`

Use case: pehle names join karna, phir final string uppercase karna.

### 5. `Collections::unmodifiableList` — List ko unmodifiable banana

```
List<Employee> result = employees.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.toList(),
        Collections::unmodifiableList
    ));
```

`List<Employee>` → `List<Employee>` (unmodifiable view)

Use case: result mein `add()` / `remove()` jaise modifications prevent karna. Dhyan rahe, ye underlying list ki view hai; ye deep immutability guarantee nahi karta.

## 2. Aur kaun-kaun se finishers use kar sakte ho?

| Finisher                                  | Input → Output            | Use case                           |
| ----------------------------------------- | ------------------------- | ---------------------------------- |
| `List::size`                              | `List<T>` → `Integer`     | List ka count                      |
| `Set::size`                               | `Set<T>` → `Integer`      | Unique count                       |
| `Optional::get`                           | `Optional<T>` → `T`       | Optional unwrap; empty case unsafe |
| `String::toUpperCase`                     | `String` → `String`       | Uppercase                          |
| `String::toLowerCase`                     | `String` → `String`       | Lowercase                          |
| `Collections::unmodifiableList`           | `List<T>` → `List<T>`     | Unmodifiable view                  |
| `Collections::unmodifiableSet`            | `Set<T>` → `Set<T>`       | Unmodifiable view                  |
| `DoubleSummaryStatistics::getMax`         | Statistics → `double`     | Maximum value                      |
| `DoubleSummaryStatistics::getAverage`     | Statistics → `double`     | Average value                      |
| `DoubleSummaryStatistics::getSum`         | Statistics → `double`     | Total value                        |
| `list -> list.stream().findFirst()`       | `List<T>` → `Optional<T>` | First element                      |
| `list -> list.stream().map(...).toList()` | `List<T>` → `List<R>`     | Final transformation, Java 16+     |

Ye examples hain, exhaustive list nahi. Finisher ka return type collector ke intermediate result se different bhi ho sakta hai.

## 3. Employee programs mein sabse useful combinations

### A. Department-wise highest-paid employee

```
Map<String, Employee> result = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.collectingAndThen(
            Collectors.maxBy(
                Comparator.comparing(Employee::getSalary)
            ),
            optional -> optional.orElse(null)
        )
    ));
```

Flow:

```
groupingBy(department)
       ↓
maxBy(salary)
       ↓
Optional<Employee>
       ↓
orElse(null)
       ↓
Employee
```

### B. Department-wise unique cities count

```
Map<String, Integer> result = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.collectingAndThen(
            Collectors.mapping(
                Employee::getCity,
                Collectors.toSet()
            ),
            Set::size
        )
    ));
```

Flow:

```
Employee
   ↓
mapping(getCity)
   ↓
Set<String>
   ↓
Set::size
   ↓
Integer
```

### C. Department-wise maximum salary value

```
Map<String, Double> result = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.collectingAndThen(
            Collectors.summarizingDouble(Employee::getSalary),
            DoubleSummaryStatistics::getMax
        )
    ));
```

Yahan `summarizingDouble()` pehle statistics banata hai, aur finisher sirf maximum salary nikalta hai.

Lekin agar sirf maximum salary chahiye, simpler collector bhi use kar sakte ho.

## 4. Apna custom finisher bhi bana sakte ho

Suppose salary ka total collect karne ke baad usko rounded integer banana hai:

```
Integer totalSalary = employees.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.summingDouble(Employee::getSalary),
        total -> (int) Math.round(total)
    ));
```

Flow:

```
summingDouble()
      ↓
Double
      ↓
custom lambda
      ↓
Integer
```

Yahan lambda hi custom finisher hai.

## 5. Sabse important rule

```
collectingAndThen(
    collector,
    finisher
)
```

Finisher ka input hamesha collector ke result type se match hona chahiye.

Examples:

| Collector                | Intermediate result       | Valid finisher example              |
| ------------------------ | ------------------------- | ----------------------------------- |
| `toList()`               | `List<T>`                 | `List::size`                        |
| `toSet()`                | `Set<T>`                  | `Set::size`                         |
| `maxBy(...)`             | `Optional<T>`             | `optional -> optional.orElse(null)` |
| `joining()`              | `String`                  | `String::toUpperCase`               |
| `summarizingDouble(...)` | `DoubleSummaryStatistics` | `DoubleSummaryStatistics::getMax`   |
| `counting()`             | `Long`                    | `count -> "Count: " + count`        |

Interview ke liye priority: `List::size`, `Set::size`, safe `Optional` handling, `Collections.unmodifiableList`, aur `DoubleSummaryStatistics::getMax` pehle master karo. Ye tumhe `groupingBy()` ke andar `collectingAndThen()` wale kaafi programs solve karne mein help karenge.

# 🚀 PART 9 — `collectingAndThen()` Deep Dive

Part 9 bahut important hai, especially **interview programs** ke liye.

Ab tak tumne ye samjha:

```text
groupingBy()
    ↓
downstream collector
```

Ab `collectingAndThen()` se hum bol sakte hain:

> **"Pehle collection complete karo, phir jo final result aaya hai usko ek aur operation se transform karo."**

---

# 1. `collectingAndThen()` kya karta hai?

Syntax:

```java
Collectors.collectingAndThen(
    collector,
    finisher
)
```

Isko simple language me:

```text
COLLECT
   ↓
RESULT
   ↓
FINISH / TRANSFORM
   ↓
FINAL RESULT
```

Example:

```java
Collectors.collectingAndThen(
    Collectors.toList(),
    list -> list.size()
)
```

Meaning:

```text
Stream
 ↓
toList()
 ↓
List
 ↓
list.size()
 ↓
Integer
```

---

# 2. Input kya hai?

`collectingAndThen()` ke 2 inputs hote hain:

### Input 1 — Collector

```java
Collectors.toList()
```

### Input 2 — Finisher function

```java
list -> list.size()
```

Complete:

```java
Collectors.collectingAndThen(
    Collectors.toList(),
    list -> list.size()
)
```

---

# 3. Output kya hai?

Output **finisher ke return type** par depend karta hai.

Example:

```java
Collectors.collectingAndThen(
    Collectors.toList(),
    list -> list.size()
)
```

Output:

```java
Integer
```

Another:

```java
Collectors.collectingAndThen(
    Collectors.toList(),
    list -> list.stream().findFirst()
)
```

Output:

```java
Optional<T>
```

So important:

> `collectingAndThen()` ka output fixed nahi hota.

# 7. `Optional::get` ka danger ⚠️

Ye code:

```java
Optional::get
```

tabhi safe hai jab tum sure ho ki Optional empty nahi hoga.

Otherwise:

```text
NoSuchElementException
```

aa sakta hai.

Safer:

```java
optional -> optional.orElse(null)
```

Example:

```java
Map<String, Employee> result =
        employees.stream()
                 .collect(
                     Collectors.groupingBy(
                         Employee::getDepartment,
                         Collectors.collectingAndThen(
                             Collectors.maxBy(
                                 Comparator.comparing(
                                     Employee::getSalary
                                 )
                             ),
                             optional -> optional.orElse(null)
                         )
                     )
                 );
```

# 15. `groupingBy()` + `collectingAndThen()` 🔥

Ye sabse important pattern hai.

Generic:

```java
groupingBy(
    KEY,
    collectingAndThen(
        COLLECTOR,
        FINISHER
    )
)
```

Example:

```java
Map<String, Integer> result =
        employees.stream()
                 .collect(
                     Collectors.groupingBy(
                         Employee::getDepartment,
                         Collectors.collectingAndThen(
                             Collectors.toList(),
                             list -> list.size()
                         )
                     )
                 );
```

Output:

```text
IT → 5
HR → 3
Sales → 4
```

Ye actually department-wise employee count hai.

Lekin iske liye:

```java
groupingBy(
    Employee::getDepartment,
    counting()
)
```

much simpler hai.

### Interview lesson:

> `collectingAndThen()` powerful hai, but use only when a finishing transformation is actually required.


```java
collectingAndThen(
    counting(),
    count -> "Count = " + count
)
```

```text
Long
 ↓
String
```

# 26. `collectingAndThen()` vs `map()`

Important conceptual difference.

### Stream `map()`

Transformation **during stream processing**:

```java
employees.stream()
         .map(Employee::getName)
```

```text
Employee → String
```

### `collectingAndThen()`

Transformation **after collection**:

```java
employees.stream()
         .collect(
             collectingAndThen(
                 toList(),
                 List::size
             )
         );
```

```text
Stream
 ↓
collect
 ↓
List
 ↓
finish/transform
```

### Memory trick:

> `map()` = stream ke andar transformation
> `collectingAndThen()` = collection ke baad final transformation

# 27. `collectingAndThen()` vs `mapping()`

Ye bhi important hai.

### `mapping()`

```java
mapping(
    Employee::getName,
    toList()
)
```

Means:

```text
Employee
 ↓
Name
 ↓
List<String>
```

### `collectingAndThen()`

```java
collectingAndThen(
    toList(),
    List::size
)
```

Means:

```text
List<Employee>
 ↓
Integer
```

# 28. Common mistake ❌

Ye mat samajhna:

```java
collectingAndThen(
    toList(),
    Employee::getName
)
```

Wrong because finisher ko:

```text
List<Employee>
```

milega, single `Employee` nahi.

Finisher ka input **previous collector ka output** hota hai.

For:

```java
toList()
```

output:

```text
List<Employee>
```

So finisher ko:

```java
List<Employee>
```

handle karna chahiye.

Correct:

```java
list -> list.size()
```

or:

```java
list -> list.stream()
            .map(Employee::getName)
            .toList()
```

(Java version ke according collection method choose karna.)

---

# 29. Another common mistake ❌

`collectingAndThen()` ko unnecessarily use karna.

Question:

> Department-wise employee count.

Don't write:

```java
groupingBy(
    Employee::getDepartment,
    collectingAndThen(
        toList(),
        List::size
    )
)
```

Better:

```java
groupingBy(
    Employee::getDepartment,
    counting()
)
```

Why?

Because:

```text
counting()
```

directly count karta hai.

### Rule:

> Agar existing collector directly answer de raha hai, `collectingAndThen()` mat lagao.

---

# 30. When SHOULD you use it?

Use it when:

### 1. Existing collector ka result transform karna ho

```text
List → Integer
Set → Integer
Statistics → value
```

### 2. `Optional` unwrap karna ho

```text
Optional<Employee> → Employee
```

### 3. Result ko immutable/unmodifiable banana ho

```text
List → unmodifiable List
```

### 4. Final custom formatting/processing chahiye

```text
Long → String
Double → formatted value
```

# 33. Interview Question

### Q: `collectingAndThen()` ka return type kya hai?

Fixed return type nahi hai.

# 34. Interview Question

### Q: `maxBy()` ke saath `collectingAndThen()` kyun use karte hain?

Because:

```java
maxBy(...)
```

returns:

```java
Optional<Employee>
```

Agar business requirement ke according direct:

```java
Employee
```

chahiye, then finisher se Optional unwrap kar sakte hain.

```java
collectingAndThen(
    maxBy(comparator),
    Optional::get
)
```

# 36. ⭐ Part 9 Decision Tree

Question dekho:

```text
Mujhe normal collection chahiye?
        ↓
      toList()
      toSet()

Mujhe collection banane ke baad
kuch aur operation karna hai?
        ↓
collectingAndThen()

Mujhe maxBy/minBy ke Optional ko
unwrap karna hai?
        ↓
collectingAndThen()

Mujhe list ka size chahiye?
        ↓
collectingAndThen(toList(), List::size)

Mujhe set ka size chahiye?
        ↓
collectingAndThen(toSet(), Set::size)

Mujhe immutable/unmodifiable result chahiye?
        ↓
collectingAndThen(...)

Existing collector directly answer de raha hai?
        ↓

```
