# 📘 HELM Interview Questions & Answers

# Section 1 : Basics

---

## Q1. What is Helm?

### Answer

Helm Kubernetes ka **Package Manager** hai.

Jaise Ubuntu me **APT** use hota hai software install karne ke liye, waise Kubernetes me **Helm** use hota hai applications install, upgrade, rollback aur uninstall karne ke liye.

Example:

* Prometheus
* Grafana
* Nginx
* ArgoCD

Ye sab easily Helm se install ho jate hain.

---

## Q2. Why do we need Helm?

### Answer

Without Helm hume bahut saari YAML files manually manage karni padti hain.

Example

* Deployment
* Service
* ConfigMap
* Secret
* PVC
* Ingress

Helm in sab ko ek package (Chart) me convert kar deta hai.

Sirf ek command se application install ho jati hai.

---

## Q3. What is the biggest advantage of Helm?

### Answer

Helm

* YAML management easy karta hai
* Reusability deta hai
* Version management deta hai
* Rollback support karta hai
* Environment wise configuration allow karta hai

---

## Q4. kubectl aur Helm me difference?

### Answer

kubectl individual Kubernetes resources ko manage karta hai.

Helm complete application ko manage karta hai.

Example

kubectl

```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f configmap.yaml
```

Helm

```bash
helm install payment payment-chart
```

Ek command me sab deploy.

---

## Q5. Can we deploy application without Helm?

### Answer

Haan.

kubectl apply use karke deploy kar sakte hain.

Lekin large projects me YAML files bahut zyada hoti hain.

Maintenance difficult ho jata hai.

Isliye companies Helm use karti hain.

---

# Section 2 : Repository, Chart & Release

---

## Q6. What is Repository?

### Answer

Repository ek storage hai jaha Helm Charts store hote hain.

Example

Bitnami Repository

Usme

* Redis
* Kafka
* Prometheus
* MySQL

ke Charts available hote hain.

---

## Q7. What is Chart?

### Answer

Chart ek package hai.

Isme application deploy karne ke liye required saari YAML files hoti hain.

Example

* Deployment
* Service
* ConfigMap
* Secret
* Ingress

---

## Q8. What is Release?

### Answer

Release matlab deployed instance of Chart.

Example

Command

```bash
helm install my-nginx bitnami/nginx
```

Repository

↓

Bitnami

Chart

↓

Nginx

Release

↓

my-nginx

---

## Q9. Can one Chart have multiple Releases?

### Answer

Yes.

Example

```bash
helm install dev-nginx bitnami/nginx

helm install qa-nginx bitnami/nginx

helm install prod-nginx bitnami/nginx
```

Same Chart

Different Releases.

---

## Q10. Difference between Repository, Chart and Release?

### Answer

Repository

↓

Charts store karta hai.

Chart

↓

Application package hota hai.

Release

↓

Installed application hoti hai.

# Section 3 : Helm Architecture

---

## Q11. Helm v2 aur Helm v3 me difference?

### Answer

Helm v2

Tiller use karta tha.

Helm v3

Tiller remove kar diya gaya.

Ab Helm directly Kubernetes API se baat karta hai.

---

## Q12. Why was Tiller removed?

### Answer

Security issues.

Maintenance issue.

Har cluster me install karna padta tha.

Isliye Helm v3 me remove kar diya.

---

## Q13. Helm Kubernetes se connect kaise karta hai?

### Answer

Helm same kubeconfig use karta hai jo kubectl use karta hai.

Current Context ke basis pe cluster select karta hai.

---

## Q14. kubeconfig kya hota hai?

### Answer

Ye configuration file hoti hai.

Isme

* Cluster
* User
* Authentication
* Context

store hota hai.

---

## Q15. Current Context kya hota hai?

### Answer

Current Context batata hai

Helm ya kubectl kis Kubernetes Cluster se connected hai.
