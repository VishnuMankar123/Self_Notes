---

### 🧠 What it means

**Client-Server Architecture** is a model where two parts work together:

* **Client** → asks for something
* **Server** → gives the answer

---

### 🖥️ Real-life example

Think of it like a **restaurant** 🍽️

| Role             | In Real Life             | In Computing                           |
| ---------------- | ------------------------ | -------------------------------------- |
| Customer         | You place an order       | **Client** (e.g., your browser or app) |
| Waiter + Kitchen | Prepares and serves food | **Server** (handles and sends data)    |

---

### ⚙️ How it works (steps)

1. **Client sends a request** → “I want this data/page.”
2. **Server receives it** → Checks what’s needed.
3. **Server processes** → Runs code, queries database.
4. **Server sends a response** → Sends result back.
5. **Client displays** → Shows result to the user.

---

### 💡 Example

You open a website like `www.google.com`

1. Your browser (client) → sends request to Google’s server.
2. Google’s server → processes and sends search page back.
3. Browser → shows it on your screen.

---

### 🔗 Common examples

* **Web apps**: Browser (client) ↔ Web server
* **Mobile apps**: App (client) ↔ API server
* **Games**: Player app (client) ↔ Game server

---

### 🧩 Types

1. **Two-tier architecture** → Client ↔ Server
2. **Three-tier architecture** → Client ↔ Application Server ↔ Database Server

---

### ✅ Advantages

* Centralized data & control
* Easy to maintain & secure
* Multiple clients can connect

### ❌ Disadvantages

* If the server fails, everyone is affected
* Network dependency

# One-Tier (Single-Tier) Architecture

**Kya hai:**
Sab kuch ek hi system/instance mein hota hai — presentation, business logic, aur data sab ek jagah pe.

**Kaise work karta hai:**

* Application aur data dono ek hi machine ya process mein run karte hain.
* No network communication between layers because layers aren’t separated.

**Example:**

* A simple desktop app (e.g., a standalone calculator, a single-user MS Access file with forms and tables).
* A local-only utility where user interface and data store are in the same program.

**Diagram (simple):**

```
[Client + App + Database]  —> (Single machine/process)
```

**Pros:**

* Very simple to build and deploy
* Low latency (no network calls)
* Good for single-user or prototype apps

**Cons:**

* Not scalable — can’t handle many users
* Hard to maintain as app grows
* Less secure and less modular

## 🧩 **Types of Client–Server Architecture**

### 🥇 1. **Two-Tier Architecture**

➡️ **Client ↔ Server**

**How it works:**

* Client directly talks to the server.
* Server handles both **business logic** and **database**.

**Example:**
A desktop app (like an old banking software) directly connecting to the database server.

**Diagram:**

```
Client  ⇄  Server (App + Database)
```

**Pros:** Simple, fast for small systems
**Cons:** Not scalable, difficult to maintain for large apps

---

### 🥈 2. **Three-Tier Architecture**

➡️ **Client ↔ Application Server ↔ Database Server**

**How it works:**

* Client sends request to **Application Server**
* Application Server processes logic, fetches data from **Database Server**
* Sends result back to client

**Example:**
Modern web applications —
Browser → (Client)
Spring Boot or Node.js → (App Server)
MySQL / Oracle → (DB Server)

**Diagram:**

```
Client ⇄ Application Server ⇄ Database Server
```

**Pros:**
✅ Scalable
✅ Secure (database not directly exposed)
✅ Easy to maintain

**Cons:**
⚠️ Slightly complex setup

---

### 🥉 3. **N-Tier Architecture (Multi-Tier)**

➡️ **Client ↔ Web Server ↔ App Server ↔ DB Server ↔ Other Services**

**How it works:**

* Used in **large enterprise systems**.
* Multiple layers handle different responsibilities (like API layer, business logic, database, caching, etc.).

**Example:**
E-commerce site like Amazon —
Client → Web Server → App Server → Database + Payment + Logging

**Diagram:**

```
Client ⇄ Web Server ⇄ App Server ⇄ Database ⇄ Other Services
```

**Pros:**
✅ Very scalable
✅ Secure & modular
✅ Easy to add or change parts

**Cons:**
⚠️ High cost and complexity

## 🧠 **Loopback Address (127.0.0.1)** — Simple Explanation

### 🔹 Definition:

**Loopback address** ek **special IP address** hota hai jo **apne hi computer ko refer karta hai**.
Matlab:

> Jab aap apne computer se apne computer ko hi request bhejte ho.

---

### 🔹 Default Loopback Address:

```
127.0.0.1
```

and hostname:

```
localhost
```

Dono ka meaning same hai.

---

### 💡 Example:

Agar aap browser me likho:

```
http://127.0.0.1:8080
```

ya

```
http://localhost:8080
```

👉 Toh aapka browser **aapke hi system par chal rahe server** (like Tomcat, Spring Boot, etc.) se connect karega.

---

### 🔹 Use:

1. **Testing purpose** –
   Local web servers (Tomcat, XAMPP, Node.js) ko test karne ke liye.

2. **Network configuration check** –
   Ping command se check karte hain ki TCP/IP stack sahi chal raha hai ya nahi.

   ```
   ping 127.0.0.1
   ```

   Agar reply aata hai → network stack working fine.

3. **Local communication** –
   Apps ek hi computer ke andar data exchange karne ke liye loopback ka use karti hain.

---

### 🔹 Important Points:

* Yeh packets **kabhi network par nahi jaate** — sirf system ke andar circulate hote hain.
* Range: `127.0.0.0 – 127.255.255.255` (sab loopback ke liye reserve hai).
* Commonly used: `127.0.0.1`

---

Jaise tum khud se baat karte ho ("main khudse practice kar raha hoon") —
waise hi **loopback** me computer apne aap se baat karta hai 🖥️➡️🖥️

## 🔹 **Concept 1 – DNS क्या करता है**

**Teacher:**
DNS का काम है → “Domain Name” को “IP Address” में बदलना।

**Example:**

```
www.google.com  ➜  142.250.190.78
```

इंसानों को नाम याद रखना आसान है, लेकिन कंप्यूटर सिर्फ IP address समझते हैं।
DNS दोनों के बीच translator का काम करता है।

---

## 🔹 **Concept 2 – जब आप Browser में कोई Website खोलते हैं तो क्या होता है**

**Teacher:**
चलो step by step समझते हैं कि जब आप browser में `www.google.com` लिखते हैं तो background में क्या-क्या होता है 👇

---

### 🟩 Step 1: Browser Cache Check

* Browser सबसे पहले अपने **local cache** में चेक करता है कि क्या उस domain का IP पहले से मौजूद है।
* अगर मिला → वही IP use कर लेता है।
* अगर नहीं मिला → अगला step।

---

### 🟨 Step 2: OS Cache Check

* Browser फिर **Operating System (DNS Cache Table)** में check करता है।
* अगर नहीं मिला → आगे बढ़ता है।

---

### 🟦 Step 3: Router/Local DNS Check

* अब request जाती है आपके **Router** या **Local DNS Server** तक।
* अगर वहाँ भी नहीं मिला → request भेजी जाती है आपके ISP के DNS Resolver को।

---

### 🟧 Step 4: Recursive DNS Resolver (ISP DNS)

* यह आपका **Internet Service Provider (Jio, Airtel आदि)** का DNS होता है।
* इसे कहते हैं **Recursive Resolver**, क्योंकि यह बाकी servers से recursively जवाब ढूंढता है।

---

### 🟥 Step 5: Root DNS Server

* अगर ISP के पास IP नहीं है, तो यह **Root DNS Server** से पूछता है।
* Root server actual IP नहीं बताता — वह बताता है कि उस domain का TLD server कौन-सा है।
* Root servers दुनिया में केवल **13 logical sets (A–M)** हैं।

---

### 🟪 Step 6: TLD (Top Level Domain) Server

* Root server `.com`, `.org`, `.in` जैसे extensions के लिए TLD server का path देता है।
* अब resolver उस **TLD server** से पूछता है कि यह domain कहाँ hosted है।

**Example:**
`.com` server कहेगा → “google.com का authoritative server है ns1.google.com।”

---

### 🟫 Step 7: Authoritative Name Server

* अब resolver उस authoritative server से पूछता है — “google.com का actual IP बताओ।”
* Authoritative server actual IP देता है जैसे `142.250.190.78`।
* यही final जवाब होता है।

---

### ⬛ Step 8: Response to Browser

* यह IP अब resolver → system → browser को वापस भेजी जाती है।
* Browser इस IP को cache कर लेता है (next time fast access के लिए)।
* फिर browser TCP/IP connection बनाता है और web page लोड हो जाता है ✅

---

## 🔹 **Concept 5 – DNS Load Balancer कैसे काम करता है**

**Teacher:**
जब किसी domain के पीछे कई servers होते हैं (high traffic sites),
तो DNS एक ही domain के लिए **multiple IP addresses** देता है।
इससे load अलग-अलग servers पर divide हो जाता है।

---

### ⚙️ Common DNS Load Balancing Algorithms

| Algorithm     | Description                                             |
| ------------- | ------------------------------------------------------- |
| Round Robin   | हर request को अलग server पर भेजता है (sequence में)     |
| Geo-based     | User के location के पास वाले server पर भेजता है         |
| Latency-based | जो server सबसे fast response दे रहा हो, उसी पर भेजता है |
| Weighted      | Priority के हिसाब से servers को traffic देता है         |

---

### 🧩 **Example: Round Robin Load Balancing**

| Client | DNS Response (IP) | Server Selected   |
| ------ | ----------------- | ----------------- |
| User A | 10.0.0.1          | Server 1          |
| User B | 10.0.0.2          | Server 2          |
| User C | 10.0.0.3          | Server 3          |
| User D | 10.0.0.1          | Server 1 (repeat) |

👉 इससे load बराबर बंट जाता है और कोई server overload नहीं होता।

## **1️⃣ TCP (Transmission Control Protocol)**

**Key Features:**

1. **Reliable delivery:**

   * TCP ensure karta hai ki **sab packets sahi order me aur loss ke bina** receiver tak pahunch jaaye.
   * Agar koi packet lost ho jaye, to TCP automatically **resend** karta hai.

2. **Connection-oriented:**

   * Sender aur receiver ke beech **connection establish** hota hai pehle (3-way handshake).
   * Jaise phone call start karte ho, dono ready hain baat karne ke liye.

3. **Error checking & flow control:**

   * Agar data me error ho → TCP detect karke **request karta hai resend**
   * Flow control se sender ka data receiver ko overwhelm nahi karta.

**Analogy:**

* TCP = **Registered Post / Courier Service**

  * Letter guaranteed deliver hoga, agar lost ho to resend hoga, aur sab letters order me pahunchenge.

**Use Cases:**

* Web browsing → **HTTP/HTTPS**
* Email → **SMTP, IMAP, POP3**
* File transfer → **FTP**

---

## **2️⃣ UDP (User Datagram Protocol)**

**Key Features:**

1. **Faster delivery:**

   * UDP **connection nahi banata**, simply packet bhej deta hai.
   * Error checking aur resend ka kaam nahi karta → speed fast.

2. **Connectionless:**

   * Sender aur receiver ke beech pehle se connection establish nahi hota.
   * Jaise aap ek postcard bhejte ho, direct receiver ko.

3. **Less reliable:**

   * Agar packet lost ho gaya → **koi automatic resend nahi**.
   * Order guarantee bhi nahi hai.

**Analogy:**

* UDP = **Postcard / WhatsApp message**

  * Jaldi bheja jaata hai, lekin agar lost ho gaya, firse bhejna **aapko khud karna padega**.

**Use Cases:**

* Video/Audio streaming → **YouTube, Netflix**
* Online gaming → **fast updates, minor packet loss acceptable**
* DNS queries → **fast request-response**

---

**Summary Table:**

| Feature        | TCP                 | UDP                    |
| -------------- | ------------------- | ---------------------- |
| Delivery       | Reliable            | Unreliable             |
| Connection     | Connection-oriented | Connectionless         |
| Speed          | Slower              | Faster                 |
| Error Handling | Yes, resend         | No                     |
| Use Case       | Web, Email, FTP     | Streaming, Gaming, DNS |

---

## **1️⃣ TCP (Transmission Control Protocol)**

* **Type:** Transport Layer Protocol
* **Function:**

  * Data ko **reliable aur ordered** delivery ensure karta hai.
  * Error checking aur retransmission ka kaam karta hai.
* **Connection:** Connection-oriented (pehle handshake hota hai)
* **Example Use:** HTTP, FTP, Email
* **Analogy:** Courier service – sab parcels order me aur safe deliver hote hain.

---

## **2️⃣ IP (Internet Protocol)**

* **Type:** Internet Layer Protocol
* **Function:**

  * Data packets ko **logical addressing (IP address)** aur **routing** provide karta hai.
  * Decide karta hai ki packet **kaunse path se destination tak jaayega**.
* **Connection:** Connectionless (bina handshake ke packet bhejta hai)
* **Example Use:** IP packet delivery across networks
* **Analogy:** Road network / GPS – packet ko destination tak pahunchata hai, lekin delivery ki guarantee nahi deta.

---

## **Key Differences (Simple Table)**

| Feature    | TCP                            | IP                             |
| ---------- | ------------------------------ | ------------------------------ |
| Layer      | Transport                      | Internet                       |
| Delivery   | Reliable, ordered              | Unreliable, no order guarantee |
| Connection | Connection-oriented            | Connectionless                 |
| Function   | Data delivery & error checking | Packet addressing & routing    |
| Analogy    | Courier service                | Road / GPS system              |

---

💡 **Important:**

* TCP aur IP aksar **TCP/IP** ke form me saath me use hote hain.
* IP packet ko **destination tak pahunchata hai**, TCP ensure karta hai ki **data sahi aur complete mile**.

### 💻 **3. Parts of a URL**

Parts breakdown:
1️⃣ **Protocol** → https
2️⃣ **Host name / Domain name** → [www.neraclasses](http://www.neraclasses)
3️⃣ **Top-level domain (TLD)** → .in
4️⃣ **Port number** → :443 (optional if using default port)
5️⃣ **Path** → /page1
6️⃣ **Query separator** → ?
7️⃣ **Query string** → course=network
8️⃣ **Fragment** → #section2

**👨‍🎓 Student Notes:**
🧾 URL = Protocol + Domain + TLD + Port + Path + Query + Fragment
⚙️ Default Ports:

* HTTP → 80
* HTTPS → 443

📌 Port number optional for default ports.

### 🔐 **4. Protocols – HTTP vs HTTPS**

**👨‍🏫 Teacher:**

* **HTTP (HyperText Transfer Protocol)**

  * Port 80
  * Plain text communication
  * Not encrypted → vulnerable to hackers
* **HTTPS (HTTP Secure)**

  * Port 443
  * Uses SSL/TLS encryption
  * Secure communication between client ↔ server

**👨‍🎓 Student Notes:**

| Protocol | Port | Security     | Encryption |
| -------- | ---- | ------------ | ---------- |
| HTTP     | 80   | ❌ Not secure | No         |
| HTTPS    | 443  | ✅ Secure     | SSL/TLS    |

🔒 HTTPS = Secure, encrypted communication between browser & website.

### 🌍 **5. Internet Protocol (IP)**

**👨‍🏫 Teacher:**

* IP = Method to send data from one computer to another over the Internet.
* Uses **IP address** to locate destination machine.
* Similar to home address or phone number concept.
* Data is converted into **binary (electronic signals)** before transmission.
* Used with communication models like TCP/IP.

**👨‍🎓 Student Notes:**
🧠 IP (Internet Protocol):

* Transfers data packets between devices.
* Needs receiver’s IP address.
* Converts data → binary → sends over network.

### 🧱 **6. TCP/IP Model – Layers**

**👨‍🏫 Teacher:**
TCP/IP model adopted in **1983** (ARPANET standard).
It has **4 layers**:
1️⃣ **Application Layer** – User interaction (HTTP, FTP, SMTP).
2️⃣ **Transport Layer** – Data delivery control (TCP, UDP).
3️⃣ **Internet Layer** – Logical addressing & routing (IP, ICMP).
4️⃣ **Network Access Layer** – Physical network (Ethernet, Wi-Fi).

Data Flow (Sender → Receiver):

* Sender: App → Transport → Internet → Network
* Receiver: Network → Internet → Transport → App

**👨‍🎓 Student Notes:**
📘 **TCP/IP Model Layers**

| Layer          | Function                     | Example Protocols |
| -------------- | ---------------------------- | ----------------- |
| Application    | User-level communication     | HTTP, SMTP, FTP   |
| Transport      | Reliable/unreliable delivery | TCP, UDP          |
| Internet       | Routing, addressing          | IP, ICMP          |
| Network Access | Physical transmission        | Ethernet, Wi-Fi   |

📡 Sender → (App→Trans→Net→Phys)
Receiver → (Phys→Net→Trans→App)

### 🔁 **7. TCP vs UDP**

**👨‍🏫 Teacher:**

* **TCP (Transmission Control Protocol)** – Reliable, connection-oriented.
* **UDP (User Datagram Protocol)** – Faster, connectionless, less reliable.

**👨‍🎓 Student Notes:**

| Feature     | TCP        | UDP               |
| ----------- | ---------- | ----------------- |
| Connection  | Oriented   | Connectionless    |
| Reliability | Reliable   | Unreliable        |
| Speed       | Slower     | Faster            |
| Use Case    | Web, Email | Streaming, Gaming |

## **1️⃣ Application Layer**

**Function:**

* Ye layer **user aur application programs** ke beech communication ka kaam karti hai.
* Ye data ko aise format me prepare karti hai jo **network par bhejne ke liye ready** ho.
* Directly **end-user interact** karte hain (browser, email client).

**Example Protocols & Use:**

| Protocol       | Purpose                                                                     |
| -------------- | --------------------------------------------------------------------------- |
| **HTTP/HTTPS** | Web browsing; HTTPS encrypted version of HTTP                               |
| **FTP**        | File transfer between client and server                                     |
| **SMTP**       | Sending emails                                                              |
| **POP3/IMAP**  | Receiving emails                                                            |
| **DNS**        | Domain name resolution (e.g., [www.google.com](http://www.google.com) → IP) |

**Analogy:** Ye layer **office receptionist** jaisi hai jo request samajhkar proper department ko forward karta hai.

---

## **2️⃣ Transport Layer**

**Function:**

* Ye layer **data ko segments me todta hai** aur reliable delivery ensure karta hai.
* **Error checking, flow control, congestion control** ka kaam bhi karta hai.
* Sender aur receiver ke beech **end-to-end communication** maintain karta hai.

**Example Protocols & Use:**

| Protocol                                | Features                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| **TCP (Transmission Control Protocol)** | Reliable, connection-oriented, ensures all packets arrive in order                |
| **UDP (User Datagram Protocol)**        | Unreliable, connectionless, faster, used for streaming, DNS queries, online games |

**Analogy:** Ye layer **post office** jaisi hai jo letters ko sahi address pe deliver karne ki responsibility leta hai, aur agar letter lost ho jaye to resend karta hai (TCP).

---

## **3️⃣ Internet Layer**

**Function:**

* Ye layer **logical addressing** aur **routing** ka kaam karti hai.
* Ye decide karti hai **data ka kaunsa path lena hai sender → receiver tak**.
* Packet ko **source IP se destination IP** tak bhejna iska kaam hai.

**Example Protocols & Use:**

| Protocol                                     | Features                                    |
| -------------------------------------------- | ------------------------------------------- |
| **IP (Internet Protocol)**                   | Addressing & routing; IPv4 or IPv6          |
| **ICMP (Internet Control Message Protocol)** | Error reporting, e.g., ping command         |
| **ARP (Address Resolution Protocol)**        | Maps IP addresses to physical MAC addresses |

**Analogy:** Ye layer **GPS navigator** jaisi hai jo decide karti hai kaunsa route follow karna hai destination tak pahunchne ke liye.

---

## **4️⃣ Network Access Layer** (Link Layer / Physical Layer)

**Function:**

* Ye layer **physical transmission** ka kaam karti hai: cables, switches, Wi-Fi signals.
* Data ko **frames** me convert karke **actual network hardware** se bhejti hai.

**Example Protocols & Use:**

| Protocol/Technology               | Purpose                             |
| --------------------------------- | ----------------------------------- |
| **Ethernet**                      | Wired LAN connection                |
| **Wi-Fi (IEEE 802.11)**           | Wireless LAN connection             |
| **PPP (Point-to-Point Protocol)** | Direct connection over serial links |
| **Frame Relay, ATM**              | WAN transmission protocols          |

**Analogy:** Ye layer **delivery truck / courier service** jaisi hai jo actual physical delivery karta hai.

---

## **📡 Data Flow Example**

**Sender:**
Application → Transport → Internet → Network Access → Physical Media → Receiver

**Receiver:**
Physical Media → Network Access → Internet → Transport → Application

**Example:**

* Aap browser me `www.google.com` type karte ho.

1. **Application Layer:** Browser request prepare karta hai → HTTP GET request
2. **Transport Layer:** TCP segment me divide karke error checking lagata hai
3. **Internet Layer:** Packet ko IP address ke through route karta hai
4. **Network Layer:** Ethernet/Wi-Fi se actual physical network par send karta hai

Receiver ke side me ye process reverse hota hai → finally aapko Google page milta hai.

## 🧠 OSI Model — Short Notes (From Nehra Classes Lecture)

### 📌 Full Form:

**OSI → Open System Interconnection Model**
→ Framework for communication between two devices over a network.

---

### 🏗️ Layers in OSI Model (Total 7)

+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| Layer No. | Layer Name          | Type                          | Main Function                                                                               |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 7         | Application Layer   | Software                      | User interface to access network (e.g., browsers like Chrome, Firefox). Uses HTTP, HTTPS,   |
|           |                     |                               | FTP, SMTP protocols.                                                                        |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 6         | Presentation Layer  | Software                      | Performs data translation, compression, and encryption/decryption. Converts human-readable  |
|           |                     |                               | data into binary form.                                                                      |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 5         | Session Layer       | Software                      | Manages sessions — create, maintain, and terminate communication. Adds checkpoints for      |
|           |                     |                               | error recovery.                                                                             |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 4         | Transport Layer     | Middle Layer (Heart of OSI)   | Ensures reliable data delivery using TCP (connection-oriented) or UDP (connectionless).     |
|           |                     |                               | Divides data into segments, handles flow control & error correction.                        |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 3         | Network Layer       | Hardware                      | Responsible for routing packets using IP addresses. Chooses the best path to send data.     |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 2         | Data Link Layer     | Hardware                      | Manages error detection and correction during physical transmission. Uses MAC addresses.    |
|           |                     |                               | Divides data into frames.                                                                   |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+
| 1         | Physical Layer      | Hardware                      | Transfers raw bits over the physical medium (cables, signals, voltages). Deals with actual  |
|           |                     |                               | hardware.                                                                                   |
+-----------+---------------------+-------------------------------+---------------------------------------------------------------------------------------------+


### ⚙️ Classification of Layers:

* **Software Layers:** Application (7), Presentation (6), Session (5)
* **Hardware Layers:** Network (3), Data Link (2), Physical (1)
* **Bridge Layer:** Transport (4)

---

### 🕓 History:

* Introduced: **1983**
* Adopted by **ISO (International Standards Organization)** in **1984**

---

### 📍 Key Points:

* OSI model is **advanced and detailed** compared to TCP/IP model.
* Helps standardize data communication globally.
* Provides **uniformity** and **error-free data transfer**.
* **Transport Layer** is called the **heart** of OSI model.
* Works from **Application → Physical** (Sender side) and reverse on **Receiver side**.

➡️ Local file storage

➡️ Company website (small-scale)

**Server Room Features:**

* छोटा area (जैसे एक कमरा)
* Limited servers & cooling
* Single organization के लिए
* Maintenance manually होती है

## 🏗️ **Cloud Computing कैसे काम करता है**

### 🔹 Step-by-Step Process:

1. **User Request करता है**

   * तुम किसी cloud service provider (जैसे AWS, Azure, Google Cloud) को request भेजते हो।
2. **Service Provider allocate करता है resources**

   * Cloud में virtual servers (VMs), storage, database allocate हो जाते हैं।
3. **Internet के ज़रिए access करते हो**

   * तुम किसी भी device से (mobile, laptop, browser) access कर सकते हो।
4. **Pay-as-you-go model**

   * जितना use किया, उतना pay किया — no maintenance, no hardware tension।

### **Cloud Service Models - Q&A Notes**

**Teacher:** Cloud computing me cloud service models kya hote hain?
**Student:** Cloud service models basically teen categories me hote hain:

1. **IaaS (Infrastructure as a Service)**
2. **PaaS (Platform as a Service)**
3. **SaaS (Software as a Service)**

---

**Teacher:** IaaS kya hota hai?
**Student:** IaaS me cloud provider aapko **hardware resources** provide karta hai jaise ki:

* CPU
* RAM
* Storage
* Networking devices
* Virtualization tools

Aap in resources ko use karke **apni virtual machine (VM)** deploy kar sakte ho. Yahan **operating system aur applications ko manage karna aapki responsibility hoti hai**.

**Example:** AWS me **EC2 (Elastic Compute Cloud)** service IaaS ka example hai.

---

**Teacher:** PaaS kya hota hai? IaaS se difference kya hai?
**Student:** PaaS me aapko **hardware + operating system** dono provide kiye jaate hain cloud provider se.

* Infrastructure to cloud provider ka hai
* Operating system bhi cloud provider ka hai
* Aapko sirf apni **applications aur data** manage karna hota hai

**Difference:** IaaS me aap apna khud ka OS choose karke manage kar sakte ho, PaaS me OS cloud provider ka hi hota hai aur aapko manage karne ki zarurat nahi.

**Example:** AWS me **Elastic Beanstalk** PaaS ka example hai, jahan aap apni application deploy kar sakte ho without worrying about OS.

---

**Teacher:** SaaS kya hota hai?
**Student:** SaaS me **hardware, OS, platform, applications sab cloud provider manage karta hai**.

* Aapko sirf application use karna hota hai
* Aapko kuch bhi manage nahi karna

**Examples:**

* CRM software
* ERP systems
* Email marketing software
* Accounting software

---

**Teacher:** On-premises infrastructure kya hota hai?
**Student:** On-premises me:

* Hardware, OS, middleware, data, applications sab **aapki company manage karti hai**
* Aapko apne server, storage, network sab khud setup aur maintain karna padta hai
* Cost aur operational efforts zyada hote hain

**Example:** Agar aap business ke liye ek ERP application run karna chahte ho, to aapko apna **data center setup** karna padega.

**Teacher:** On-premises vs cloud?
**Student:** Cloud adopt karne ka main reason hai:

* **Cost saving** (pay-as-you-go model)
* **No team required for managing infrastructure**
* **Flexibility**

**Example:** Car analogy:

* On-premises = Apni car kharidna, petrol, maintenance, driver sab aap manage karte ho
* Cloud = Taxi hire karna, sirf distance ka paisa dena, sab responsibility taxi company ki

---

**Teacher:** Shared responsibility model kya hai?
**Student:**

* Cloud me kuch resources **cloud provider manage karta hai**, kuch **customer manage karta hai**
* IaaS: Provider = networking, storage, servers, virtualization
  Customer = OS, middleware, applications, data
* PaaS: Provider = hardware + OS + runtime
  Customer = applications + data
* SaaS: Provider = sab manage karega
  Customer = sirf use karega

---

**Teacher:** AWS me IaaS ka example kya hai?
**Student:** **EC2 (Elastic Compute Cloud)**

* Virtual machines ko **instances** kehte hain
* AWS Management Console se instances launch aur manage kar sakte ho
* OS aur application aap manage karte ho

**Teacher:** PaaS ka AWS example?
**Student:** **Elastic Beanstalk**

* Application deploy karna easy
* OS aur platform ko cloud provider manage karta hai

**Teacher:** SaaS ka AWS example?
**Student:** ERP systems, CRM software jo AWS provide karta hai, jise aap **directly use kar sakte ho**

---

**Teacher:** Cloud ke advantages kya hain?
**Student:**

* **Cost-effective**
* **Flexible aur scalable**
* **No need for separate teams**
* **Quick deployment**

**Teacher:** Cloud ke layers ka virtualization diagram samjhao?
**Student:**

1. Hardware → Cloud provider manage karta hai
2. Firmware/Hypervisor → Virtual hardware create karta hai
3. Virtual machines → Customer deploy karta hai apna OS + apps
4. Applications aur data → Customer manage karta hai (IaaS/PaaS)
5. SaaS me sab provider manage karega

---

**Teacher:** AWS console me kaun kaun si services important hain?
**Student:**

* **EC2** → Virtual machines
* **S3** → Storage
* **VPC** → Networking
* **Elastic Beanstalk** → Platform for apps
* Aur bhi bahut saari services, jo practical me use hoti hain

### **AWS EC2 & Cloud Scaling Q&A Notes**

**Teacher:** Namaste! Aaj hum baat karenge **Elasticity** aur **Scalability** ke baare me. Pehle batao, Elasticity kya hoti hai?
**Student:** Elasticity ka matlab hai system ya infrastructure ki **ability** ki woh apne resources ko **auto-adjust kar sake demand ke hisaab se**. Jaise traffic badhe, toh resources automatically increase ho jayein aur traffic kam ho toh decrease ho jaye.

**Teacher:** AWS me Elasticity ka use kaise hota hai?
**Student:** AWS me Elasticity ka matlab hai ki **servers ka number demand ke hisaab se increase ya decrease hota hai**, **server capacity ko nahi badhate**. Yeh mostly **short-term** ke liye hota hai.

**Teacher:** Example do Elasticity ka.
**Student:** Maan lo humari application pe initially **1 server** hai, traffic bahut kam hai. Ab holiday me traffic increase ho jaye, toh **AWS automatically ek ya do aur servers add kar dega** (scale-out) aur traffic kam hone pe servers remove kar dega (scale-in).

**Teacher:** Scale-out aur scale-in kya hota hai?
**Student:**

* **Scale-out:** Jab workload ya traffic badhta hai, toh **additional servers add karna** → zyada users ko handle kar sake.
* **Scale-in:** Jab workload ya traffic kam hota hai, toh **servers ko remove karna** → unnecessary cost save hoti hai.
* Ye dono **auto-scaling** ke through hote hain aur **shutdown/reboot ki zarurat nahi hoti**.

**Teacher:** Auto-scaling kya hai?
**Student:** Auto-scaling ek AWS feature hai jo:

1. **Monitor karta hai traffic aur resources usage**
2. **Decides karta hai kitne servers chahiye**
3. **Automatically add ya remove karta hai servers**
   Isse humari app ki **performance stable** rehti hai aur **cost bhi low** rehti hai.

**Teacher:** Ab batao **Scalability** kya hoti hai?
**Student:** Scalability ka matlab hai **system resources ko increase ya decrease karna** jaise **CPU, RAM, Storage** ko scale up ya down karna.

* Yeh **long-term solution** hota hai
* Example: Database server pe 32GB RAM aur 12 vCPU hai, traffic badh gaya → hum **server ki RAM 64GB aur CPU 16 kar dete** hain.

**Teacher:** Elasticity aur Scalability me difference kya hai?
**Student:**

| Feature     | Elasticity                            | Scalability                                    |
| ----------- | ------------------------------------- | ---------------------------------------------- |
| Purpose     | Short-term demand adjust              | Long-term performance adjust                   |
| Adjust      | Number of servers                     | Server capacity (CPU/RAM/Storage)              |
| Example     | Extra server add during traffic spike | Database server RAM increase for growing users |
| AWS Feature | Auto-scaling                          | Vertical scaling                               |

**Teacher:** Horizontal aur Vertical Scaling me kya difference hai?
**Student:**

* **Horizontal Scaling (Scale-out/In):** **Number of servers change** hota hai, same capacity ke servers add/remove hote hain.

  * Example: 1 server → 3 servers during traffic spike
* **Vertical Scaling (Scale-up/Down):** **Server ki capacity change** hoti hai, CPU/RAM/Storage badhaya ya kam kiya jata hai.

  * Example: 32GB RAM → 64GB RAM

**Teacher:** Elasticity me Horizontal ya Vertical scaling hoti hai?
**Student:** Elasticity me **horizontal scaling** hoti hai, kyunki **number of servers auto-adjust hota hai**.

**Teacher:** Scalability me Horizontal ya Vertical scaling hoti hai?
**Student:** Scalability me **vertical scaling** hoti hai, kyunki **server capacity increase ya decrease hoti hai**.

**Teacher:** Ek simple scenario do Elasticity ka.
**Student:**

* Maan lo website pe initially **2 servers** hai
* Holiday ke din traffic badh gaya → Auto-scaling se **2 extra servers add**
* Traffic kam hua → **Extra 2 servers remove**
* User ko service interruption nahi hua

**Teacher:** Ek simple scenario do Scalability ka.
**Student:**

* Database server pe 32GB RAM hai, queries slow ho rahi hain
* Server ko **power-off karke RAM 64GB aur CPU 16** kar diya
* Server restart → application fast ho gayi
* Yaha **server count same raha, capacity badhi**

**Teacher:** Key terms yaad rakhne layak kya hain?
**Student:**

* **Elasticity** = Auto-adjust number of servers (short-term)
* **Scalability** = Increase/decrease server capacity (long-term)
* **Auto-scaling** = Elasticity achieve karne ka AWS feature
* **Scale-out** = Add servers
* **Scale-in** = Remove servers
* **Vertical Scaling** = Increase server capacity (CPU/RAM/Storage)
* **Horizontal Scaling** = Add/remove servers

---

✅ **Summary Tip:**

* Elasticity → Short-term → Horizontal → Number of servers
* Scalability → Long-term → Vertical → Server capacity
* Auto-scaling → AWS ka magic tool jo elasticity provide karta hai

## 👨‍🏫 **Teacher Explanation: Regions in Cloud Computing**

### 🔹 What is a Region?

* Cloud providers (AWS, Azure, GCP) duniya ke alag–alag areas me **data centers ke groups** banate hain.
* Har group ko **Region** kaha jata hai.
* Ek Region me kai **Availability Zones (AZs)** hote hain.

---

### 🔹 Distance Between Regions

* Regions **alag–alag cities ya countries** me hote hain.
* Distance region ke location pe depend karta hai, lekin average:

  * **Minimum:** ~500 km (same country ke regions)
  * **Maximum:** 10,000+ km (different continents ke regions)

| Example          | Region 1            | Region 2                    | Distance (Approx.) |
| ---------------- | ------------------- | --------------------------- | ------------------ |
| AWS ap-south-1   | Mumbai              | ap-southeast-1 (Singapore)  | ~3,900 km          |
| AWS us-east-1    | Virginia (USA)      | us-west-1 (California, USA) | ~3,700 km          |
| AWS eu-central-1 | Frankfurt (Germany) | ap-southeast-2 (Sydney)     | ~16,000 km         |

---

### 🔹 Why Regions Are Far Apart?

1. **Disaster recovery** – Agar ek region me flood, fire, ya power issue ho to doosra safe rahe.
2. **Latency optimization** – User ke nearest region se fast response milta hai.
3. **Data compliance** – Countries ke data laws ke hisaab se data local rehna chahiye (e.g., India data India me).

---

## 👨‍🎓 **Student Notes:**

📘 **Cloud Region**

* Data centers ka geographical group.
* Har region independent hota hai (apna power, cooling, network).
* Multiple **zones** hote hain ek region ke andar.

📏 **Distance:**

* 500 km – 10,000 km tak ho sakta hai (country aur continent pe depend karta hai).

📦 **Examples:**

* `ap-south-1` → Mumbai
* `ap-southeast-1` → Singapore
* `us-east-1` → Virginia

📡 **Purpose:**

* Disaster recovery
* Latency reduce karna
* Legal compliance maintain karna

## 📘 **Concept 1 – Data Center क्या होता है**

### 🧑‍🏫 Explanation:

Data Center एक **physical building** होता है जिसमें हज़ारों servers, routers, cooling systems, और power backup systems होते हैं।
यहीं पर Cloud के सारे data और applications store किए जाते हैं।

**Example:**
अगर आप Amazon EC2 instance बनाते हो, तो असल में वो किसी AWS Data Center में run होता है।

### 💡 Key Points:

* Data Center = Physical infrastructure (hardware, cooling, electricity)
* इसमें कई racks और servers होते हैं
* 24×7 बिजली, cooling, और internet backup होता है
* AWS के हर Data Center में **redundancy** (backup power + internet) मौजूद होती है

---

## 📘 **Concept 2 – Availability Zone (AZ) क्या होती है**

### 🧑‍🏫 Explanation:

Availability Zone एक **Region के अंदर मौजूद independent location** होती है जिसमें **एक या एक से ज़्यादा Data Centers** होते हैं।

हर AZ को इस तरह design किया गया है कि अगर एक Zone fail हो जाए (जैसे बिजली कट जाए या network down हो जाए)
तो दूसरा Zone automatically काम करे।

### 💡 Example:

AWS Mumbai Region (`ap-south-1`) में 3 Availability Zones हैं:

* `ap-south-1a`
* `ap-south-1b`
* `ap-south-1c`

अगर `1a` down हो जाए, तो traffic `1b` या `1c` पर redirect हो जाता है।

---

## 📘 **Concept 3 – Region क्या होता है**

### 🧑‍🏫 Explanation:

**Region** एक **geographical area** होता है जिसमें कई Availability Zones (AZs) होती हैं।
हर Region का अपना infrastructure, data laws, और pricing होता है।

### 💡 Example:

| Region Name              | Code         | Availability Zones |
| ------------------------ | ------------ | ------------------ |
| US East (N. Virginia)    | `us-east-1`  | 6 AZs              |
| Asia Pacific (Mumbai)    | `ap-south-1` | 3 AZs              |
| Asia Pacific (Hyderabad) | `ap-south-2` | 3 AZs              |

---

## 📘 **Concept 4 – Relationship Between Region, AZ, and Data Center**

### 🧑‍🏫 Hierarchy Diagram:

```
AWS Cloud
 ├── Region (e.g., ap-south-1 → Mumbai)
 │     ├── Availability Zone (ap-south-1a, 1b, 1c)
 │     │     ├── Data Center(s)
 │     │     │     ├── Physical Servers
```

👉 मतलब:

* Region = Group of AZs
* AZ = Group of Data Centers
* Data Center = Group of Servers

* Route 53, EC2, and S3 resources are Region-based.

### AWS Services Introduction | Q&A Notes

**Teacher:** AWS की सर्विसेस को हम कैसे categorize कर सकते हैं?
**Student:** AWS की सर्विसेस को तीन कैटेगरी में बांटा गया है:

1. **Zonal Services (जोनल सर्विसेस)** – केवल एक **Availability Zone (AZ)** में उपलब्ध होती हैं। उदाहरण: **Subnet**।
2. **Regional Services (रीजनल सर्विसेस)** – एक रीजन के कई AZs में उपलब्ध होती हैं। उदाहरण: **EC2, ELB, VPC, Elastic Beanstalk**।
3. **Global Services (ग्लोबल सर्विसेस)** – कई रीजन में उपलब्ध होती हैं। उदाहरण: **IAM, Route 53, CloudFront**।

---

**Teacher:** Zonal, Regional और Global services में फर्क क्या है?
**Student:**

* **Zonal:** केवल एक AZ में उपयोग हो सकती हैं।
* **Regional:** पूरे रीजन में, यानी एक से ज्यादा AZs में उपयोग हो सकती हैं।
* **Global:** एक से ज्यादा रीजन में उपलब्ध होती हैं।

---

**Teacher:** EC2 क्या है और इसका उपयोग कैसे करते हैं?
**Student:**

* **EC2 (Elastic Compute Cloud)** एक **रीजनल सर्विस** है।
* इसमें **Virtual Machine (VM) = Instance** बनाते हैं।
* आप रीजन और AZ चुनकर **instances launch** कर सकते हैं।
* EC2 में आपको **OS configuration, software installation, firewall setup** आदि खुद करना होता है।

---

**Teacher:** ELB क्या है?
**Student:**

* **ELB (Elastic Load Balancer)** एक **रीजनल सर्विस** है।
* Incoming traffic को **multiple EC2 instances** में distribute करता है।
* **Elastic** इसलिए क्योंकि इसमें **auto-scaling** का support होता है।
* Scale Out → Instances बढ़ाना, Scale In → Instances कम करना।

---

**Teacher:** Elastic Beanstalk क्या है और कैसे काम करता है?
**Student:**

* **Elastic Beanstalk (PaaS)** आपको **applications deploy करने की सुविधा** देता है।
* Infrastructure का **operational burden** AWS खुद manage करता है।
* आप सिर्फ **code upload** करते हैं, Beanstalk automatically servers, databases, load balancers और scaling setup करता है।
* यह भी **रीजनल सर्विस** है।

---

**Teacher:** EC2 और Elastic Beanstalk में फर्क क्या है?
**Student:**

| Feature             | EC2                                             | Elastic Beanstalk                        |
| ------------------- | ----------------------------------------------- | ---------------------------------------- |
| Control over server | High, आप खुद configure करते हैं                 | Low, AWS manage करता है                  |
| Setup complexity    | High, OS और environment configure करना पड़ता है | Low, बस code upload करना होता है         |
| Scaling             | Manual setup or ELB needed                      | Auto-scaling built-in                    |
| Target user         | DevOps/Server knowledge required                | Developers जो code deploy करना चाहते हैं |

---

**Teacher:** Lightsail क्या है?
**Student:**

* **Lightsail** एक simple **VPS** service है।
* Pre-installed tools और applications (WordPress, cPanel, Joomla आदि) के साथ आती है।
* **Easy to use**, लेकिन **auto-scaling नहीं है**।
* यह भी **रीजनल सर्विस** है।

---

**Teacher:** AWS Lambda क्या है?
**Student:**

* **Lambda** एक **serverless computing platform** है।
* आप **code run कर सकते हैं बिना server manage किए**।
* **Events** (जैसे S3 upload, scheduled task) के response में code execute होता है।
* Lambda भी **रीजनल सर्विस** है।
* उदाहरण:

  * S3 में picture upload → Lambda automatically resize कर दे।
  * EC2 instance stop होने पर → Lambda auto-restart कर दे।

---

**Teacher:** Lambda और EventBridge कैसे काम करते हैं?
**Student:**

* **EventBridge** events capture करता है।
* Lambda उन events के response में code execute करता है।
* Supports **event-driven automation** और **scheduled tasks**।

---

**Teacher:** AWS की सर्विसेस summary?
**Student:**

1. **EC2** → Virtual Machines, रीजनल।
2. **ELB** → Load balancing, रीजनल।
3. **Elastic Beanstalk** → Application deployment, PaaS, रीजनल।
4. **Lightsail** → Easy VPS, रीजनल, pre-installed apps।
5. **Lambda** → Serverless functions, रीजनल, event-driven।

## ⚙️ **Amazon EBS (Elastic Block Store) — Kya Hai?**

**Amazon EBS** ek **block storage service** hai jo **EC2 instances** ke liye use hoti hai.
Iska matlab — ye **virtual hard disk** jaisa kaam karti hai jo aapke **EC2 (virtual machine)** ke sath attach hoti hai.

---

### 🧠 **Simple Definition:**

> **EBS** ek **persistent block storage** hai jo **Amazon EC2** instances ko data store karne ke liye disk ke roop me milta hai.

---

## 💡 **Example Samajhiye:**

Agar aapne **EC2 instance** launch kiya (jaise ek Linux server),
to us server ko apne files, database, application data store karne ke liye **hard disk** chahiye hoti hai.
Wahi **EBS volume** hota hai.

📘 Example:

* EC2 Instance = Computer (CPU + RAM)
* EBS Volume = Hard Disk (Storage)

---

## 🔹 **EBS Ki Key Features:**

| Feature               | Description                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------------- |
| **Block Storage**     | Data blocks ke form me store hota hai (like local disk).                                    |
| **Persistent**        | Instance band hone ke baad bhi data delete nahi hota (jab tak aap manually na delete karo). |
| **Attach/Detach**     | Aap volume ko kisi bhi EC2 instance ke sath attach ya detach kar sakte ho.                  |
| **Scalable**          | Size badha ya ghata sakte ho bina data lose kiye.                                           |
| **Backup (Snapshot)** | Aapka data ka backup Amazon S3 me snapshot ke roop me store hota hai.                       |
| **Encrypted Storage** | Data-at-rest aur data-in-transit dono encrypted hota hai.                                   |

---

## 🧩 **EBS Volume Types:**

| Type                               | Description                 | Use Case                      |
| ---------------------------------- | --------------------------- | ----------------------------- |
| **gp3 (General Purpose SSD)**      | Balanced performance & cost | Boot volumes, small databases |
| **io2 (Provisioned IOPS SSD)**     | High performance (IOPS)     | Databases like Oracle, MySQL  |
| **st1 (Throughput Optimized HDD)** | Sequential data ke liye     | Big data, log processing      |
| **sc1 (Cold HDD)**                 | Low-cost, infrequent access | Archive data, backup          |

---

## 🪣 **EBS vs S3 (Difference Table):**

| Feature          | **EBS**                   | **S3**                       |
| ---------------- | ------------------------- | ---------------------------- |
| **Storage Type** | Block Storage             | Object Storage               |
| **Attach To**    | EC2 Instance              | Internet accessible          |
| **Persistence**  | Tied to specific instance | Independent                  |
| **Performance**  | High I/O speed            | Slower (API-based access)    |
| **Use Case**     | OS, database, app files   | Backups, media, static files |

---

## 📘 **EBS Snapshot:**

* EBS volumes ka backup **Snapshot** ke form me **S3** me store hota hai.
* Snapshot se aap **naya volume restore** kar sakte ho.

📙 Command Example:

```bash
aws ec2 create-snapshot --volume-id vol-0abcd1234efgh5678 --description "My backup"
```

---

## 🎯 **EBS Ka Use Kis Liye Karte Hain:**

| Use Case                                            | Description                              |
| --------------------------------------------------- | ---------------------------------------- |
| **EC2 instance ka OS aur data store karne ke liye** | Boot volume ke roop me                   |
| **Database storage**                                | MySQL, PostgreSQL, Oracle, MongoDB, etc. |
| **File system storage**                             | Application data, logs                   |
| **Backup & Restore**                                | Snapshots ke zariye                      |
| **High-performance workloads**                      | Low-latency I/O tasks ke liye            |

---

## 🧠 **In Short:**

> **Amazon EBS** ek **virtual hard disk** hai jo **EC2 instances** ke liye high-performance, persistent, aur secure block storage provide karti hai.

## 🎯 **Session 13 – AWS Storage Services (EFS, Snow Family, S3 Glacier)**

### 🔹 भाग 1 – EFS (Elastic File System)

**Q1. AWS EFS क्या है?**
EFS यानी **Elastic File System** — AWS की एक **serverless, scalable, managed file storage service** है।
यह एक ही डेटा को **multiple EC2 instances** पर एक साथ शेयर करने की सुविधा देता है।

**Q2. EBS की limitation क्या थी?**
EBS को एक समय में केवल एक EC2 instance से attach किया जा सकता है।
भले ही “multi-attach” फीचर है, पर वह भी अधिकतम 16 instances तक सीमित है और block-level पर काम करता है।

**Q3. EFS क्यों जरूरी है?**
क्योंकि यह **file-level storage** देता है और एक ही समय पर **हजारों EC2 instances** को access करने की अनुमति देता है।

**Q4. EFS की खासियतें क्या हैं?**

* Serverless (कोई manual provisioning नहीं)
* Auto scaling – डेटा के अनुसार size बढ़ता/घटता है
* Encrypted & Secure
* Concurrent file access
* AWS Managed Service
* Multi-AZ (Regional Service)
* NFS v4 protocol पर काम करता है

**Q5. EFS किस use-case में helpful है?**
जब एक ही डेटा को **कई सर्वर या एप्लिकेशन** को एक साथ access करना हो — जैसे shared configuration files या web content।

**Q6. EFS regional क्यों कहलाता है?**
क्योंकि यह **multi-AZ** में data store करता है और पूरे region में accessible होता है, जबकि EBS केवल एक AZ तक सीमित है।

---

### 🔹 भाग 2 – AWS Snow Family

**Q7. AWS Snow Family क्या है?**
यह **physical storage devices** का collection है जिसका उपयोग **large-scale data transfer** (on-premises ↔ cloud) के लिए किया जाता है।
जब internet bandwidth कम हो या cost ज़्यादा हो तो Snow devices से data physically move किया जाता है।

**Q8. Snow Family में कौन-कौन सी services आती हैं?**

1. **AWS Snowcone** – छोटी device (~8 TB), portable, edge computing के लिए।
2. **AWS Snowball Edge** – medium-size device (40–80 TB), large data transfer के लिए।
3. **AWS Snowmobile** – बहुत बड़ी truck-size device (100 PB तक), पूरे data center migration के लिए।

**Q9. Snow devices की खास बातें क्या हैं?**

* Highly secure (256-bit encryption)
* Tamper-proof
* Portable (airplane impact सह सकते हैं)
* Offline data transfer possible
* Edge computing support

**Q10. Snow Family कब use करते हैं?**
जब –

* Internet slow या unavailable हो
* Data बहुत बड़ा (TB–PB level) हो
* Remote/isolated location हो
* पूरा data center migrate करना हो
* Disaster recovery setup करना हो

---

### 🔹 भाग 3 – AWS S3 Glacier

**Q11. AWS S3 Glacier क्या है?**
यह AWS की **archival storage service** है — यानी पुराने या rarely accessed data को **कम cost** में store करने के लिए।
Backup, long-term retention, और compliance data के लिए perfect है।

**Q12. Glacier के storage classes कौन से हैं?**

1. **S3 Glacier Instant Retrieval** – तुरंत access (millisecond), थोड़ा महँगा।
2. **S3 Glacier Flexible Retrieval** – कुछ मिनट से घंटे में access, कम cost।
3. **S3 Glacier Deep Archive** – 12 घंटे में restore, सबसे सस्ता।

**Q13. Glacier कहाँ useful है?**

* Backup data
* Long-term archives (years)
* Legal/compliance data
* Rarely accessed files

### 🔹 Summary Comparison Table

| Feature / Service | **EBS**                         | **EFS**             | **S3 Glacier**         | **AWS Snow Family**  |
| ----------------- | ------------------------------- | ------------------- | ---------------------- | -------------------- |
| Storage Type      | Block-level                     | File-level          | Object-level (Archive) | Physical device      |
| Access Type       | One EC2 (Multi-attach up to 16) | Many EC2s           | Rare access            | Offline transfer     |
| Scalability       | Manual                          | Auto                | Auto                   | Physical capacity    |
| Use Case          | OS, DB                          | Shared file storage | Backup/Archive         | Large data migration |
| Connectivity      | AZ-based                        | Regional (Multi-AZ) | Internet               | Offline/Physical     |

## 🧩 **1️⃣ EBS vs EFS vs Glacier vs Snow — Real-life Examples के साथ**

---

### 🟢 **EBS (Elastic Block Store)** — “Laptop की Hard Disk” जैसा है 💽

**सोचो:**
तुम्हारे लैपटॉप में एक **Hard Disk (SSD)** लगी है।
वह सिर्फ **उस लैपटॉप से जुड़ी** होती है।
अगर तुम उसे किसी दूसरे लैपटॉप में लगाना चाहो — manually करना पड़ेगा।

**ऐसे ही AWS में:**

* **EBS** एक **Block Storage** है (Hard Disk जैसा)।
* एक समय में सिर्फ **एक EC2 instance** से जुड़ सकता है।
* Performance बहुत fast होती है (जैसे OS या Database के लिए)।
* अगर EC2 बंद हो जाए तो Disk का data safe रहता है।

🧠 **Example:**
मान लो तुम्हारा EC2 server एक Database चला रहा है (MySQL)।
उसका data एक EBS volume पर stored है।
जब तुम EC2 बंद करते हो — data delete नहीं होता क्योंकि वो disk (EBS) अलग से मौजूद रहती है।

---

### 🔵 **EFS (Elastic File System)** — “Google Drive” या “Network Shared Folder” जैसा है 📁

**सोचो:**
कंपनी में एक shared network drive है — जैसे
“Z:\SharedDocs”
जहाँ से सभी employees एक साथ file खोल सकते हैं, edit कर सकते हैं।

**ऐसे ही AWS में:**

* **EFS** एक **File Storage** है।
* एक ही data को **multiple EC2 servers** एक साथ access कर सकते हैं।
* यह **auto-scale** होता है — तुम्हारे data के size के हिसाब से अपने-आप बढ़ता या घटता है।
* AWS इसके पीछे storage manage करता है (serverless है)।

🧠 **Example:**
मान लो तुम्हारे पास 10 EC2 web servers हैं जो एक ही web application चला रहे हैं।
तुम्हारे static files (images, config files, CSS, etc.) सबको common चाहिए।
तो तुम EFS बनाओगे और सब servers में mount कर दोगे।
अब कोई भी server file update करे — बाकी सबको भी वही change दिखेगा।

🔹 **Comparison:**

* EBS → Single user (like your laptop HDD)
* EFS → Multi-user shared folder (like office shared drive)

---

### 🟣 **AWS Snow Family** — “Data Courier Truck” जैसा है 🚚

**सोचो:**
तुम्हारे पास बहुत सारा data (10 TB या 100 TB) है,
और तुम्हारा Internet बहुत slow है — upload करने में महीनों लग जाएंगे।
तो तुम क्या करोगे?

AWS कहता है — “भेज दो physical device से।”

**Snow Family वही करता है:**

* AWS तुम्हें एक **device भेजता है (Snowcone/Snowball/Snowmobile)**
* तुम अपने data को उसमें copy कर देते हो
* फिर device को AWS को वापस भेज देते हो
* AWS तुम्हारा data अपने data center में upload कर देता है

🧠 **Example:**

* 10 TB data है — तो **Snowball Edge** मंगवाओ
* Copy करो → Ship करो → AWS upload कर देगा
* 100 PB (Petabyte) data है — तो **Snowmobile (Truck)** भेजते हैं!

🔹 **Comparison:**

* Internet के बजाय **Physical courier way** से data transfer होता है
* Useful जब bandwidth कम हो या data बहुत बड़ा हो

---

### 🟠 **S3 Glacier** — “Old Data Storage Locker” जैसा है 📦

**सोचो:**
तुम्हारे घर में पुराने files, bills, या certificates हैं जो साल में एक बार ही काम आते हैं।
तुम उन्हें bank locker में रख देते हो —
क्योंकि वो **safe** रहते हैं और रोज़ access करने की ज़रूरत नहीं।

**ऐसे ही AWS में:**

* **S3 Glacier** वही “locker” है cloud में।
* यह **archival storage** है — rarely used data के लिए।
* Access slow होता है (कुछ मिनट से घंटे लगते हैं)
* लेकिन cost बहुत सस्ती है।

🧠 **Example:**
तुम्हें किसी company के **10 साल पुराने invoices** या **backup logs** रखने हैं (legal requirement)।
उन्हें Glacier में डाल दो — safe रहेंगे, कम खर्च आएगा, और जरूरत पड़े तो restore कर लो।

## 🧩 **1️⃣ AWS Snow Family क्या करती है (Quick Recap)**

AWS Snow Family का काम है –
**"बहुत बड़े डेटा को AWS Cloud में या AWS से बाहर ट्रांसफर करना"**
जब internet से upload/download करना बहुत slow या महँगा पड़ जाए।

इस family में तीन members होते हैं 👇

| Device            | Capacity  | Use                        |
| ----------------- | --------- | -------------------------- |
| **Snowcone**      | ~8 TB     | Small data, Edge computing |
| **Snowball Edge** | 40–80 TB  | Medium data transfer       |
| **Snowmobile**    | 100 PB तक | पूरा Data Center migration |

## ⚙️ **2️⃣ AWS Snow Family Workflow – Step-by-Step**

नीचे पूरा workflow 6 simple steps में है 👇

---

### 🟢 **Step 1 – Job Creation in AWS Console**

सबसे पहले user (या admin) AWS Console में जाकर **Snow Job** बनाता है।

➡️ वहाँ आपको चुनना होता है:

* कौन सा device चाहिए (Snowcone, Snowball, Snowmobile)
* Source data कहाँ से आएगा (on-premises servers, NAS, etc.)
* Destination (S3 bucket)
* Encryption key (KMS key)
* Shipping address

🧠 **Example:**
तुम्हारे पास 50 TB logs हैं जिन्हें S3 में डालना है → तो तुम **Snowball Edge** चुनोगे।

---

### 🟢 **Step 2 – Device Shipping by AWS**

AWS उसी region के data center से तुम्हें physical device courier करता है।

* Device पहले से ही **encrypted** और **tamper-proof** होता है।
* AWS device को track करने के लिए **AWS OpsHub software** provide करता है।

---

### 🟢 **Step 3 – Data Copying (Local Upload)**

जब device तुम्हारे पास आता है 👇

1. उसे power on करो
2. Laptop/Server से connect करो
3. **AWS OpsHub software** या **CLI commands** से device में data copy करो
4. Device internally data को **AES-256 encryption** से encrypt करता है

📘 **Tech details:**

* File system automatically manage होता है
* Edge computing possible है (Snowball Edge पर EC2 instances भी चल सकते हैं)
* Connectivity: Ethernet या Wi-Fi (Snowcone)

🧠 **Example:**
तुम अपने local NAS से 50 TB logs को copy करते हो → Snowball Edge पर।

---

### 🟢 **Step 4 – Device Return to AWS**

Data upload पूरा होने के बाद:

* Device को securely shut down करो
* AWS को वापस courier कर दो
* Shipment track कर सकते हो AWS Console से

Device में data encrypted होता है, इसलिए कोई बीच में data नहीं पढ़ सकता।

---

### 🟢 **Step 5 – Data Upload to S3 (by AWS)**

जब AWS को device वापस मिल जाता है:

1. AWS device को अपने **import facility** में connect करता है
2. Device के अंदर का encrypted data decrypt करके
   तुम्हारे चुने हुए **S3 bucket** में upload कर देता है
3. Upload complete होने पर device को sanitize (data delete) किया जाता है

📘 **Internal Layer:**

* Device से data → AWS import servers → S3 buckets
* AWS logs maintain करता है (CloudWatch / Snow job status)

---

### 🟢 **Step 6 – Verification & Job Completion**

जब upload पूरा हो जाता है:

* तुम्हें **notification** मिलती है (email या console)
* तुम S3 bucket में अपने data को verify कर सकते हो
* Device का data AWS permanently erase कर देता है (secure wipe)

---

```
     ┌────────────────────────────────────┐
     │          AWS Snow Family           │
     └────────────────────────────────────┘

        ▼ Step 1: Create Job in AWS Console
              ↓
        AWS prepares encrypted Snow device
              ↓
        ▼ Step 2: Device shipped to customer
              ↓
        ▼ Step 3: Customer copies data to device
            (via OpsHub / CLI)
              ↓
        ▼ Step 4: Customer ships device back to AWS
              ↓

              ↓

```

### 🧩 **Session 14 – AWS Database Services (Amazon RDS Introduction)**

🎓 *By: Nehra Classes | Trainer: Vikas Nehra*

---

#### 🧠 **1. Database क्या होता है?**

**Teacher:** Database क्या है?
**Student:** Database एक **structured collection of data** होता है जिसे इस तरह organize और store किया जाता है कि डेटा को efficiently **retrieve, manage और manipulate** किया जा सके।

**Example:**
Employee details वाली टेबल जिसमें ID, Name, Salary आदि stored हों — यह एक database table का हिस्सा है।

---

#### 🧩 **2. DBMS क्या है?**

**Teacher:** DBMS (Database Management System) क्या करता है?
**Student:** DBMS एक software है जो database के साथ interact करने की सुविधा देता है। इससे हम data को:

* Create
* Retrieve
* Modify
* Manage
  कर सकते हैं, साथ ही **security और integrity** बनाए रखते हैं।

---

#### 🧮 **3. RDBMS क्या है?**

**Teacher:** Relational Database क्या होता है?
**Student:** RDBMS में data **tables (rows और columns)** के रूप में store किया जाता है, और टेबल्स के बीच **relationships** बनाए जाते हैं (जैसे primary key, foreign key)।
**Example:** MySQL, PostgreSQL, Oracle, SQL Server आदि।

---

#### 💬 **4. SQL क्या है?**

**Teacher:** SQL का use क्या है?
**Student:** SQL (Structured Query Language) एक standard language है जो relational databases के साथ **query, update और structure define** करने के लिए उपयोग होती है।

---

#### ⚙️ **5. Normalization क्या है?**

**Student:** Normalization एक process है जिससे data को इस तरह organize किया जाता है कि redundancy (duplicate data) और dependency कम हो, जिससे database efficient बनता है।

---

#### 🔍 **6. Indexes क्या करते हैं?**

**Student:** जैसे किताब में Index हमें जल्दी page तक पहुंचाता है, वैसे ही database में Index data retrieval को **fast** करता है।

---

#### ⚔️ **7. DBMS vs RDBMS Difference**

| Feature       | DBMS              | RDBMS                      |
| ------------- | ----------------- | -------------------------- |
| Structure     | Files-based       | Tables (rows/columns)      |
| Relationships | नहीं enforce करता | Enforce करता (keys के साथ) |
| Normalization | Optional          | Mandatory                  |
| Examples      | MS Access         | MySQL, Oracle, SQL Server  |

---

#### 🏗️ **8. Physical Database Server की Problems**

**Teacher:** Traditional (on-premise) database servers में क्या दिक्कतें हैं?
**Student:**

* Hardware failure (CPU, RAM, HDD issues)
* Scalability problem (resources बढ़ाना कठिन)
* Maintenance downtime
* Power & cooling issues
* Space requirement
* High cost (hardware + license + maintenance)
* Backup, recovery, security सब खुद manage करना
* Limited redundancy (high availability मुश्किल)

---

#### ☁️ **9. Cloud क्यों बेहतर है?**

**Teacher:** Cloud databases को क्यों prefer किया जाता है?
**Student:**
क्योंकि Cloud databases (जैसे AWS RDS) में:

* High availability
* Scalability
* Low maintenance
* Automatic backup
* Cost efficiency
* Disaster recovery
* Security और performance बेहतर होती है।

---

#### 🌐 **10. AWS Database Services Overview**

**AWS में Database Services:**

1. **RDS (Relational Database Service)** – Managed relational DB.
2. **DynamoDB** – NoSQL database.
3. **Elasticache** – In-memory cache.
4. **Redshift** – Data warehousing service.

---

#### 🧱 **11. Amazon RDS क्या है?**

**Teacher:** RDS क्या है — Database या Service?
**Student:** RDS एक **database नहीं** है, यह एक **managed database service** है जो AWS पर relational databases को **setup, operate और scale** करने की सुविधा देती है।

**RDS Features:**

* AWS खुद database instance manage करता है
* User को infrastructure manage करने की जरूरत नहीं
* Focus सिर्फ application logic पर रह सकता है

---

#### 💡 **12. RDS कौन-कौन से Database Engines को Support करता है?**

| Database Engine | Owner                                            |
| --------------- | ------------------------------------------------ |
| MySQL           | Open Source                                      |
| PostgreSQL      | Open Source                                      |
| Oracle          | Oracle Corporation                               |
| SQL Server      | Microsoft                                        |
| MariaDB         | Open Source                                      |
| Amazon Aurora   | AWS (proprietary, MySQL & PostgreSQL compatible) |

---

#### 🧭 **13. RDS के Benefits**

* Fully managed (no manual maintenance)
* Automatic backup & recovery
* High availability (Multi-AZ)
* Easy scaling
* Cost-effective pay-as-you-go model
* Secure (encryption & IAM integration)

---

### ✅ **Summary Notes**

* **Database** = structured data collection
* **DBMS** = software to manage databases
* **RDBMS** = relational model (tables, keys)
* **SQL** = language for database operations
* **Normalization & Indexing** = improve efficiency
* **AWS RDS** = managed relational database service
* **Supports 6 Engines:** MySQL, PostgreSQL, Oracle, SQL Server, MariaDB, Aurora
* **Solves:** hardware, scaling, maintenance & cost issues of traditional servers

## 🧾 **AWS IAM Service – Getting Started with IAM Users & Groups**

### 🎯 **Objective:**

To understand and perform basic IAM (Identity and Access Management) operations — creating **Users**, **Groups**, and assigning **Permissions** in AWS.

---

### 🧠 **Concept Summary**

* **IAM (Identity and Access Management)** is an AWS service used to **securely control access** to AWS resources.
* With IAM, you can **create users, groups, and roles**, and assign permissions using **policies**.
* It’s a **global service** (not region-specific).
* IAM ensures **least privilege principle** — give only the permissions required.

---

### 🧩 **Step-by-Step Practical**

#### 🪪 **1. Open AWS IAM Console**

* Go to AWS Console → Search **IAM** → Open the IAM Dashboard.
* Left side menu shows options: Users, Groups, Roles, Policies.

---

#### 👥 **2. Create IAM User**

1. Click **Users → Add user**
2. Enter username (e.g., `developer1`)
3. Select **Access type**:

   * ✅ *AWS Management Console access* (for GUI login)
   * ✅ *Programmatic access* (for CLI / SDK)
4. Set a custom password (e.g., `Dev@1234`)
5. Choose **Require password reset** (optional)
6. Click **Next** to set permissions.

---

#### 👨‍👩‍👦 **3. Create IAM Group**

1. Go to **Groups → Create group**
2. Name it (e.g., `Developers`)
3. Attach a policy:

   * Example: **AmazonS3FullAccess** or **EC2ReadOnlyAccess**
4. Click **Create group**
5. Now add your user (`developer1`) into this group.

---

#### 🔑 **4. Assign Permissions to User or Group**

* If user is part of a group → permissions are inherited from the group.
* Alternatively, attach a policy directly to the user.

Example:

* Policy name: `AmazonEC2FullAccess`
* Effect: Allow
* Action: All EC2 actions
* Resource: All resources

---

#### 🧾 **5. Test the Access**

1. Sign out of the root account.
2. Login using the new IAM user credentials.
3. Try accessing allowed and restricted services — verify permission boundaries.

---

### 💻 **6. Optional: Access Keys (for CLI)**

If programmatic access was chosen:

* Go to IAM → Users → Select user → **Security credentials** → Create Access key
* Use these in AWS CLI:

  ```bash
  aws configure
  AWS Access Key ID [None]: AKIAxxxxxxx
  AWS Secret Access Key [None]: XXXXXXXXXXXXX
  Default region name [None]: ap-south-1
  Default output format [None]: json
  ```

---

### 🧾 **Output / Result**

✅ IAM User `developer1` created successfully.
✅ IAM Group `Developers` created with attached policy.
✅ User inherits permissions from the group and can access allowed services only.

---

### ⚙️ **Key Points**

* Root account should not be used for daily operations.
* Always create IAM users for team members.
* IAM is **Global**, not tied to a region.
* Use **Policies** to define what actions are allowed/denied.
* Follow **Principle of Least Privilege**.

---

### ❌ **Common Errors & Fixes**

| Error                 | Cause                    | Solution                               |
| --------------------- | ------------------------ | -------------------------------------- |
| “Access Denied”       | Missing permission       | Attach required policy                 |
| “User cannot login”   | Console access not given | Enable “AWS Management Console Access” |
| “Invalid credentials” | Wrong username/password  | Reset from IAM console                 |

---

### 🧩 **Conclusion**

> In this session, we learned how to manage access in AWS using IAM by creating users, groups, and assigning permissions through policies. This ensures secure and organized control over AWS resources.
