# Q1. What is Docker?

### Answer (From Your Notes)

**Docker is an open-source containerization platform** that is used to **build, package, ship, and run applications inside containers.**

A Docker container contains:

* Application Code
* Required Libraries
* Dependencies
* Runtime Environment

Because everything required is packed inside the container, the application behaves the **same in Development, Testing, UAT, and Production**.

Docker uses **Linux Kernel features** like:

* **Namespaces** → provide isolation
* **cgroups** → provide resource limits (CPU, Memory, etc.)

### Example

Suppose you developed a Spring Boot application.

Instead of installing:

* Java
* Maven
* Tomcat
* Required libraries

on every server, you create one Docker Image.

```bash
docker run my-springboot-app
```

Now the application will run exactly the same on every machine.

---

* Open Source
* Containerization Platform
* Portable
* Lightweight
* Isolation
* Same Environment Everywhere

---

### Remember

> **Docker = Build Once, Run Anywhere**

# Q2. What are the main components of Docker Architecture?

### Answer (From Your Notes)

Docker architecture mainly consists of **five components**:

## 1. Docker Client

This is the command-line tool that developers use.

Example:

```bash
docker run nginx
docker build .
docker pull ubuntu
```

The Docker Client **doesn't create containers itself**.

It sends requests to the **Docker Daemon**.

---

## 2. Docker Daemon (dockerd)

Docker Daemon is the **background service** responsible for managing Docker.

It performs operations like:

* Create Container
* Run Container
* Stop Container
* Delete Container
* Build Images
* Manage Networks
* Manage Volumes

When you execute:

```bash
docker run nginx
```

Flow becomes:

```
Docker Client
      │
      ▼
Docker Daemon
      │
      ▼
Creates Container
```

---

## 3. Docker Image

A Docker Image is a **read-only template** used to create containers.

It contains:

* Application Code
* Libraries
* Dependencies
* Runtime

One Image can create **multiple containers**.

Example:

```bash
docker run nginx
docker run nginx
docker run nginx
```

Three different containers are created from the same image.

---

## 4. Docker Container

A Container is the **running instance of a Docker Image**.

It has its own:

* Process
* Network
* File System
* Writable Layer

Changes made inside the container are stored in the **Container Layer (Writable Layer)** using **Copy-On-Write (COW)**.

---

## 5. Docker Registry

Docker Registry is used to **store and share Docker Images**.

Examples:

* Docker Hub (Public Registry)
* Private Docker Registry

Commands:

```bash
docker pull nginx
```

Downloads an image from the registry.

```bash
docker push myimage
```

Uploads an image to the registry.

Your notes also show how to create a **Private Docker Registry** using:

```bash
docker run -d -p 5000:5000 --name registry registry:2
```

and push images to it.

---

## Docker Architecture Flow

```
Developer
     │
     ▼
Docker Client
     │
     ▼
Docker Daemon
     │
 ┌───┼───────────────┐
 ▼   ▼               ▼
Images Containers Networks
     │
     ▼
Docker Registry
(Pull / Push Images)
```

---

### Interview Keywords

* Docker Client
* Docker Daemon
* Docker Image
* Docker Container
* Docker Registry

---

### Remember Trick

**CIDCR**

* **C** → Client
* **I** → Image
* **D** → Daemon
* **C** → Container
* **R** → Registry

# Q3. What is a Docker Container?

## Answer (From Your Notes)

A **Docker Container** is a **running instance of a Docker Image**.

It is a **lightweight**, **isolated**, and **portable** environment that contains everything required to run an application, such as:

* Application Code
* Runtime
* Libraries
* Dependencies
* System Tools

Unlike a Docker Image, a **Container is writable**.

When a container starts, Docker creates a **Writable Container Layer** on top of the read-only image layers. Any changes made inside the container are stored in this writable layer using **Copy-On-Write (COW)** technology.

---

### Example

Create a container from the Ubuntu image:

```bash
docker run -it ubuntu bash
```

Now you are working **inside the container**.

Or create a web server container:

```bash
docker run -d --name my-webserver nginx
```

---

### Real-Life Example

Think of a **Docker Image as a class** in Java.

A **Docker Container is an object** created from that class.

One Image can create multiple Containers.

Example:

```bash
docker run --name app1 nginx
docker run --name app2 nginx
docker run --name app3 nginx
```

Here, one **nginx image** creates three different containers.

---

# Q4. What is a Docker Image?

## Answer (From Your Notes)

A **Docker Image** is a **read-only template** used to create Docker Containers.

It contains everything required to run an application:

* Application Code
* Runtime
* Libraries
* Dependencies
* Environment Variables
* Default Commands

A Docker Image is **immutable**, which means it cannot be modified after it is built.

One Docker Image can be used to create **multiple containers**.

Images are usually built using a **Dockerfile** and can be stored in a **Docker Registry** like Docker Hub or a Private Registry.

---

### Image Layers (Very Important)

According to your notes, a Docker Image is made up of multiple **read-only layers**.

Each Dockerfile instruction creates a new layer.

Example:

```dockerfile
FROM ubuntu
RUN apt update
RUN apt install -y nginx
COPY . /app
```

Layers created:

* Layer 1 → Base Ubuntu Image
* Layer 2 → apt update
* Layer 3 → Install nginx
* Layer 4 → Copy application

Docker caches these layers, making image builds faster.

---

### Example

Build an image:

```bash
docker build -t myapp .
```

Run a container:

```bash
docker run myapp
```

---

# Q19. What is a Dockerfile?

## Answer (From Your Notes)

A **Dockerfile** is a **text file** that contains a series of instructions used to **build a Docker Image** automatically.

Instead of installing software manually every time, we write the steps in a Dockerfile. Docker executes these instructions one by one to create an image.

Each instruction (such as **FROM, RUN, COPY, CMD**) creates a **new read-only layer** in the Docker Image. Docker caches these layers, making future builds faster.

---

### Example

```dockerfile
FROM ubuntu:22.04

RUN apt update

RUN apt install -y nginx

COPY . /app

CMD ["nginx","-g","daemon off;"]
```

Docker creates layers like this:

```
Layer 1 → FROM ubuntu
Layer 2 → RUN apt update
Layer 3 → RUN install nginx
Layer 4 → COPY application
Layer 5 → CMD
```

---

### Why do we use Dockerfile?

* Automates image creation
* Eliminates manual installation
* Easy to share
* Supports version control
* Same environment everywhere

---

### Interview Keywords

* Text File
* Build Docker Image
* Automation
* Docker Instructions
* Layers

---

### Remember

# Q22. What is the difference between COPY and ADD?

## Answer

### COPY

`COPY` simply copies files and folders from the **host machine** to the **Docker Image**.

Example:

```dockerfile
COPY app.jar /app/
```

It only performs file copying.

---

### ADD

`ADD` can do everything that `COPY` does, but it has **two extra features**:

1. It can download files from a URL.
2. It automatically extracts compressed files (like `.tar.gz`).

Example:

```dockerfile
ADD app.tar.gz /app/
```

Docker automatically extracts the archive.

---

## Which one should we use?

**Use `COPY` whenever possible.**

Use `ADD` only if you specifically need:

* URL download
* Automatic extraction of compressed files

This is the Docker best practice.

> **Note:** This specific difference isn't covered in your notes, so this part is added from standard Docker knowledge.

---

| ----------------- | -------------------------------------------------- |
| Copies files only | Copies files + URL support + Auto extract archives |
| Recommended       | Use only when extra features are needed            |
| Simple            | More powerful                                      |

---

### Remember

# Q26. What is the difference between `docker stop` and `docker kill`?

## Answer

Both commands stop a running container, but the way they stop it is different.

| docker stop                                  | docker kill                                |
| -------------------------------------------- | ------------------------------------------ |
| Gracefully stops the container               | Immediately terminates the container       |
| Sends **SIGTERM** signal first               | Sends **SIGKILL** signal                   |
| Gives application time to clean up resources | No cleanup time                            |
| Preferred in production                      | Used only when container is not responding |

### Example

Graceful stop:

```bash
docker stop my-webserver
```

Force stop:

```bash
docker kill my-webserver
```

### Interview Tip

If your Spring Boot application is processing requests and you execute:

```bash
docker stop app
```

Spring Boot gets time to:

* Finish current requests
* Close database connections
* Save logs

If you execute:

```bash
docker kill app
```

The application stops immediately without cleanup.

> **Note:** Your notes explain `docker stop` in detail, but `docker kill` is not covered. This difference is added from standard Docker knowledge.

# Q28. What is a Docker Volume?

## Answer (From Your Notes)

A **Docker Volume** is a **persistent storage mechanism** used to store data outside the container's writable layer.

Normally, when a container is removed, all data stored inside its writable layer is lost.

A Docker Volume stores data separately, so the data remains available even after the container is deleted.

Volumes are managed by Docker and can be shared between multiple containers.

Your notes also explain that Docker stores volumes under the Docker Root Directory (for example, `/var/lib/docker/volumes` on Linux).

---

### Real-Life Example

Suppose a MySQL container stores database files.

Without a Volume:

```
Delete Container
      ↓
Database Lost
```

With a Volume:

```
Delete Container
      ↓
Volume Still Exists
      ↓
Database Safe
```

---

### Interview Keywords

* Persistent Storage
* External Storage
* Data Persistence
* Shared Storage

---

### Remember

>
> **Volume survives**

# Q31. What is Docker Compose?

## Answer

**Docker Compose** is a tool used to **define and manage multiple Docker containers** using a single **`docker-compose.yml`** file.

Instead of running multiple `docker run` commands, we define all services in one YAML file and start them together with a single command.

Docker Compose is mainly used for applications that have multiple services like:

* Spring Boot Application
* MySQL Database
* Redis
* Kafka
* Zookeeper
* Nginx

---

### Example

Suppose your application consists of:

* Spring Boot
* MySQL
* Redis

Without Docker Compose:

```bash
docker run mysql
docker run redis
docker run springboot-app
```

You need to execute three commands.

With Docker Compose:

```bash
docker compose up
```

Everything starts automatically.

---

### Sample docker-compose.yml

```yaml
version: "3.8"

services:
  app:
    image: springboot-app
    ports:
      - "8080:8080"

  mysql:
    image: mysql:8
    ports:
      - "3306:3306"

  redis:
    image: redis
    ports:
      - "6379:6379"
```

---

### Advantages

* Manage multiple containers
* Single configuration file
* Easy networking between containers
* Easy startup and shutdown
* Good for development environment

---

* docker-compose.yml
* YAML

# Q37. What is the purpose of ENTRYPOINT in Dockerfile?

Whenever the container starts:

will always execute.

* Makes container behave like an executable
* Prevents accidental replacement of the main command

# Q39. What is the difference between CMD and ENTRYPOINT?

## Answer

Both are Dockerfile instructions used to specify what should run when a container starts.

---

### CMD

* Specifies the **default command**.
* Can be overridden while running the container.

Example:

```dockerfile
CMD ["java","-jar","app.jar"]
```

Run normally:

```bash
docker run myapp
```

Runs:

```text
java -jar app.jar
```

Override:

```bash
docker run myapp ls
```

Now Docker executes:

```text
ls
```

---

### ENTRYPOINT

Defines the **main command**.

It always executes whenever the container starts.

Example:

```dockerfile
ENTRYPOINT ["java","-jar","app.jar"]
```

Even if the user runs:

```bash
docker run myapp
```

Docker always executes:

```text
java -jar app.jar
```

---

### CMD + ENTRYPOINT Together

This is the most common interview question.

```dockerfile
ENTRYPOINT ["java","-jar"]

CMD ["app.jar"]
```

Container starts as:

```text
java -jar app.jar
```

If user runs:

```bash
docker run myapp test.jar
```

Docker executes:

```text
java -jar test.jar
```

Here:

* **ENTRYPOINT remains fixed**
* **CMD changes**

---

## Interview Comparison Table

| CMD               | ENTRYPOINT                         |
| ----------------- | ---------------------------------- |
| Default command   | Main command                       |
| Can be overridden | Executes every time                |
| Optional          | Defines executable behavior        |
| Used for defaults | Used for mandatory startup command |

---

### Interview Keywords

* Default Command
* Main Command
* Override
* Executable

---

### Remember (Best Trick)

```text
ENTRYPOINT = Boss 👨‍💼
(It always works)

CMD = Assistant 👨‍💻
(It provides default values and can change)
```

---

## ⭐ 4+ Years Java Backend Interview Tip

Agar interviewer pooche:

> **"Why do Spring Boot Dockerfiles generally use ENTRYPOINT instead of CMD?"**

Best answer:

> **"In Spring Boot applications, we usually use `ENTRYPOINT` because the application (`java -jar app.jar`) should always start whenever the container starts. If we need to change only the JAR name or runtime arguments, we combine `ENTRYPOINT` with `CMD`, where `ENTRYPOINT` defines the fixed Java command and `CMD` supplies the default arguments."**

# Q41. What is the EXPOSE instruction in Dockerfile?

## Answer

The **EXPOSE** instruction tells Docker that the container **listens on a specific port** at runtime.

It is mainly used as **documentation**.

**Important:** `EXPOSE` **does not publish** the port to the host machine.

---

### Example

```dockerfile
EXPOSE 8080
```

This means:

> The application inside the container listens on port **8080**.

But it **cannot** be accessed from the host until you publish the port using `-p`.

---

### Example Dockerfile

```dockerfile
FROM eclipse-temurin:21

COPY app.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java","-jar","app.jar"]
```

---

### Interview Point

Many candidates think:

```dockerfile
EXPOSE 8080
```

means

```bash
http://localhost:8080
```

❌ Wrong.

You still need:

```bash
docker run -p 8080:8080 myapp
```

---

### Interview Keywords

* Documentation
* Internal Port
* Does Not Publish

---

### Remember

```text
EXPOSE

↓

Container knows the Port

NOT

Host Access
```

---

### Follow-up Questions

* Is EXPOSE mandatory?
* Difference between EXPOSE and -p?

# Q45. How do you define Networks in Docker Compose?

```yaml
      - frontend
      - backend

    image: postgres
    networks:
      - backend

networks:
  frontend:
  backend:
```

```text
                     │
```

# Q46. What is Docker Swarm?

## Answer

**Docker Swarm** is Docker's **native container orchestration tool**.

It allows multiple Docker machines (called **Nodes**) to work together as a **single cluster**.

Using Docker Swarm, we can:

* Deploy applications across multiple servers.
* Scale services easily.
* Perform load balancing.
* Achieve high availability.
* Recover automatically if a node fails.

---

### Swarm Components

There are two types of nodes:

### Manager Node

Responsible for:

* Cluster Management
* Scheduling
* Service Deployment
* Maintaining Cluster State

---

### Worker Node

Responsible for:

* Running Containers
* Executing assigned tasks

---

### Diagram

```text
           Manager Node

          /      |      \

         /       |       \

 Worker-1   Worker-2   Worker-3

      Containers Running
```

* Manager
* Worker
* Scaling
* High Availability
